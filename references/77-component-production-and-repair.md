## Zero-guesswork route
1. Classify the commission: new ad, targeted revision, technical study, or script/audio only. Inspect one adequate product source. For a real ad follow SKILL phases 1–3 (verified proof, user-locked claims/voice, three distinct hooks, actual authorized audio, intended platform); if necessary ask one compact question for missing essentials. Keep decisions persisted. If no audio can be provided yet, prepare a clearly labelled silent preview rather than certify a finished advertisement. The user may request genuinely silent production; use the explicit silent workflow in older guide 76. A technical study is not a finished ad.
2. Plan story and timing. Define an actual event in each beat, its focal subject, outgoing and incoming anchors, and a concrete visual proof; not simply a headline and floating decoration. Keep one main idea. Compare at least two distinct composition sketches and two candidate fonts using actual copy; use licensed assets and never distribute fonts. Choose by legibility, hierarchy, product fit, and narrative meaning. Do not use the sample palette, exact copy or card layout by default.
3. Build a new source spec and creative record. For a composite of independent shapes, text, image, or supported 3D layers that repeats, use V41 components. For a single object use a normal layer. For live UI use the UI capture tool; do not invent product screenshots. For 3D type use text3d, solid glass use glass_object, softbody contact use dedicated contact renderer. Keep CGI selective, not every shot. For a nonrepeating complex animation build a direct timeline and choose actions from the catalogs. If technical capability is missing, use a supported substitute only if it preserves intent, and disclose it. Do not write a redundant renderer.
4. Run the commands below. Check `scene-audit.json` and `motion-audit.json`; resolve warnings by looking at real frames. Use native stills and boundary excerpts via compositor guide 71. Do not blindly apply suggested changes: an intentionally hidden or offscreen object is not an error. A group expansion changes all descendants. Watch the rendered preview with its actual audio, review every beat and decide specific changes. For a revision preserve unaffected content, timing and audio. Never auto-mark pass. If a tool cannot play audio/video, explain exactly what was not verified.
5. Gate final export and verify. Deliver links to actual files only. A passed technical gate does not establish design quality or rights. For a required 1080 width final export, never silently substitute lower resolution. Inspect final render independently; native quality is not the same as a scaled preview. Do not use master as a claim of uncompressed audio; the existing master is lossless RGB picture with AAC audio when provided.

## Component schema and exact behavior
Root `components` maps names to `{duration: seconds, layers: [...]}`. Children use local coordinates centered at (0,0) and local seconds from zero to duration. Default child active interval is entire component. Static x/y default to zero. Track timestamps and path-morph timestamps are shifted by instance start. Namespaced internal parents and mattes are rewritten. Parent and matte must precede use; references outside the component are not accepted. All components are expanded to ordinary renderer layers. Group is an affine parent, not a flattened offscreen precomp; opacity is applied to each child, not exact group opacity; refractive passes remain ordered. Components are appended after ordinary base layers (and in instance order). For exact custom z ordering, use an ordinary compiled/direct plan. No nested instance layouts within templates, no component-local cues/actions, no per-instance arbitrary dimension override, and no component-local softbody impulse timelines or mesh softbody; apply supported effects to individual namespaced objects after expansion using normal actions where supported. Individual IDs and group IDs have unique names; `instance__child` is the emitted ID. Instance `overrides` map child names to text/color/src/material/font only, and do not change other instances. External asset aliases and paths use the existing compiler. 64 instances, 512 total layers limit. For other advanced features use the existing direct renderer.

Use `examples/components-v41.json` as a small library of three local reusable component definitions; copy only the relevant definition into the source `components`. A text label instance may look like:
```json
{"id":"notice","component":"status","start":1.2,"x":360,"y":640,"scale":0.9,"rotate":0,"overrides":{"label":{"text":"SAVED"}}}
```
`instance_layouts` is optional; use a grid with `center`, `columns`, `spacing:[dx,dy]`, or arc/radial with `center`, `radius:[rx,ry]`, `angle` (degrees), `spread` (degrees). Arc distributes items about the center angle including endpoints; radial starts at angle and spaces without duplicating the endpoint. Layout common fields are `component`, `start`, `stagger`, `scale`, `items:[{id,overrides,rotate}]`. For a single object choose ordinary instance. Layouts only place copies; they do not silently add global animation. Add global actions or continuous_motion targeting instance group or namespaced child. Existing actions will reject conflicting tracks or unsupported layer types. The 58 previous animation actions and recipes remain available; use their catalogs. Example `director-v41.json` demonstrates a grid with three different labels and coordinated group convergence.

## Diagnostic and repair procedure
`python scripts/scene_audit_v41.py audit work/study41/plan.json` emits source SHA, sampled effective opacity under ancestor transforms, early/late ancestor intervals, and completely offscreen bounds for unwarped supported flat rectangles, ellipses, lines, images. It cannot see actual pixels, text clipping, occlusion, perspective, masks, mesh/material motion, or absolute creative quality. Use actual renders. `parent_hidden_frames` may be intended by a fade or cut. For a parent ending before its child, first decide whether the group should really extend or the child should end earlier. Only after checking all affected descendants, choose an explicit repair proposal from the report. Example:
```sh
python scripts/scene_audit_v41.py repair work/study41/plan.json work/repair41/plan.json --expected-sha256 COPY_HASH_FROM_AUDIT --select extend:group_id
```
This writes a new compiled plan and refuses changed source, unknown repair IDs or existing output. It is not a new approved production session. Inspect the output, translate the intended fix into canonical source, start a new session, review again. Do not change an intentional hidden interval. Never apply a fix merely to obtain a clean audit.

## Weak-agent concrete quality rules
- Prioritize in this order: truthful product evidence and user constraints, readable design, motivated continuity, then detail/texture. A higher number of effects is not a score. If the same event could be sold by unrelated products without change, redesign that beat around actual evidence.
- In a transition inspect the outgoing, midpoint, and incoming frames, and play at intended speed. If there is an accidental blank frame or unreadable overlap, keep the shared object visible until the incoming event is readable; resize supporting objects before collision; use a mask or intentional cut rather than a default crossfade. Do not layer multiple identical labels during their reading window. Keep intentional breathing room and do not add motion solely to defeat the audit.
- When two objects share motion and timing, parent them, use local coordinates and one group track. When siblings have different text or colors, use overrides. For repeated layouts choose grid/arc/radial, then customize the story, camera, hierarchy and transitions. Do not duplicate keyframes by hand unless timing differs.
- If 3D edges are poor, inspect 1080-native PNG, quality/antialias/atlas/bevel and reflection arrangement first. Compare lossless vs upload output. For real CUDA benchmark only on real hardware; run gpu_doctor and inspect telemetry. Never claim GPU speed on a CPU fallback.
- Keep an explicit unresolved review list. For each problem note observed time, layer ID, root cause, one change, new rendered evidence, and whether resolved. When an automated warning is intentional, record why. If blocked by missing evidence, files or hardware, state the limitation and deliver only the actual completed portion.
