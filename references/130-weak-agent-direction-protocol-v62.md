# 130 — Weak-agent film direction protocol: decisions that must change the picture (V62)

This is the active creative operating guide for a new narrated motion film. The job is to **make the film**, not to hand the user another planning document. Keep plans terse and internal; execute the next available stage. Current SKILL.md and 119 override all historical visual-source directions. If locked script/audio exists, do not ask for new copy, voice or music. If it doesn't, use guide 123 to route the actual missing input, not an unauthorized silent render.

## 0. Source and story lock

Inspect the product for facts **only**. Separate `verified live behavior`, `user-provided plan/in development`, and `purely illustrative metaphor`. Use wording/visual disclaimers appropriate to evidence; never fake demonstrations or measured protection guarantees. Write one meaningful change: “At first the viewer sees ___; ___ happens; by the end they understand ___.” If the script is locked, the change must follow its actual words. Do not start authoring the renderer while this sentence is just “we show these nine features.”

## 1. Generate mechanisms, not palettes

Produce three **different** internal visual mechanisms with distinct spatial subjects, action mechanics and outcomes. Don't generate three combinations of teal/blue with code windows. Compare them against available renderer capability, locked speech, product truth and strongest emotional moment. Choose one; let the user decide only if they reserved that choice. Example for fictional in-development script protection:

- **Ownership rupture:** a handwritten code strand receives an author's mark, is torn/reposted, then reconfigures into an *illustrative* protected execution path; repeated physical motif with changed role.
- **Wrong-way gate:** a token travels through an increasingly complex fork; the false route collapses while a verified selected path continues; conveys access rules conceptually, not a functional claim.
- **Constraint machine:** source tokens fold into an original new instruction grammar; the pattern develops in perspective and reveals that it is a hypothetical VM protection architecture.

This list is not a set of mandatory shots. Pick a mechanism because it leads to meaningful on-screen action. Don't copy Claude's script-inspection film verbatim into an unrelated security advert.

## 2. Map the whole picture **without filling it with detail**

Make a terse private progression of dominant subject and visible consequence. Three meaningful compositions are a better starting point than a long table of tiny assets: *opening question / pivotal change / earned result*. Draft actual phone-sized thumbnails. Identify **one hero subject**, one meaningful action or intentional hold and one contrast for each. If a tiny diagram must be explained by the caption, redesign at larger scale. Do not assume an engineering product needs a grid, code snippets, terminal chrome and complex diagrams in every scene.

The same palette may carry distinct scenes. Meaningful visual variety is in framing, spatial relations and outcomes—not necessarily in more colors, assets, velocity, or constant cuts. **Claude's stronger work is often simpler than the elaborate GPT film.** Prefer a clean, visually decisive image over a crowded 'premium-tech' collage. Use `references/133-clarity-over-complexity-v63.md` for the observed comparison and subtractive method.

## 3. Program motion as an event, not a collection of easings

For each core event, define: `cause → anticipation (optional) → displacement / deformation / revealed relation → secondary reaction (optional) → clear result → carried anchor or cut`. Use readable relative motion; physical acceleration/overshoot is appropriate for a springing button, not every UI component. For a sharp edit, a deliberate hard cut or one-frame contrast can be stronger than elaborate ease-in/out. Rhythm means varying **how** things move, not injecting constant visual noise.

At least one main event should demonstrably change the viewer's understanding **without reading the headline**. This is an editorial criterion, not a magic numeric pixel threshold. If the only actual motion is `position +5px`, opacity fade, scale 0.96→1, slowly rotating halo or new text over unchanged cards, this is **supporting motion**, not the central event. Recompose the whole state before adding micro-animation. A quiet final result hold is fine with a specific purpose.

## 4. Start with cheap evidence, repair early

Implement a simple, deterministic scene clock; select the most meaningful high-risk transition. Render a moving **1–3 s slice**, inspect start/peak/end and actual playback, then make a cheap **complete rough cut**. The rough cut should use the *actual stems* and approximate real duration so it exposes boring and overly long sections. Do not spend the full task budget refining only the clever VM morph. Also review a low-motion section and the ending. A deliberate hold can be strong. If they repeat the same title/icon/card relationship without narrative purpose, change the **mechanism**. First try removing unnecessary detail; only add motion if it serves a visible change.

In feedback, identify both *design issues* and *render bugs*: “cards are positioned diagonally because their default left/top is nonzero” is a layout bug; “four captions above an unchanging card are boring” is a creative bug. Fix the correct level. Render and inspect again. A screenshot sheet reveals composition but not motion smoothness: watch the playable slice when available.

## 5. Finish honestly

Do not call a film finished until real media exists, it decodes correctly, and applicable evidence checks have been made. Inspect full-cut intervals, typography at mobile size, main action visibility, tempo, voice/music/sfx mix and boundaries; repair actual defects. Technical success is necessary, **not** artistic approval. A genuine failure to obtain audible review, rights certainty or playback capability must be disclosed. Never invent QA findings, licensing, model tests, before/after improvements or user approval.

### Anti-slop self-check for a coding agent

Don't tell yourself “I made 400 frames, therefore it's animated”. Describe the strongest 3-second segment with the captions hidden. Does it convey a recognizable meaningful change? What does it do that the preceding section did not? If the answer is “more lines appear in the same box”, the film is probably using the renderer as a slide-generator. Revisit the art direction and the object hierarchy. An expert's move is sometimes to **delete 300 lines of clever but visually irrelevant effects** and build one confident event at full-screen scale.
