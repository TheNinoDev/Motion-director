# 91 — Direct original visuals, not a sequence of decorated slides

The renderer is a means, not the art director. Use the documented NOIZ-reference observations in 06, 18, 26–31 and 33 as a library of transferable principles. Do not need original reference clips from the client. Do not copy exact artwork, scripts, music, brand identity or claim original settings. Earlier development studies prove mechanisms, not professional ads. The user-provided failed sample illustrates what to reject: text in similar screen positions, small inert website captures, repeated dark background, feature inventory, isolated scenes. Contact sheet shows compositions, not reliable motion/audio assessment by itself.

## 1. Design three distinct concepts before opening a render tool
Pick one focal benefit and actual proof. Explore a literal product-interaction story, a semantic metaphor or object transformation, and an editorial/typographic contrast. These are idea prompts, not three forced styles. Each concept must define first visual, mechanism of change, actual product connection, emotional tone, ending/callback, feasibility and risks. Choose the concept whose outcome is most visible, specific and honest, not the one using the most features. If none is stronger than text on screenshot, rewrite concept. Avoid using the same opening/transition treatment from last project. No universal 3D intro, glass, jelly, orbit, dark gradient, CTA animation. Choose targeted effects to express meaning, not to satisfy a count.

## 2. Turn a concept into an executable film treatment
For each visual beat record: actual aligned time range; readable focal subject; framing/crop; BEFORE; ACTION with cause; AFTER; reason the change matters; background/supporting activity; next-shot anchor; voice phrase/music/SFX cue; real product asset and state; layering and technique. If animation carries across two narration phrases, keep it one action. Separate narration phrases from actual edits and transitions. Keep subject identity/palette/typography consistent enough to connect cuts; vary framing and scale enough to develop the story. Avoid arbitrary world changes. Plan outgoing and incoming states together. A deliberate hold to read proof, set up contrast or land emotion is valid. Do not disguise frozen composition with tiny oscillation. Motion density should come from meaningful information changes, not nonstop movement or excessive flashing.

Example functional direction (fictional version app, all screens illustrative unless verified):
| Beat | Before → action → after | Purpose / connection |
|---|---|---|
| Hook | Three distinct filenames enter as oversized cropped type, one caret hesitates; type stacks into file rows | Confusion is both spoken and visible; row geometry becomes next shot |
| Setup | Camera pulls back into actual file list, crop prioritizes three relevant rows; pointer moves to real history control | Product appears through existing visual structure, not isolated screenshot |
| Discovery | Click triggers visibly verified state change; the selected row stays anchored while other rows recede, small meaningful accent | Show actual result without invented count or UI behavior |
| Payoff | Selected name grows into final editorial line, same alignment and brand color; pause on result | Callback and resolution, not a generic feature list |
Animation methods: e.g. group transform, clip/reveal, actual image crop, named cue, gesture reaction, matched handoff. Select from actual supported properties. Neither the timing nor style is a reusable client template. Adapt to voice timing and brand.

## 3. Concrete lessons from reference analysis
| Observation in bundled reference breakdown | Reusable design principle | Apply without copying |
|---|---|---|
| Chrome number shrinks into list; later numeric payoff | A hero object changes job and scale | Use relevant product glyph/value and carry its anchor into proof; only use a number if grounded |
| Macro letter → wider wordmark → real page | Reveal context through scale and framing | Design crop around real component with compatible silhouette |
| Repeated status words resolve back to a cursor | Visual repetition expresses consequence | Accumulate only a state the story needs; collapse to one focal object |
| Fixed text baseline while visuals change | Continuity through a stable anchor | Keep one positional relationship across a purposeful hard cut |
| Contrast between tiny quiet statement and giant expressive motif | Dynamic scale and negative space | Give silence/space a role, then use larger contrast for payoff |
| Visual metaphor paired with interface proof | Alternate symbolic and literal information | Connect metaphor's shape/operation to the actual UI; don't substitute fiction for proof |

The earlier guides include technical methods for original symbol/metal text, true 3D meshes, macro lighting, procedural arrays, comedy, UI interaction, curves, masks, softbody and compositing. Read only what the chosen scene needs. Selective 3D: often 1–2 hero moments, sometimes zero, more only when central and quality is feasible. No compulsory exact count. Real 3D for spatial objects if necessary, honest 2.5D for flat design. Never call a flat fake a physical simulation.

## 4. Product evidence that reads at phone size
Capture or extract actual interface states at adequate resolution, read-only; preserve the original assets. Determine the smallest relevant UI region, enlarge it sharply, mask unrelated chrome, retain authentic labels/state. Use actual before/after frames for interactions and separate legitimate cursor overlays. Any abstract remake, dummy graph, decorative numbers or synthetic mockup must be labeled illustrative and never represented as actual behavior. No invented product UI, fake verified badges, fake user metrics, competitor accusations or safety guarantees. Screenshots of code inspection do not establish that a script is safe. Use supplied permission and public data, redact incidental sensitive identifiers as needed. If actual proof unavailable, choose a truthful non-demo story or ask for missing source; don't hallucinate proof.

## 5. Art direction — give concrete choices
Work in phone-first 9:16 by default only for vertical briefs. Decide one dominant type family/pair, weight/spacing, style of imagery, contrast, and role of brand colors. Render two genuinely distinct styleframes with real words and asset before picking; examples: large editorial crop vs macro interface focus, not same layout with hue change. Use font catalog/resolver with installed/licensed fonts; don't ship font binaries. Inspect at phone-size and native resolution. Reserve plausible safe zones for destination overlays; check current platform if necessary; don't blindly use one inset for all. Scale readable content, avoid large dead zones around tiny proof and repeated small identical cards. Text is part of choreography, not a constant subtitle layer plus duplicate headline. Captions separate and clean. Use purposeful depth, believable contact shadows, rounded bevels and coherent light where appropriate; reduce sheen, distortion, grain or excessive DOF when it interferes with reading. Preserve visual balance on dark/light transitions.

## 6. Motion grammar and technical selection
Design movement lanes (subject, framing/camera, supporting accent). Primary action gets priority; supporting motion leads eye or explains state. Use anticipation only for action, settle only where a stop deserves weight, velocity continuity when passing through, sharp cut when contrast matters. Prefer variable scale/framing and shared anchors over consecutive identical fades. Match incoming/outgoing silhouette, motion direction or color/position; inspect middle frames, not just endpoints. A hard cut is legitimate if intentional. Use a short pause before payoff when it improves comprehension. Sync focal events to actual word accents and music, not blindly every beat. SFX are sparse purposeful accents, not a metronome on every frame.

Tool decisions (existing capabilities, not new code): read 86 for compiler/capabilities; 85 reusable sequences; 80 motion profiles; 75–76 stateful motion and continuity; 77 component hierarchy; 78 pixel review; 81–83 gestures/events/cues; 68–70 real 3D type, elasticity and contact; 71 GPU; 62–67 optics, continuity and materials. Use `director_v49.py capabilities SOURCE.json LAYER_ID` and catalog before inventing any property. Plan absolute vs local coordinates; consider parent transforms, visibility intervals, matte, text bounds and ownership of animated lanes. Keep one canonical editable spec; do not manually modify expanded keyframes or generated artifacts. Do not create a new renderer to avoid learning existing supported tools unless genuinely necessary and explicitly justified. Use existing engines freely; if an alternative specialized renderer cannot pass the standard gate, disclose limitation and provide equivalent actual evidence, not a fictional manifest.

## 7. How to repair a bad scene creatively
| Symptom | Actual redesign |
|---|---|
| Text plus tiny screenshot | Reframe relevant UI to fill subject area; reveal through an action, crop, cursor and actual feedback; integrate wording into visual hierarchy |
| Every shot same | Change visual role/scale/negative space for new story development; keep anchor/palette so film feels connected |
| No emotional movement | Plan reaction/realization, one purposeful accent and a hold; vary performance or pacing only if audio may be revised |
| Every object bounces | Remove competing scale pulses; assign focal movement, give other objects stable roles |
| Effect looks cheap | Simplify material/geometry, adjust light/sampling or remove unnecessary effect entirely |
| Transition stutters | Compare actual start/middle/end, check speed and direction, parent transforms, masks and visibility; correct actual cause |
| Proof not legible | Recapture, crop, enlarge; make actual result dominant, check native and phone-size frames |
| Weak initial hook | Replace narrative/visual premise if needed; do not just add particles to first frame |

Do not blindly apply all fixes. Protect user-approved work and factual evidence. A weaker agent is expected to reject its own weak first idea even if it compiles.
