# V58 — hard conversational boundary, not a render setting

This root workflow changes the order of work after two failed independent agent attempts. A new ad defaults to voiceover AND soundtrack until the client explicitly changes scope. A user who has no files is not opting out. Read this before any manual audio handoff. The host may ask the agent to continue autonomously; that is not a voice/music decision or permission to waive a dependency. An unavailable audio tool does not turn the task into a silent promo. End the response at the dependency; resume from actual new user input. This is an instruction, not a programmatic lock.

## Decision map

| User's actual words / available assets | Next actual response | Film render permitted? |
|---|---|---|
| "Make a promo of this website" | Inspect briefly, give one recommended story + ask voice/language/music and missing consequential release questions | No |
| "Everything up to you" with no previous audio discussion | Recommend narration and music, ask whether they have files or want a handoff; if explicitly delegates acquisition, choose actual authorized route | No while assets missing |
| "English, choose the music, no files" | Complete provider-specific tagged script and novice audio/music packet, obtain via tools only when authorized | No while assets missing |
| "Use my voice, no music" with voice file | Verify audio, preserve scope, document explicit music waiver | Yes after checks |
| "No voice, music only" with no track | Obtain cleared track or handoff | No while music missing |
| "Silent visual preview only, I will do audio later" | Clearly label explicit intermediate; provisional timing | Yes, preview only |
| "Make it silent, only SFX" | Record exact waiver, obey intended scope | Yes after scope recorded |
| Existing voice and cleared music supplied | Inspect, audition when capable, use actual alignment | Yes after checks |
| "Continue" from automation with no new input | Repeat only the specific dependency if necessary, no new full render | No |
| "Just write the script" | Full script with appropriate acting directions, optional concise relevant setup | Not requested |

Do not interpret a user saying "no audio" ambiguously when asked whether they possess files: distinguish no files from explicit no narration/music. Ask a single clarification if needed. Do not make the user choose technical settings. Independent permission and product safety restrictions remain binding. If the request itself is disallowed, do not perform it; explain and offer permissible alternatives as appropriate.

## Actual conversation example (fictional app; adapt language and details)

User: "Make a cool ad for my calendar app." Agent has verified only drag-to-reschedule. Good first response:

“I’d make a short edit about moving a meeting in one drag, rather than a tour of the entire app. For audio, I recommend a playful narrated edit with a rhythmic soundtrack. Should the narration be English or German? Do you have a voice recording or saved TTS voice already, or should I prepare one? Any song in mind, or should I choose the music? And is it for organic social posts or paid advertising?”

Stop. No timeline or rendered teaser attached. Omit questions answered by the user. Can include a tentative hook, not a false claim of audio production. If the user chooses all routes, continue immediately with actual assets or handoff, not another generic questionnaire.

User: "English, choose music, I have no audio, organic TikTok." Next response must contain the complete selected story and actual spoken script, not a storyboard alone. The illustrative acting example below assumes a compatible model; verify native cue support before using any provider tags in real output.

```text
[curious] Wait. Nine in the morning?
[sighs] That's not happening.
[thoughtful] What about eleven?
[playfully] There. Much better.
```

For a real project, select and verify actual provider/model/rights, include the exact separate voice design paragraph if appropriate, name actual supported controls and how to generate and export. Research actual tracks (current trend evidence if relevant and a suitable timeless alternative), identify official legal source and scope of synchronization rights. The fictional example does not invent a song, URL or a provider UI. A real handoff lacking these details is incomplete unless the missing verification is explicitly identified and a usable lawful route given. If audio availability blocks completion, stop the turn after the packet. User returns the unprocessed voice and authorized track separately; agent edits them, checks pronunciation and timing. Never ask for a password. Do not ask the user to download from an unauthorized source. A provider/account/plan restriction must not be bypassed.

## Explicit failure example from the returned test

The client reported no audio or voice questions. The delivered response said the 22-second promo used only synthetic accents, no voiceover and no licensed music, then offered to make narration later. This is a failure of scope and order even if its 1080x1920 output is valid. The right next deliverable at the missing-audio stage was a question or a user-visible audio packet, not a finished picture cut. Do not assume the agent's complete private process from the end message; enforce the observable behavior here. A screenshot-oriented legacy render path is not permission to evade the root.

## Recover when the mistake already happened

1. Name the existing export as picture-only/unapproved intermediate unless explicitly requested. Retain it, actual sources and verified product evidence. Do not claim it is finished.
2. Resolve voice language/route and music/rights with the client. Do not ask again for known product facts. Deliver complete tagged script and practical audio handoff where applicable.
3. Obtain audio and measure actual cue timing. Re-direct the film around that audio and one central action. Do not simply lay voice/music underneath the old slide sequence.
4. Re-render only after these prerequisites. Compare against the actual old output and explain concrete fixes.

The preproduction tool checks recorded fields; only actual chat and files establish whether the client received a packet or sent a waiver. Do not fill in pretend answers. The first-turn stop is behavioral and applies even if a direct renderer is callable.
