# 95 — Editorial rewrite and complete audio handoff (V52 controlling)

Read this before any new ad/script reply. Guides 89 and 90 contain supporting examples, exact existing compiler cues and routes; guide 24 contains the immutable user-tested voice prompt. This guide controls the visible output and decision sequence, not a new generator.

## 1. Write a script worth editing
Never write the narration as a list of features first and then cover it in effects. Start from a concrete viewer situation, a specific tension and a change viewers can see. Determine what the ending resolves. Choose the product-specific proof before locking the promise.

Internally create three *different* openings, e.g. (a) relatable mistake, (b) unexpected contrast, (c) a visually demonstrable action. Three questions with synonymous words count as one. For each write the next line, potential first visual and reason the revealed product resolves it. Reject a hook that needs an invented benefit or cannot lead into the rest. If all hooks require identical generic product explanation, rethink premise. Do not show all internal alternatives unless user wants them. Select strongest unless meaningful choice belongs to user.

Then draft and perform a second pass:
- Delete anything a viewer already knows from the previous line or the picture, unless repetition has comic/rhythmic meaning.
- Replace vague claims with concrete nouns/verbs and a demonstrable outcome. Do not use unsupported “best”, “safe”, “verified”, “free”, comparison, number, speed or availability claims.
- Use short and longer phrases deliberately; a reaction may be two words. Write punctuation for breath and timing, simple spoken language, natural contractions when appropriate. Do not force slang, announcer tone or exaggerated hype.
- Verify first line creates a reason to keep watching and final line lands the same premise. CTA is optional if a memorable payoff is stronger; user objectives control.
- Estimate spoken duration including performance pauses as provisional. Do not pad to a standard number of seconds; adapt to actual recorded speech. A hard target may require a shorter rewrite before lock. Once locked, ask before changing words; never add filler for a tool gate.

### Example of the editorial process (fictional version comparison app)
Assume the provided product proof really shows a compare feature. Weak: “Manage and compare your files with powerful version history, seamless search and a modern dashboard.” This has no scene or payoff. Three distinct openings: “I sent the wrong file.” (confession), “Why are there three final files?” (recognizable situation), “These two files look identical.” (demo). The third only works if differences can actually be shown. For a comic story choose the second. Write a small sequence: confusion, dry listing, recognition, relief. Verify actual words/claims against evidence. Do not use this example for a real brand unmodified.

Clean words:
```
Why are there three final files?
Final. Final-two. Final-actually-final.
Oh. This is the one I sent.
Found it.
```
The phrase-level performance plan is not a tag quota:
| Phrase | Intent | Operative accent / timing | Visual purpose |
|---|---|---|---|
| Why are there three final files? | Genuine amused confusion | THREE, rising question | Establish competing names |
| Final... | Dry increasingly absurd enumeration | Progressively tighter pauses | Repetition visually grows |
| Oh... | Realization, softer | THIS, small breath before | Actual comparison reveals correct version |
| Found it. | Understated relief | Clean short landing | One file remains, premise resolves |

Do a read or text-based breath check honestly; if you cannot listen, do not say you auditioned. Specific, meaningful beats beat a long feature inventory. Copy can be approved/delegated independently of audio.

## 2. Voice routing with exact deliverables
Choose a route based on user's files, consent, available authorized capabilities, intended sound and distribution. Check current official documentation and eligibility when browsing is available; source links and UI examples in 21/24/25/87 are historical references, not current guarantees. Never ask for credentials or direct anyone around age/guardian/plan limits. A free tier does not imply commercial clearance. No voice cloning without authorization. If user supplies existing valid voice, keep it; if audio immutable, do not rewrite. If script only, do not force user to buy or generate anything.

For a known supported expressive provider, every complete narration deliverable includes the actual provider-ready text in one separate copyable block (or clearly numbered chunks only when needed). Never output **only** a clean script, a JSON manifest, a table of tag names or “use tags.” The exact spoken words must match the approved clean copy after removing tags. Place meaningful supported cues immediately before the intended phrase, not on every word; include deliberate neutral contrast where natural. For a multi-phrase ad, one generic tag repeated on every line is not a performance plan. A very short locked line can need fewer cues; never invent words or needless tags to pass V50. With unsupported or unknown provider, deliver clean words and phrase-level acting instructions and a conditional supported route suggestion; do not silently assume provider syntax. The existing compiler table in 90 is authoritative for its accepted internal cue keys. Model availability must be checked separately; tags guide but do not guarantee performance.

For the fictional example, **if** the verified ElevenLabs expressive route is selected, paste-ready input is:
```
[curious] Why are there three final files?
[sarcastic] Final. Final-two. Final-actually-final.
[thoughtful] Oh. This is the one I sent.
[excited] Found it.
```
If the verified Fish S2 route is selected, instead use:
```
[curious, rising tone] Why are there three final files?
[slightly sarcastic] Final. Final-two. Final-actually-final.
[thoughtful, measured tone] Oh. This is the one I sent.
[excited] Found it.
```
Do not show both in routine handoff; show the actual selected provider. If the last cue overacts, audition another permitted delivery. Preserve clean words. If tags are spoken aloud, repair take or model choice; do not silently accept. Human recording: clean script and separate notes only, no spoken brackets. Captions always use clean words.

Voice Design is separate from Text to Speech. For the user's preferred compatible holographic voice, read the exact original paragraph in guide 24 and place it byte-for-byte in its own copyable block when a new voice is genuinely needed. Do not summarize, replace with character lore, or embed it in the campaign narration. If user has a saved successful voice, skip design; do not regenerate unnecessarily. If another provider has no equivalent voice-description field, explain it and choose an authorized matching voice if possible, not a fabricated control. Preserve user voice preference across episodes unless requested otherwise.

## 3. The actual user-facing handoff: no missing pieces
A handoff is successful only when the user can act with what you sent. The following is an output structure, not boilerplate. Fill it with actual project content; never send placeholders or invented selections. Use the user's chat language for directions and requested language for script.

**Selected voice route** — link official site/tool; model name verified or explicitly uncertain; explain necessary account/rights requirements succinctly and offer an eligible route if not available. If agent can legally generate and user delegates, use real tool; otherwise explain one exact manual path.

**Voice setup** — if new voice: explain Voice Design versus TTS, provide exact description as a separate block, instruct preview/save of chosen voice using same genuine campaign excerpt. If existing voice: select it, no re-design. If recording: clean text and recording direction, no duplicated setup.

**Paste this in Text to Speech** — actual final tagged script; no shot notes, timestamps, Markdown formatting inside provider text, placeholder tags, or instructions to be spoken. Explain tags are performance instructions; provide separate brief acting notes and clean narration when needed. Instruct user to generate, listen for exact words, pronunciation, emotion and overacting, then export/download the original MP3/WAV through actual supported control. If output must be split, supply numbered ready chunks and ask for the corresponding raw files; never ask user to assemble them. If UI uncertain name the relevant feature/function rather than invented button location. Give useful direct official documentation links from verified sources or explicitly dated bundled references.

**Music** — select or recommend a real track/version with actual source and license (see next section). For client choice, provide meaningful alternatives and choose a recommended one rather than asking them to search. Explain exactly where to get the authorized original file or how platform-only insertion works. If actual track or rights cannot be verified, say which part is pending, give a feasible lawful next step and do not represent a placeholder track as selected. Do not block delivery of copy and voice directions.

**Send me** — list only missing raw files, e.g. dry voice WAV/MP3 and selected lawful music file. The agent owns trimming, aligning, ducking, SFX, mix and editing. Do not request an export already provided. No account password, payment, DAW work or raw music download against license. Explain that the next production step requires the actual files in a new turn, not background rendering. If no missing files, proceed with actual inspection.

## 4. Music choice as part of creative direction
Determine whether music should carry tension, pace, comedy or emotional landing. Research 2–3 actual suitable options when choice matters: a current/rising candidate with dated relevant evidence **if research confirms it**, and a timeless eligible choice. Do not fabricate viral claims or require a viral track if unsuitable. For each actual candidate provide title/artist/version, official listening source, why it works for speech and story, tentative energy accents, evidence of trend if claimed, commercial rights scope/limits and exact lawful obtain route. Distinguish streaming, platform-only insertion, and licensed downloadable sync use. Music clearance is separate from voice rights. For public/promoted ad check paid placement and cross-platform terms. Current rights can vary; link the actual license, not vague “copyright-free.”

If you cannot browse or verify: disclose the limitation, do not invent titles/chart dates/licensing. Offer e.g. a known authorized user-owned stem, original music through available authorized creation tools, or an officially cleared library route the user is eligible to use. If user says no music, respect it. If platform-only track cannot be embedded, explain why and follow legitimate picture-only path with release scope caveat (97/92). User never has to rip tracks, evade restrictions, or mix manually.

## 5. Receipt when files arrive
Check actual stream and duration, distinguish dry VO/music/mixed audio, validate exact text and tags not spoken, record rights and audition honestly. If you cannot listen or transcribe, label those pending; do not invent observations from waveform or filename. Use verified measured phrase/word timing (ASR with correction, forced alignment or manual listening as supported), not rough timing extrapolation, and bind to original file version. If speech changes, re-lock and re-align relevant edit. Edit VO first, then music and SFX; check actual intelligibility, pauses, clip/peak and endings. Read 92/87 for existing gate limitations and commands. The user should get no new questionnaire if the actual files settle the remaining questions.
