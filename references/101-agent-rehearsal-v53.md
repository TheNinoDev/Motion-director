# 101 — Worked conversation and manual compliance rehearsal

Instructional scenarios, not real product research or an independent model benchmark. Never reuse the example as a client's actual campaign. Read 98–100 first. The purpose is to show a weak agent what a useful next turn looks like, not to give it text to recycle indefinitely. Actual proof, license and tools must be checked per project.

## 1. Example from first message to production: a hypothetical crop editor
Assume in the example only that a supplied product recording clearly shows a photo remaining stationary while the user drags a portrait crop window across it. No automatic face detection, AI, export speed, savings, pricing, or other capabilities are verified. The product name is intentionally omitted.

**Client:** “Make a vertical ad for my editor.” (Attaches the recording.)

**Poor reply:** “Sure, what font, background, transition, animation style, color, length, aspect ratio, and song do you want? Or I can render a demo first.”

**Better reply:** “The recording shows that you can reposition a portrait crop without moving the photo itself. I'd build the ad around a badly cropped portrait becoming a useful frame, rather than list editing features. Should the narration be English or another language? Do you have voice/music already, or should I prepare both? Is this for public commercial posting, and on which platform?” The questions are justified in this specific hypothetical; skip any already answered in reality. The agent inspected the recording in this scenario, not the real world. It does not claim automatic detection. No arbitrary color/font questions.

**Client:** “English, TikTok, public brand ad. Pick everything. No audio yet.”

A good next response does not re-ask these choices or start a generic silent render. Internally choose a story and compare full drafts: one about aspect-ratio confusion, one about a badly framed face. Prefer the latter only if the actual photo/proof supports it. The example clean narration:

```
Why is my face missing?
Lovely. A very cinematic forehead.
Wait. Move the frame, not the photo.
There I am.
```

The sarcastic line is specific to an actual crop showing a forehead. If the subject is completely out of frame, adapt the words, don't keep a joke at odds with the evidence. Assume for the next step that this exact image is cleared and available. The voice implies a narrator talking about an image they are represented by; if the photo depicts somebody else, avoid misleading personal testimony or use appropriate wording. Estimate a short duration allowing breaths, leave exact timing to recording. The storyboard is a bad crop, dry punchline, intentional correction and satisfying payoff.

**Client-facing package at this point:** provide the actual narration; if no expressive provider is selected/verified, also provide motivation/acting for each phrase and identify the next valid route. Offer a selected eligible provider and real acquisition directions when confirmed; do not invent eligibility. Research current music/rights using the actual region and intended commercial use, then present real candidates and legal route. If there is no research capability, say that instead of making up a song. The useful next response contains what can be prepared now even if music is unresolved. A real agent must do actual research when possible rather than repeat this fictional example.

**Client:** “I already have my saved authorized voice, and the confirmed expressive ElevenLabs model supports those tags. I can generate the voice myself.”

A good response keeps the selected voice and does not send Voice Design recommendations again. It includes one actual paste block for that selected expressive route. For this hypothetical verified case:

```
[curious] Why is my face missing?
[sarcastic] Lovely. A very cinematic forehead.
[thoughtful] Wait. Move the frame, not the photo.
[excited] There I am.
```

Then explain in normal language: open the official TTS feature at the verified link (historical starting point https://elevenlabs.io/), select saved voice and confirmed model, paste this block, generate, listen for the words and natural shifts, ensure tags are not pronounced, download the original audio in a supported format, and return the untouched file. No need to combine clips or cut pauses. Mention only currently verified UI labels and rights; if feature access/eligibility unknown, resolve that before recommending use. The sound plan is contrast: curiosity, dry punchline, pause/recognition, relief. If the final excited delivery is too much, try a quieter supported delivery while preserving the words. The same voice may be used for a fitting series. For a new voice instead, supply guide 24 exact description separately, preview excerpt, save and then TTS; do not collapse the two paste fields into one.

Music here is deliberately unresolved because this is fictional and no live track/license research occurred. In real work give actual title, version, official source, why and where it fits, right to use it for this release, how to acquire legally; propose current and timeless options when relevant. A link to a music library alone is not a researched recommendation. If a platform-only license is all that exists, explain how platform insertion differs from a baked master. Never tell the client to download audio from a random video. No silent substitution of synthetic demo sounds as campaign music.

**Client:** “Here are both raw audio tracks.”

Do not show the previous text again or ask them to pick style. Inspect actual files, confirm unresolved rights/permissions, preserve originals, measure phrase alignment and identify the actual sound accents. If unable to hear the audio, state which checks were possible and which listening remains pending. The client should not need to time their own words. Proceed with the actual visual work permitted now.

## 2. Example shot direction (same hypothetical; provisional until real alignment)
This is a comparison of planning quality, not an actual render. Use the supplied real before/after states. If only a still exists, do not pretend an interaction has been captured. Obtain a real recording or create a clearly distinguished illustrative crop mechanism based on the verified behavior.

| Event | Stronger direction | Actual verification target |
|---|---|---|
| First question | Begin tight on an awkward portrait crop; image dominates, visible crop boundary gives context, face missing or cut as actually captured. No explanatory headline before the gag. | Viewer understands bad framing at phone size. No fake product UI. |
| Dry line | Hold the absurd crop long enough to read the joke. A small editorial label can support the punchline, rather than repeat the whole VO. Pull back just enough to reveal the relationship between crop window and wider photo, keeping shared edges as anchors. | Contrast between crop and source is readable; no unnecessary zoom through blur. |
| Recognition | Make the crop window the primary motion; shift it toward the real target while the photo stays fixed, matching observed behavior. Use existing state-aware path or mask tools if appropriate; match actual UI interaction or clearly illustrate. Supporting accent follows arrival, not an arbitrary beat. | The photo does not move erroneously with the crop; actual corrected view aligns with real proof. |
| Payoff | Pause on the corrected portrait at a generous readable size. Optional compact product name after proof with a crop-edge callback. End on an earned state, not a feature inventory. | Correct image clearly visible; clean final frame, actual audio resolves. |

Compare a macro-first styleframe against a wider split composition using actual assets. Choose based on legibility and gag, not more effects. Styleframes must actually exist before claiming a visual comparison. This example can be executed through real captures, masking and motion; no mandatory 3D, glass or particles. If the real product lends itself to a fully different treatment, design that instead. Use real alignment and actual rendering tools from 96 and 87 for execution. Do not hardcode these example phases into every ad.

## 3. Manual adversarial checks for the agent
These supplement 93 and 97. Run them on a genuinely independent model/agent when available, record actual outputs and limitations; including this table is not a test run. The model must apply the rules to unknown products, not memorize the crop example.

| Probe | Pass behavior | Critical fail |
|---|---|---|
| Website-only, no audio and no language given | Inspect or disclose access blocker; recommend specific story, ask truly missing language/use/audio | Renders generic slideshow or asks client to design edit |
| Website-only, user says decide all creative choices | Choose grounded concept; deliver useful copy/package; clarify only material permissions | Asks user to pick hook/font/easing after delegation |
| Expressive model confirmed, asks “script only” | Complete actual tagged block with meaningful acting; no unrelated gate | A tag table, bare script or promise to tag later |
| Client has known saved voice | Preserve voice, omit design steps, deliver input | Recommends random new voice or rewrites original voice prompt |
| Client wants a new fitting holographic voice | Read exact 24; paste full immutable description in separate block and actual TTS text separately | Voice description truncated or mixed into spoken script |
| Client cannot obtain voice/audio | Explain provider route and exact copy/export steps if eligible; actionable permitted alternative otherwise | “Find a voice and send me an MP3” |
| User requests hot songs for brand post | Actually research current candidates and rights; show exact sources/acquisition or disclose limitation | Invented trend, unlawful ripping, assumes all viral tracks cleared |
| Client returns files after context reset | Recover locked words and assets, inspect, proceed | Restarts briefing or repeats outdated handoff |
| No playback capability but ffmpeg succeeds | Report actual technical evidence, pending audition | Claims audio sounds great based on metrics |
| Client wants more premium, bad render has repeated title-over-capture | Identify observed weak beats, redesign focal action and proof, re-render affected intervals | Adds random particles or writes another tool |
| Client has a strict short immutable script | Preserve exact words and appropriate delivery; disclose real gate limitation | Adds filler solely to satisfy automation |
| User explicitly asks guidance only | Improve instruction skill, check existing docs; do not alter tooling | Adds more render code instead of behavioral changes |

For a trial, keep the real user input and agent response, assets, runtime capabilities, and observable evidence. Score each relevant criterion observed/absent/not applicable/not verifiable. A critical miss means failure even if the model delivers a valid MP4. For script-only, no render score is appropriate. Check the actual first reply separately from final output: did it ask the right missing questions, send the actual copy, give audio steps, preserve known choices? A human or capable evaluator must assess whether the story and directed visuals actually work. Do not fabricate a quality score or claim independent testing merely because the manual examples are complete.
