# Brand transformation: standalone production recipe (no references required)

Use only when there is a real change, an honest product contrast, or a clearly labeled design study. Never invent a previous version, awards, user counts, pricing or launch facts. For a normal product story, the old state may instead be a genuine user problem. A contrast is not a claim that competitors are bad. One narrative, not a feature inventory.

## Seven beats (example 30 seconds; retime to actual voice)
| Beat | Approx timing | Action | Renderer |
|---|---|---|---|
| Familiar world | 0–3s | Start cropped into meaningful real UI headline, pull back to context using shared center | ui |
| Contradiction | 3–6s | Hold key phrase, cut to evidence of the problem | type/expressive |
| Interchangeability | 6–10s | Same screenshot, only hue changes; use 3–5 colors, 8–12 frames each; explicitly label illustrative recolor | brand palette |
| Unbuild | 10–14s | Map actual layout rectangles; fade original and collapse bars toward a caret | brand collapse |
| Pivot | 14–16s | Caret holds with one blink; meaningful short phrase or silence, not generic filler | brand reset / type |
| Rebuild and prove | 16–26s | Reveal actual new product, show one concrete successful interaction; optional 0–2 premium metal inserts, then genuine evidence | ui, material, scene3d, brand badges |
| Callback | 26–30s | Repeat opening motif with changed meaning; final brand, actual domain and clear CTA, hold 1.5–2.5s | brand endcard |

This is a starting structure, not an obligatory duration or script. Avoid fabricated rebrand narrative if there was no rebrand. Do not use demo screenshots, false awards or dummy price points. A palette experiment must be labeled so no viewer confuses it for released themes. Color-shift only nonsemantic imagery if colors convey status; if necessary capture the actual variant instead.

## Choreography and implementation
- Pick one consistent UI screenshot, normalized rectangles [left,top,right,bottom] over relevant elements; the collapse preset uses exactly these rectangles. It is an abstraction, not real DOM morphing.
- Keep central caret near 46% canvas height. Match next shot anchor at that location, use a cut during the quiet hold. Do not automatically zoom every shot.
- The screenshot recolor is a hue shift on saturated pixels, intentionally illustrative; preserve authentic UI separately for the proof and do not present recolors as implemented functionality.
- Evidence tiles enter with staggered smoothstep, then hold as one layout. Only actual awards, if verified. Otherwise use real product details or explicitly labeled design studies. Avoid a complete list of features: choose 1–3 evidence items all supporting the same claim.
- Endcard actual logo file preferred; wordmark text fallback only if approved as representation of brand. Size for phone, hold long enough to read domain. Keep final text and logo within safe regions. If platform overlays mask the bottom, place endcard higher and inspect.
- No animation should hide the proof result. Preserve the last real UI state 0.6–1.2s minimum as appropriate. At final QA inspect the beginning, midpoint, end of every shot and playback overall. A quiet section with deliberate framing is not automatically a bug.

## Copy starter (not a script to reuse verbatim)
Old problem → contradiction → realization → actual change → proof → understated CTA. Start specific: 'We built [actual thing] to solve [real problem]. Then we noticed [actual contradiction].' If no confirmed contradiction: show concrete user action instead. Write three distinct hooks, choose best proof, strip generic language, retain one idea, direct voice per provider guide. Never make a false confession or use the template to invent a problem. For real final work write from intake evidence and lock actual audio before editing.
