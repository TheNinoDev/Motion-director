# 145 — Editor-first, softer geometry, contextual icons (Ads Wizard v72)

## Why this correction was made

The owner found v67 the strongest tested Motion Director version. Later experiments over-corrected from generic sharp code cards to oversized illustration/icon slides and then to ensemble-icon scenes. The current 24-second 540p preview still uses a sequence of complete text/code panels rather than a continuously directed visual action. Return to v67 tools and compositing. This guide is **not** a prescription to add more assets; it is a narrow revision to how to stage and polish them.

## Before picking any icon: direct the scene

1. Write the actual visible change, not a noun list. "An unauthorized duplicate steals the key mark" is a change; "copy icon appears" is not.
2. Choreograph subjects, negative space, scale, camera/reframe, foreground occlusion, mask and audio relation. The viewer must feel the change even if every small glyph is hidden.
3. Shape the transition into the next shot: carry an edge, color block, line, velocity, shadow or object **when justified**, or choose a deliberate contrasting cut. Avoid the same slide grid with a different label.
4. Pick geometry for the action. Use warm, slightly rounded UI surfaces where tangible controls need visual quality. Sharp corners may remain on source paper, code sheets, perspective grids, cutout silhouettes or contrasting technical subjects.
5. Add contextual icons *after* the button/card/interaction is working. If an icon does not help identify or reinforce an action, delete it.

## Icon role: affordance within a designed interface

Examples, not quotas or mandatory shots:

- A small **play glyph** in an established code execution button may replace the literal word "Run" when the application context already makes its meaning unambiguous. Do not fabricate a real site button or imply an executable action you did not verify. A tooltip, nearby caption, `aria-label` in the real UI or narration can supply clarity where needed.
- A small **copy** glyph in the toolbar of a code card can identify the copy affordance. The *main action* should be the copied strip moving/curling/landing or another meaningful code interaction, not the icon moving through the frame.
- A **lock/check** glyph can clarify protection status within a toggle or status chip. The meaningful shot is the status transformation, with contextual before/after evidence or an unmistakably illustrative metaphor.
- On an **outro**, an official brand favicon/logo provided by or approved for the owner can support the URL or brand lockup. Animate the whole composition and sound payoff; do not create a second hero just for the logo.

Possible sources include Solar Icons Bold/Bold Duotone (`https://solar-icons.dev`) and Lucide (`https://lucide.dev/icons`). Verify the specific asset and license first. Solar icon artwork (480 Design) uses **CC BY 4.0**, requiring attribution and any other license obligations; Lucide uses **ISC**. Keep appropriate credits with project/release materials. Prefer consistent visual weight and the fewest shapes needed. If SVG parsing is unsafe, obtain a trusted sanitized raster and audit the origin.

## Geometry and polish

- Prefer deliberately varied roundness: e.g. soft buttons, moderate card radii, pill-shaped status chips, and harder inner code segments. These are visual relationships, not fixed pixel rules.
- Avoid repeated hard-edged window/card stacks with the same centered scale and identical easing for 20 seconds.
- Use curves/Bezier motion for meaningful arcs, object attachment at contact, tangential velocities, overshoot/settling only where physically and stylistically motivated.
- Preserve large readable type, but do not let static headings substitute for moving composition.
- Color/shape continuity helps, but an intentional snap cut can beat a lazy wipe. Judge in motion with audio at 1x and 0.5x.
- Logo permission is **narrow**: explicit user's owned isolated icon for brand signature. It does not authorize copying the site's hero photos, screenshots, layouts or unrelated third-party logos. If the user's ownership or visual artifact is unconfirmed, request clarification or use a text-only brand credit.

## Rejection examples

Reject: a large floating lock on navy, then large floating play icon on navy, then a large chip on navy; each has a new heading but no causal action.

Reject: sharp identical cards simply replaced by round identical cards. That is still a slide deck.

Prefer: a code artifact interacts with a distinct machine/gate/panel; motion expresses its state change; tiny interface affordances clarify specific controls; a clean meaningful reveal passes into the next scene. The imagery must be original and truthful for the product.

## Final visual test

Show a muted visual cut with icons removed (except any necessary logo). If viewers still understand the basic action and visual progression, polish is doing its job. If not, restage the main animation before adding decorations. Get subagent critique if supported, but keep one editor in charge.
