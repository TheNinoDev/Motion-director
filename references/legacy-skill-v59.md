# Motion Director 59 — SOURCE INFORMATION ONLY · ORIGINAL VISUALS ONLY

**READ THIS BEFORE ANYTHING ELSE.** This V59 contract OVERRIDES every conflicting suggestion in older guides, example plans, code comments and tool help. In particular, old instructions telling you to capture, crop, animate, reframe or reproduce a real website screenshot are OBSOLETE for new productions. Do not use them. Read `references/117-source-firewall-v59.md` before product discovery and `references/118-original-visual-direction-v59.md` before planning visuals.

## 1. Non-negotiable source firewall

**A website, local project, source code, supplied reference video or original HTML is an INFORMATION SOURCE, NOT A VISUAL ASSET LIBRARY.** This applies to `make a video for example.com`, `make a video about my local project`, `use these NOIZ references`, and similar instructions. By default, use sources to learn what a product does, who it serves, which outcomes are supportable, and what editorial/motion principles are relevant. Then design all video pixels from zero using the installed procedural drawing, original typography, shapes, 2D/3D models, particles, lighting, masks, compositing and rendering tools.

**NEVER insert or transform source imagery into an ad.** No site/project screenshots, original UI captures, frames, page sections, source photographs, original SVG/PNG/JPG assets, logos/favicons, CSS animations, HTML/CSS rendering, DOM screenshots, OG images, embedded page/video elements, source textures, or downloaded media. No repackaging them as cropped, blurred, stylized, 2.5D, AI-redrawn, vector-traced, transformed, recolored or partially masked objects. No matching the original site's exact layout/design tokens as a substitute for original art direction. Do not extract source audio/music, either. A screenshot can be viewed TEMPORARILY for factual research but cannot become an asset, style transfer input, scene layer or exported frame. An HTML file may be parsed for meaning, never used as the film's markup or a visual template. Do not reproduce third-party reference footage, logos or compositions.

**Only original video assets** created by the agent's tools, authorized separate assets explicitly provided for inclusion by the user, and cleared voice/music acquired in the audio workflow may appear in the deliverable. The product's factual NAME and verified functional WORDS may appear as newly typeset text; this does NOT permit copying its logo/branding artwork. A distinct user-authorized asset is an exception ONLY if user explicitly identifies and approves that asset for the finished video; a website URL, project path or general “use my site” is NOT such approval. Even for an authorized asset, keep its reuse limited to the approved scope. If authorization is absent, CREATE from scratch rather than ask for a screenshot.

**Truthful visualization:** When discussing a verified feature, show a NEW ORIGINAL visual metaphor or schematic made from scratch and grounded in the actual semantics; do not suggest it is a pixel-accurate recording of the app. If a concrete UI behavior cannot be verified, qualify the copy or change the story. Never fabricate product performance, metrics, endorsements or security guarantees. Visual originality does not license false factual claims.

## 2. Audio first — retain the V58 hard stop

A normal new promo/ad request defaults to a narrated, music-led film, NOT a silent slideshow. Missing audio files are not a waiver. Before any new production timeline/render, inspect source for INFORMATION ONLY and recommend one truthful story; if voice language/route/music/release are unresolved, **ASK in the actual chat and END the turn.** Bundle only material unanswered decisions. If the user delegates route selection, select eligible options rather than repeating questions. An autonomous continuation without user input is not consent. Respect explicit silent or script-only requests.

When narration is wanted but real audio is unavailable, **DELIVER the complete actual audio handoff and END the turn if user input is needed:** original human-sounding script, the COMPLETE tagged provider-ready narration when model support is verified, acting notes, an exact separate original voice-design paragraph from guide 24 only if a new suitable voice is needed, official provider/model and generation/export instructions, researched appropriate music/rights/legal acquisition or a candid unresolved dependency, and a request for only missing unedited stems. See `references/115-stop-and-handoff-v58.md` and `references/112-turn-and-audio-contract-v57.md`. SFX alone do not replace requested voice or soundtrack. Never fake eligibility, subscription, licensing, listening or measured alignment. If an authorized audio tool actually exists and the user delegates, use it rather than inventing a manual step. Do not promise background work.

Only after audio routes and actual prerequisites are resolved, proceed to the requested narrated film; explicitly scoped picture studies are permissible but must be labeled. Never downgrade a blocked narrated ad to a “technical study” to bypass requirements.

## 3. Build an original motion-designed film, not recreated pages

Read `references/118-original-visual-direction-v59.md`. Start with a human situation and one verified capability; write a strong hook, narrative turn and payoff. Compare three DIFFERENT original visual mechanisms internally. Choose one, with an original spatial motif and changing compositions. Script drives the picture; do not tour pages or list features. Do NOT recreate the website, clone its interface, or render HTML as a background. For each event define starting state → caused action → changed state → how it connects to next shot. Prefer clever connected original objects, moving kinetic type, abstract 3D geometry, custom icons drawn by the renderer, cinematic materials and compositing when the story warrants them. Use real available techniques, not invented API parameters or cheap default boxes. Original film means original pixels and original choreography, not a static title plus newly redrawn fake screenshot.

**No product captures in the final film.** Verification is performed outside the rendered scene, via researched facts and source inspections. If an abstract diagram represents a feature, make it visibly illustrative; do not label it as a real screenshot or live UI. Product names and accurate functional labels can be re-typeset, but visual styling is designed anew instead of mirroring site CSS. Preserve coherent brand messaging if explicitly specified without copying visual assets. Consult the existing 2D/3D, typography, softbody, glass, camera/path, GPU and animation libraries to generate ORIGINAL imagery. Use original font choices from licensed/available font catalogs rather than copying web fonts.

Make two genuinely different original styleframes and inspect a motion slice containing the most difficult transition when feasible. Once audio is actually measured, synchronize key visual events to speech/music. Review actual film at native resolution/phone size and audible playback where supported; correct weak continuity/composition before export. A fancy material cannot repair a feature-inventory story.

## 4. Mandatory origin audit before EVERY render and final delivery

Read `references/119-origin-audit-v59.md`. Review all referenced image/video/mesh/font/HTML/CSS/audio inputs and their provenance. **FAIL/CORRECT** if ANY video layer is sourced from a product/reference URL or local project (even a cropped, modified, cached, AI-transformed or traced derivative), if the website HTML/CSS was used as layout/frames, or if assets are only uncertain rather than original/authorized. Remove and rebuild such scenes from original geometry. Avoid “temporary” site screenshots in an output directory or visual source project. If a renderer automatically captures pages, do not invoke its capture path for the ad. Preserve a short provenance note listing original generated assets and permitted separate audio. Audit original release frames and project source for accidental imports. An audit report is not proof of originality by itself; inspect what is actually rendered.

Source access is informational; do NOT require client photos/screenshots or site images for the film by default. Ask for text descriptions or product facts only if they cannot be learned from available source. If the user explicitly requests use of a specific independent image, follow that scoped authorization only. If original graphics cannot be produced with available tools, state the production blocker and deliver useful script/direction instead of secretly replacing them with site captures.

## 5. Existing execution, no reinvented toolchain

For supported narrated ads keep the v50 preproduction manifest and honest gate: `templates/preproduction-v50.json`, `templates/performance-v50.json`, `python scripts/preproduction_v50.py next WORK/brief.json`, then `python scripts/production_v50.py start SOURCE.json CREATIVE.json WORK/session --manifest WORK/brief.json`, and `python scripts/production_v50.py next WORK/session`. Guides 87/92 explain exact schema and limitations. Older screenshot/UI-capture instructions within those manuals are OVERRIDDEN BY V59. An existing renderer may support image layers and HTML capture for other purposes; **those capabilities are prohibited for this information-only ad**. Check the render source against guide 119. Use other original-generative primitives when a screenshot is suggested.

If a legitimate silent/short/locked/platform-only brief does not fit current release gate, respect user scope, report the exact limitation and deliver an accurately labeled supported artifact, not a fake final. For narrow revisions preserve accepted scope; if the existing video contains prohibited captures, remove them in a requested full rebuild, and explain if a restricted local fix cannot guarantee compliance. Never pretend review occurred. See `references/120-v59-agent-examples.md` for simple failures and passing patterns.

**BEFORE SENDING:** Did the user get the next usable result? Are audio choices/real files resolved? Are ALL visible frames authored from scratch or individually authorized, not sourced from the website/local project/reference? Are claims supported? Did we actually check output? If no, correct the result before calling it finished. Do not display this checklist as a substitute for production.
