## Phase 0 — route and state
Read `references/35-standalone-production-contract.md` and `references/00-execution-playbook.md`. Route script-only, full production, campaign, or revision. For a full film use the steps below; for a revision load the last actual source/timeline and preserve all unaffected work. Write `production-state.json` in the work directory; record phase, paths, blockers and next action. Do not load every manual into context: use the phase/recipe router, read the named files, execute, then persist results before moving on. Never invent results or evidence. User constraints override defaults, but do not waive truth, rights or release checks.

## Phase 1 — minimal product intake
Read `references/01-product-intake.md` and `discovery.md`. If local project exists inspect it read-only. Otherwise the user chooses source archive, URL, saved HTML if URL inaccessible, direct product description, or adequate screenshots. One sufficiently informative source is enough. Inspect available details and establish verified problem, differentiator, audience, proof and platform. Ask only missing essential facts in one compact message. A marketing use is commercial by default; distinguish public, noncommercial and private review. Never alter a live product or invent claims.

## Phase 2 — write and direct, internally
Read `02-human-copywriting.md`, `03-hook-lab.md`, `04-duration-and-beats.md`, `campaign-strategy.md` and `25-voice-acting-and-tagging.md`. Generate three different hook families (action, contradiction, curiosity), choose the one with a provable payoff, write the complete speaker text, review natural speech and credibility. Use one central story and at most two supporting details, reserving others for campaign ledger. Do not use default corporate hype, forced slang, generic feature lists, or meaningless calls to action. Start with the idea in the first 1–2 seconds, not a logo intro. Preserve any user-locked wording. Do not request approval for ordinary creative decisions when the user delegated them.

## Phase 6 — verify and deliver
Run `scripts/layout_geometry.py` and `scripts/audit_layers.py` on layered plans and `scripts/visual_review.py` on preview, review flagged intervals + full motion, log changes and rerender. Metrics are not an aesthetic score. Follow the V14 repair loop before final export.
Default 1080x1920, 30 fps, H.264/yuv420p AAC unless requested otherwise. Duration comes from actual audio; 15–45 seconds is a starting range, not a rule. Mobile safe areas, final readable CTA hold, matching brand. Run `validate_brief.py`, `validate_plan.py`, `check_shots.py`, `check_render.py` as applicable; review decoded shots at boundaries/midpoints and full motion, listen to final mix if possible, fix errors and rerender. Use `audio_intake.py --stage release` as documented and `release_gate.py` with actual evidence in a completed release manifest. A technically valid MP4 is not proof of good editing. Do not mark checks passed without review; if capability unavailable, deliver partial/draft and say why. Provide final MP4, editable source, narration, captions/timing/audio stems as permitted, campaign ledger, QA and claims report. Preserve actual filenames and disclose unverified areas.
