# 111 — From specific copy to visible editorial action (V56)

Read this before new voiced ad writing or picture planning. Read 107 for actual audio handoff and 108/104 for implementation choices. This guide is about transferring a creative mechanism, not reproducing one note-app example or one reference film. All product examples here are fictional with explicit assumed verified behavior. Never market them as real product facts or copy these lines blindly.

## Start with a consequence that can be seen
A feature name is not a story. A benefit adjective is not a consequence. Derive a concrete before/after from actual product evidence, and choose copy that changes what the viewer expects. Pick one primary premise and one proof. Multiple features are allowed if they serve the same story, not as a list. A claim requires evidence at its actual strength: an observed button does not prove what happens after click, a working local demo does not establish security or speed superiority, and an illustrative overlay is not a real UI feature. Keep source evidence and editorial graphics distinguishable.

### Worked example: design review, not another file-search story
Assume the real inspected product supports a pin at a specific canvas location and a text comment attached to that pin. No collaboration speed, notification or AI claims are established. Target: designers, English, public short video. The creative job is to dramatize ambiguity turning into precision, not simply enumerate pin/comment features.

Three genuinely different mechanisms:
- Miscommunication: open on “move it left” while two different objects are equally plausible; resolve ambiguity by anchoring one comment to a real spot.
- Visual contradiction: a huge arrow labeled “THIS” points between objects, then a precise small pin takes over. Use clearly editorial visuals; real product proof follows.
- Action-first: start close on the pin landing at one specific corner; pull out to expose the entire composition and the attached comment. This version begins with precision instead of confusion.

Two full candidate scripts, intentionally different in premise, not paraphrases:

A: “Move it a little to the left. Which bit? The button? The text? Oh. That corner. Just pin the comment right there.”

B: “See that little gap? That's where the comment goes. Not somewhere in a pile of messages. Right on the canvas.”

A creates ambiguity and a reveal; B creates tactile specificity immediately. Choose A if two plausible design targets and the actual pin result can be shown; choose B if single-detail footage is stronger. The examples are short; expand through meaningful visible progression or deliberate music space only where a hard duration/story merits it. Do not pad out to 25 seconds with claims. For user-specified locked copy, keep the words, and improve staging, not the text without permission.

### Example performance for A
Assuming a verified compatible expressive model, this is a full illustrative TTS block, not a universal tag dictionary. Verify the actual provider's currently supported cues before use; substitute appropriate supported cues without changing spoken words.

```text
[thoughtful] Move it a little to the left.
[curious] Which bit? The button? The text?
[thoughtful] Oh. That corner.
[playfully] Just pin the comment right there.
```

The first line should sound like an ordinary instruction, not an announcer. Second line speeds up through uncertainty. Third line softens, leaving a short recognition pause. Last line is direct, lighter, and decisive—not a scream. If `playfully` is not supported on the selected route use a verified alternate or separate acting direction. Keep the voice prompt, exact narration, and notes in distinct blocks. No cue should be accidentally narrated. For human narration provide clean copy and these notes instead. Compare actual audition; no guarantee of acting from tags alone. In an actual answer, include the complete provider setup, applicable separate Voice Design prompt, chosen music research and export steps (107/110); the example block alone is not a user handoff.

## Design actual visual action before choosing effects
Use relative beat durations until the real voice and music arrive; never call these measured timings. The following shot direction is an example of causal composition changes, not obligatory effects:

| Story phase | Start state → action → result | Anchor and implementation | What to inspect |
|---|---|---|---|
| Ambiguity | Tight crop of real design, editorial bubble “move it left” approaches two plausible elements; camera reveals both; arrow hesitates between them | Keep real canvas registration fixed; separate graphic bubble/arrow layers; use path and staged hold, no fake real control | Both objects clearly visible; overlay doesn't impersonate product UI |
| Escalation | Alternating attention between button and text, not two new title screens; scale focus and directional movement create contrast | Same canvas coordinate system, parent group and actual target crops; accents match actual speech | Eye follows successive targets; not all layers compete; no unnecessary shakes |
| Recognition | One corner becomes dominant; previous arrow shape narrows toward the corner; reveal actual pin UI at same position | Reframe with maintained anchor; actual before/after capture; cue-based reveal and pointer if accurate | No visible jump in corner alignment; actual pin matches evidence; readable at phone size |
| Proof | Actual pin/comment opens; relevant text and its anchored position visible simultaneously; reduce secondary motion | Native crop, real assets; gesture markers and short coordinated material/shape accents if useful | Real behavior and label legible without narration; hold for reading |
| Payoff | Return to opening ambiguity resolved by same canvas corner and actual pinned comment, product identity integrated where appropriate | Retain shape/position motif and settle; musical resolution not arbitrary whoosh | End feels intentional; no fresh unrelated claim or logo preset |

An optional original 3D pin hero can be used if its silhouette and physical landing make the argument clearer; construct real geometry and bevels, inspect sampling and light, match its footprint to the editorial marker. Do not fake a dimensional UI feature or use low-quality chrome by habit. The same idea works with excellent 2D typography and motion. Design at phone scale and actual native resolution; do not shrink the full website into a thumbnail or show identical composition with a different caption.

## Close the design-to-implementation gap
For each chosen shot or connected section, record a concise executable intention: actual asset path/element, layer/group relationship, original and destination visible state, which properties change, relative or measured timing, anchor/transition, and an observable acceptance check. This is not a new schema; map these to existing supported fields after inspecting compiler/renderer help. Query actual layer capabilities if needed (86 / director_v49.py) and use existing paths, sequences, components, gestures, materials and cue systems. If a planned technique is unsupported, compose supported primitives or change the treatment, not the verified claim. Do not invent an API or change the skill tools during a normal ad project.

Render representative actual styleframes with meaningful different compositions, then a short moving slice containing the riskiest transition or interaction before committing expensive full rendering. For this example the recognition-to-proof handoff is the risk: check actual middle frames for pin alignment and correct final UI. If frame sampling is the only available inspection, state that limitation and don't claim continuous playback. For low budgets prioritize opening, product proof and the hardest transition; a styleframe cannot certify motion or audio. Proceed to a full movie when dependencies and scope allow, not a delivery of styleframes disguised as a final edit. Review actual full film and sound where possible, correct observed failures, preserve unmodified sections. No mandatory extra render just for a claimed iteration number.

## Rejection and concrete recovery
- If the user says “looks like PowerPoint”, check if successive shots are actually different compositions and if real content changes. Rebuild one core action and anchor the next shot; don't apply motion blur to all slides.
- If “too slow”, locate the time interval with no new information; shorten redundant preparation or bring an upcoming action forward. Preserve necessary reading time and speech intelligibility.
- If “more motion”, coordinate purposeful entry, focus, consequence, and secondary movement; do not increase all speeds or animate every pixel. Use different motion roles and density.
- If “too many effects”, remove competing accents and preserve the core cause/effect and intentional hero material. Not everything needs 3D, and not every 3D shot needs shiny metal.
- If “script sounds like AI”, remove abstract marketing nouns, find the actual human observation, rewrite unlocked speech from that viewpoint, read for natural delivery, and revalidate claims. If locked or already recorded, request permission only when rewriting is necessary; otherwise preserve voice and improve picture editing. Re-align altered takes before retiming.
- If “where do I get the audio?”, the previous handoff failed. Supply the missing exact route and paste blocks immediately, never blame novice knowledge or repeat a generic request for MP3.

A skilled agent selects the strongest technique because it serves a real action and story. Existing technical libraries enable this; they do not replace editorial judgment. See 97 for review details and 109 for the independent trial. No independent agent execution is implied by these examples.
