# V27 — Premium editing production contract

## Operational order (do not ask the user to do this)
1. Read the product, choose the most concrete provable story. Use one central tension and one clear resolution. Build three internally distinct concepts, not three versions of the same headline. Examples: (A) an interaction visibly fails then succeeds, (B) physical objects represent a complex digital problem, (C) a surprising number becomes evidence. No arbitrary ornamental CGI. Choose based on specific original assets and a real payoff.
2. Draft speech as one creator telling a friend something interesting. First sentence must make sense on its own without logo or setup; read aloud. Replace sales language with observable actions and short clauses. Label product claims and actual proof separately. Narration should sound like a reaction, not product feature paperwork. Reserve other features for later videos.
3. Voice: use the exact user-tested original in guide 24, not an imitation of a real performer. Put the voice design description and spoken script in different messages/fields. Compile provider-approved tags using compile_voice, retain untagged captions, choose 3–5 emotional turns (curiosity, reaction, tension, understated payoff). Neutral elsewhere. Direct the *contrast* between phrases rather than stacking tags. If a robotic take, wrong pronunciation or unnatural pause is heard, request regeneration of that phrase with adjacent context; keep voice ID/seed/model when supported. Prefer a real authorized high-quality provider or user upload; never present flite/espeak as final. If no TTS tool is available give the actual user-facing tutorial and exact provider-ready script per guide 21. Confirm tags against live provider docs at use time. Do not require the user to cut up audio. If external timestamps unavailable, align by verified listening or ASR/forced alignment; missing timing remains a blocker.
4. Music: ask rights scope first, research current songs only when needed, offer 3–5 evidenced picks plus timeless options, provide authorized acquisition path. Get source audio; don't replace the user's chosen music. Analyze transients, tempo, downbeat and structural changes. The new `music_cues` produces candidate onsets, not BPM/downbeats. Listen and check. Select major beats for conceptual turns; dialogue controls informative shots, song controls a few accelerations and sound accents. Preserve rests. Avoid sound effects on every cut. Use sound_design + mix_picture for exact time cues, adjust gain against actual voice, audition in mono and on small speakers. Do not claim any track is trending without current evidence.
5. Art direction: use brand palette plus one intentional contrast. Choose type by actual assets, weight and optical sizing. Make 3 alternative style frames for the hardest shot; no placeholders or constant UI chrome. Keep a statement or object readable, with 50–80% canvas occupancy when it is the sole hero. Avoid tiny pointless annotations and fixed header/object/footer layouts. For 720 design units, leave approximately 45px at sides, 100px top and 210px bottom for essential material (platform overlays vary; verify actual platform). Use scale contrast: macro face -> clear context -> tiny deliberate pause; avoid random scale effects. Crop a real screenshot by meaningful control/section, show context before/after. Dark space should build tension, not hide lack of ideas. Use restrained realistic color and typography, avoid repetitive glow.
6. Construct a single global picture clock. Draft visual events independent of phrases: each 0.6–2.0 seconds may change framing, density, focal point, silhouette, or material, but not on a fixed timer. Important proof needs a readable hold. Multi-layer animation uses primary motion (story action), secondary (response), tertiary (lighting/optics); ensure the focal object dominates. Do not animate every element simultaneously in different directions. Long transforms use one persistent layer/group, not isolated templates joined by crossfade.
7. Implement from recipes; choose literal model/capture for proof and a semantic metaphor for one hero CGI (optionally two). Use exactly same visual anchor in adjacent shots. Four file chips -> stack -> single link, a graph line -> underline -> cursor, a button outline -> aperture -> authentic UI, or a glyph -> extrusion -> typography lockup. Reserve motif meaning; do not animate chrome rings merely because they look cool. Match boundary position, size, motion direction and velocity. If a cut needs no transition use hard cut on visual action, not random dissolves. Parent the camera to existing world, animate camera independently. Use varied shot scales, small motion overlap, anticipation and follow-through. Optional motion blur only on fast travel. Test the moving object at first/last frame and +/- 0.1 s around cut; if it jumps or stalls, adjust track endpoints and timing.
8. Advanced compositing: choose matte by purpose. For image-through-letter use alpha matte, for topographic fade use luma mask, for optically blended highlights screen/add; for shadow multiply. Keep type opacity independent of background. Composite an actual mesh render pass with typography, partial mask and independent camera; don't label display-space filters as physical ray tracing. Lighting: single large key softbox-like reflector, opposing dark fill, slim rim; rotate environment rather than constantly rotating geometry. Use roughness .15–.30 as starting point for chrome, .3–.5 for satin, increase if highlight flickers. Inspect macro and wide states. Avoid blown highlights/dark type and angular generic objects. Never reuse arbitrary exact example logo or theme as proof. Geometry and lighting settings are recommended starts, not reconstructed proprietary values.
9. Review the renderer output, not source. Inspect boundaries, plus five temporal samples per visual arc. Ask: does the viewer know what to look at, is there contrast, incremental meaning, readable product proof, smooth anchor trajectory, credible voice, a real payoff? If 3 weakest intervals are identified, fix their specific failure, not add random FX. Do a quiet read with no audio to check narrative clarity, then listen with image off for intelligibility, finally play at normal speed and on phone-size preview. If not possible, state limitation and don't mark professional review passed. Technical checks are not aesthetic ratings. Stop reporting file count as progress. Deliver a complete draft if incomplete with exact blockers, real final only after release gate. Preserve all unaffected files in revisions.

## Concrete technique routes
- Persistent object transition: create group at global time; children fixed locally. Animate x/y/scale, change child label only after an occluding matte or deliberate cut. Keep world velocity through transition. Use global compositor.
- Flowing shapes: resample matched paths with equal orientation; `morph_path`, then `trim` to animate path drawing, shape scale and opacity. Parent line and original object to same group. For complex 3D topology use tested fusion/mesh recipes rather than forcing 2D tween to fake it.
- Dynamic detail: actual native screenshot, crop portfolio first, pan toward contact with parent camera, use hold after each move for legibility. Don't manufacture controls or verified numbers.
- Layered typography: whole-line mask then independently stagger emphasized word, use `staggered_line` only when letter shaping is safe. A huge count may scale into window aperture; use actual data. Avoid generic bold headlines every scene.
- Cinematic macro: actual mesh pass, framing and reflection direction authored as tracks, separate foreground text; use contrast scrim only if necessary. Preserve silhouette and don't show reflective surface darkness as 'premium'.
- Advanced material and particles: prior engines already in skill; composite as held or animated asset rather than rewrite. Select 1–2 hero shots with meaningful function and purposeful motion. Eye comfort is more important than FX count.
