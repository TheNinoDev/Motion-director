# 122 — A do-able film direction loop for weak coding agents

This is the **current film-production playbook** for new ads. Read after 121, not every legacy script. It is guidance, not a tool, validator or exact shot template. The brief controls story, scope, audio and rights. A website or local repo supplies factual semantics ONLY, never final visual pixels. When a user has already supplied voice/music/script, use them, not a new interview.

## Pass 1 — One transformation with a reason
Write one sentence: “The audience begins believing/seeing **A**; an observable action **B** changes it into **C**; the final image proves/clarifies **C**.” Name the exact verified product fact supporting C. If the only sentence is “show brand and features”, rewrite the premise. Distinguish shipped feature from proposed/in-development feature; show “building” or “planned” without implying active security or invulnerability.

Invent three different visual *mechanisms* internally, each with an original subject that changes role. A mechanism is a consequence: an information ribbon is compressed into custom instructions, a copied script visibly loses access controls, a user-controlled key splits valid and invalid branches. A 3D icon, chrome texture, moving camera or neon glow ALONE is not a mechanism. Choose one governing metaphor and one persistent motif; do not sprinkle all the options randomly. Start with the user's story or actual voice, not the easiest renderer example.

## Pass 2 — Make a shot state map, NOT a page list
For each major beat write ONE small private record:

```
BEAT / voice phrase: actual or provisional time; narrative question
SUBJECT: what shape/word/object is currently dominant?
ENTRY: exact starting appearance, relationship and scale
CAUSE: what acts upon it? pointer, barrier, split, fold, impulse, rule
ACTION: observable transformation/path/state mutation (not mere float/zoom)
RESULT: readable state that would not exist without the action
NEXT: which exact object / geometry / direction connects to next beat?
IMPLEMENT: existing supported primitives, never guessed properties
CHECK: frame before / peak / after plus real movement when possible
```

Visual role variation should be real: a giant kinetic graphic, a burst or patterned field, a spatial object/reveal, a readable proof close-up, an editorial empty-space contrast, a final callback. These are optional roles, **not** a mandate to use all six. Adjacent long major beats must not be the same code window/backplate with a different title unless a deliberately escalating repeated structure is essential to the story. Typography may itself be the main action when its shape/meaning transforms; subtitles alone are not choreography.

## Pass 3 — Render 2 styleframes and a REAL moving microtest
Do not write 500 lines or a full 25-second render before checking whether the concept actually works. First produce two different original key images with actual text/subject in meaningfully different compositions (not just green vs blue). Then implement **one 1–3s high-risk movement**: whichever metamorphosis carries the story, not merely an intro zoom. Inspect frames just before action, at its peak and after its result, **plus the actual moving clip** if playback is possible. If the object only moves slightly and its function still seems unchanged, fix the shot before duplicating the same approach across 25 seconds. A contact sheet diagnoses composition, not precise motion or audio.

Original visuals may be written from scratch using the existing toolchain: blank HTML/CSS/SVG/Canvas scenes, Python/Blender vectors/meshes, kinetic text, particles, masks, camera-path layers and compositing. **Using self-authored blank HTML/CSS for an original render is allowed; copying the website's HTML/CSS or DOM layout is prohibited.** An independently designed diagram of a generic code editor or interface is acceptable if it is clearly an illustrative invention and not marketed as a genuine screenshot. Don't clone page layout, brand artwork or stock fonts from the site. Real names/factual labels can be re-typeset in new original typography. A user explicitly granting use of a particular visual asset is a narrow exception.

## Pass 4 — Finish a continuous editorial rhythm
Build a 20–30 second film around a few meaningful transformations, intentional holds and shifts of scale/energy. Avoid slow pans used just to fill narration. A visual event can cross several sentences; a sentence can contain multiple animated actions. Match actual stressed words, musical section changes and purposeful effects when stems exist; never invent word timestamps from text length. Frame a hook within the opening seconds, then develop a graphic question and resolve it with changed visual meaning. Contrast a busy scene with a quiet proof frame instead of making every frame equally neon and busy. If it uses 3D, check silhouette, geometry, materials and perspective at native resolution. **Motion quality is not visual complexity; original art can be restrained and still compelling.**

To help weak models avoid the “static moving card” trap, periodically compare representative filmstrip frames in sequence. Ask whether at least one meaningful subject changes its identity, topology, relation, state, number, capability or role between two major events. If only headline/background intensity/position changes during several consecutive long segments, storyboard a causal transformation. This is a qualitative editing test, not a rigid pixel-motion quota. A deliberate 1–2s freeze, pause or long hold can be correct when resolving the story or respecting actual spoken/musical timing.

## Pass 5 — Read the film like a viewer, not a developer
Inspect the actual opening, transformation, proof and ending. Could the viewer tell the story without the marketing headings? Are real product facts truthful and in-development capabilities labeled as such? Does the same motif change meaning? Are there readable holds and transitions that match actual audio? If one section feels like a slide, rework **the visual action**, not only glow, speed or number of frames. If a renderer fails, change technique where needed but preserve the editorial mechanism. A successful video decode doesn't prove good art, and an AI cannot honestly assert it listened if only a waveform was examined. Deliver verified artifact; disclose the precise remaining inspection or licensing blocker.

## Visual rescue example
Weak: code document floats on green plate. Title changes `Obfuscation` → `Custom VM` → `Bound access`, plate remains central. Better, subject to grounded real/planned features: original source glyphs **fracture and remap** into new instructions; these instructions **assemble into a moving interpreter/virtual machine ring**; an original key-device pairing **separates valid and invalid access paths**; then the recurring glyph closes as a protected object labeled **in development**. That is a stateful semantic transformation rather than an animated feature list. This is an idea, not an assertion that the actual product already implements every protection successfully.
