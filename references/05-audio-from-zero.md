# Audio production for a beginner
**Text-to-speech (TTS)** converts script text into spoken audio. **Speech-to-text (ASR/transcription)** converts audio into text. **Forced alignment** locates known words/phrases against voice audio. Do not confuse them. If the user gives script and music, generate VO from exact script, then align. If user gives VO instead, transcribe or align to supplied text; do not resynthesize unnecessarily.

## Workflow with real files
1. Keep `inputs/script.txt` plain text, no performance tags unless your actual provider explicitly supports them. `script-direction.md` notes emphasis, voice/language and intent. Keep approved text unchanged. Break phrases at punctuation or natural breath, not arbitrary every N words. Ask for pronunciations only if truly ambiguous.
2. Probe TTS: installed engine or authorized connector/API, verified voice availability, permission/cost. Prefer high-quality expressive voices when available. Provider voice generation is not included here. Use provider SDK/CLI docs matching installed version; save actual file, then ffprobe. No unauthorized cloning. If no capable TTS, request recorded voice or use labeled scratch synthesis only with appropriate delegation. `prepare_audio.py` can generate espeak draft per phrase (robotic, not premium), exact phrase offsets from actual PCM frames. It does not produce word-level timing.
3. Normalize input to mono PCM WAV 48 kHz for VO, stereo WAV for music. Measure actual duration. With provider word timing, validate increasing times and script fidelity; with local ASR/alignment use installed Whisper/whisper.cpp or forced aligner if available (check docs and model permissions). If unavailable, phrase lengths from separately synthesized WAVs are reliable phrase boundaries but not word timestamps; avoid fake word sync. Manually listen and mark cues if environment supports it. For supplied whole VO with no aligner, use phrase estimates explicitly marked or ask for timing if exact sync required. Export SRT with verified phrase timestamps; do not imply automatic transcription if none ran.
4. Music file gate: user supplies MP3/WAV/M4A/FLAC/AAC/OGG or other decodable audio, or explicitly delegates/waives. Verify it decodes. Do not use unrelated music; respect permission. Choose offset and section based on energy and voice. Analyze transient/onsets via available tools; optional simple RMS onset candidates are not beat tracking or verified BPM. Audition if possible. Do not claim exact beats from frame changes. Keep original untouched.
5. Timeline clock: use actual VO duration + lead/tail. Listen for words, pauses and breath. Map motion to phrase start/end, emphasize actual spoken keyword when known, use actual music cue if available. If beat conflicts with voice, prioritize speech. Sound effects only for meaningful actions, not every motion; subtle mouse click, impact, whoosh or tonal texture, sourced/authorized or synthesized. Never add noisy effects just to increase count.
6. Mix: dry voice first; music under it, begin around -18 dB relative gain, adjust by ear and measured signal. Duck when voice starts; attack around 20–60 ms, release 200–500 ms as starting points. Do not assume peak difference equals perceived loudness. Avoid clipping: limiter at ~-1 dBFS, measure loudness (starting social target around -16 to -14 LUFS integrated, not platform guarantee). Save stems and full PCM mix. AAC encode and check final audio. Do not normalize individual phrases so aggressively that performance dynamics vanish.

Example commands (test actual binaries; replace paths):
```
ffmpeg -v error -i voice.mp3 -ar 48000 -ac 1 -c:a pcm_s16le voice.wav
ffmpeg -v error -i song.m4a -ar 48000 -ac 2 -c:a pcm_s16le music.wav
ffmpeg -hide_banner -i mix.wav -af loudnorm=I=-15:TP=-1.0:LRA=7:print_format=json -f null -
```
Last command measures via a filter pass; it does not write a normalized file. Implement two-pass loudness normalization only with actual measured values. Never claim LUFS pass without inspecting measurements. If music is missing, do not start full editing unless the user waived or delegated it. Script/storyboard conceptual planning is okay; final timeline waits for actual audio.
