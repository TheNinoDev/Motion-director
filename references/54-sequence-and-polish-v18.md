# Coherent sequences and polish (v18)
The quality gap is chiefly in composition, staging and temporal continuity, not the number of effect names. A sequence must make an idea visible. Do not blindly use a chrome ring or floating dashboard.

## Select a visual grammar
- Consolidation: several actual categories / objects visually converge into one. Use the sequence engine when the claim is supported. Keep the focal anchor and consistent shape, make the convergence visible, reveal the actual interface.
- Reveal: show a cropped detail and then the real context. Do not make a fake cursor click prove functionality. Use a real capture or authorized static screenshot.
- Compare: show before and after using two supplied or captured verified states. Never imply actual competitor deficiencies from invented mockups.
- For search, rejection, success or task completion, consider the existing UI, expressive or layers engines; animate the state change and reuse the same location and object.
- For abstract premium materials use cinematic, material or scene3d only if the metaphor is necessary. Use a real brand-specific symbol, not a generic torus by default.

## Method for weak agents
1. Write a five-beat sequence from the verified script: concrete opening, escalation or question, visual turn, evidence, payoff/CTA.
2. For each beat identify one foreground object, its incoming and outgoing position/state, one secondary motion, and what remains still. Use meaningful motion; do not assign an ornament to every sentence.
3. Mark boundaries in actual voice/music frames. Build a coherent scene with sequence or layers, rather than seven interchangeable slides. Use 1–3 optical effects per visual event only where useful; keep UI and text clean.
4. Render three non-consecutive key moments plus one transition. At mobile scale inspect headline, proof and focal hierarchy. If disconnected, fix object position and direction before adding effects. If a shot feels empty, improve scale/crop or replace visual metaphor; do not automatically add grid lines.
5. Render preview; run visual_review.py. View all phases, transitions and ending, listen to audio, fix. A technical check is not visual approval. Log each issue and correction. Do not score the output as a percentage of a reference; no calibrated metric exists.
6. Do not include artificial data, invalid claims, fake UI or a reference creator's branding. Final production uses the supplied actual voice/music, rights, and release checks.

## Concrete controls
Sequence engine: beats, labels, crop, motion, paper, background, foreground, accent, layout, texture, samples. Reuse prior V14–17 effects via neighboring unified shots where motivated; do not stack all the capabilities in one shot. Motion samples integrate actual subframe renders in approximate linear light, not merely blur the whole image; boundaries are clamped to avoid mixed cuts. Higher samples cost more CPU.

## Visual QA questions
Is the first visible image meaningful? Is typography active rather than generic subtitles? Does a shared motif develop and pay off? Can a viewer identify the product evidence at phone size? Are all accents semantically meaningful? Does the final card hold long enough? Are there any repeated compositions without new information? Are any text lines or critical UI controls clipped? Is the audio's strongest moment synchronized to a visible change? These require looking and listening, not solely image-difference metrics.
