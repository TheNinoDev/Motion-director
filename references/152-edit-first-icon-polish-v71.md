# 152 — Edit first; icons polish the scene (Ads Wizard v71)

## Correcting the production mistake

The user has explicitly rejected *both* v68's one-large-artwork-per-scene approach and v70's attempt to solve it with more icon actors. The new actual 24-second RobloxLARP video still shows an isolated code document, isolated pink stolen document, isolated shield, isolated VM chip, isolated key/lock, and a predominantly centered upload card under repeated uppercase headings. The result is a more polished **asset slideshow**, not an authored film. The correct fix is not more or better imported icons. Icons should typically be the **final-stage UI polish** on work whose core animation is already effective.

## The priority pyramid

1. **Meaning/story and audio:** the promised visual consequence, actual VO phrases/music/SFX cue points, strongest visual question and answer. Do not invent product claims.
2. **Editing and direction:** staging, typographic timing, camera framing, continuity, transitions, energy variations, shot grammar and cause/effect. Plan the next shot while designing the previous one.
3. **Native-editor animation:** screen transforms, grouped movement, masks, cropped reveals, focus shifts, depth, connected timelines, contact/response, light where motivated. Build an editable native timeline, not a substitute PPT renderer.
4. **Polished visual components:** designed cards, buttons, browser/panel motifs, progress states, tags, badges, input fields, status chips, outline typography, thin separations and intentional layout.
5. **Assets as finishing details:** restrained, cohesive Solar Bold/Bold Duotone SVGs inside those components, where an icon clarifies a button/status/category/action. A small icon should make an existing button/card feel professionally designed, not carry an entire scene.

The pyramid is a decision order, not a literal requirement for every medium. For photography, 3D product showcases, mascot films or content where an illustrated object is genuinely the story, the object may be a hero. Do not ban legitimate subject-driven imagery; **reject default isolated icon heroes in software/tech ads.** A purposeful standalone product icon can be appropriate on a deliberate end frame, but only when the composition earns it.

## What specifically counts as supporting use

GOOD:
- A button has a short caption, pressed depth and responsive ripple; a small key glyph clarifies `Authorize` and changes tint when accepted.
- Three staggered cards form an actionable sequence; small document, shield and check icons sit *inside* their top-left badges and never fly out to become the whole shot.
- A lock indicator lives *inside* a code editor toolbar; the code pane moves/changes and the badge briefly updates to explain the transition.
- A tiny upload arrow appears *inside* an upload action button after the panel is already moving; the loading state transforms while the camera follows the UI.
- Icons live in a coherent family and are treated as component details with clear padding, baseline, radius and optical weight.

BAD:
- Entire frame is one enormous shield icon, header `PROTECTION`, empty background for two seconds.
- Remove the shield, replace it with one giant microchip, and change only the title.
- Add three flying keys as a forced fix when the underlying film still has no composition or story.
- Build more elaborate asset art but leave the same central pedestal shot, gradient and bold title.
- Introduce arbitrary glass/shadows/particles/swooshes to hide a missing visual idea.

## Actual step-by-step agent protocol

### Step A — storyboard without external icons
For each beat write: `audible phrase | focal visual sentence | primary editor action | before/after | camera/depth | following handoff`. The main action should be a verb such as `fold`, `split`, `reorder`, `reveal`, `dock`, `mask`, `track`, `select`, `expand`, `trace`, or `resolve` and refer to **real visible components**. A verb like `display icon` is insufficient. Build two visibly different compositions from the same script, then select the stronger one.

### Step B — native proof first
Render a short native-editor motion proof with only layout, type, cards, shapes and motion. View at normal speed on a phone-sized preview. If the sequence looks like successive title slides without artwork, the concept fails. Re-stage it **before sourcing artwork**. A plain shape can be excellent as a mask, typography underlay, indicator or animated control; it should not substitute for an action.

### Step C — restrained asset pass
Now inspect which controls need a glyph. For a typical software ad, Solar Bold or Bold Duotone is a useful default family, not a mandate. Choose one consistent icon style and semantic size relative to the hosting component; optical alignment and contrast matter more than icon count. If the icon must grow into the hero to make the scene interesting, return to Step A. Record asset provenance and license; do not borrow website/reference-video artwork without explicit permission. Assets may arrive via the official static package or user-authorized source. Apply only safe SVG rendering.

### Step D — performance and seam review
SFX should emphasize clicks, confirmations, UI contact, transitions and causally important changes; no repeated whoosh wallpaper. View the film both *with* and *without* icon layers. Hide icons for the editorial-dependency test, not for release. The experience should still make sense. Review at actual speed and 0.5x. Ask whether a button genuinely behaves like a button, a card like a card, and whether the next shot is causally connected. Review every unexpected idle hold; don't add decorative perpetual motion as a compliance trick.

### Step E — QA and repair
Run `scripts/edit_asset_role_audit_v71.py` on the shot plan for warnings and `scripts/seam_review_v66.py` / `scripts/hold_audit_v65.py` on the MP4 when useful. These scanners cannot judge taste; the director must watch and repair. If an asset acts as an unmotivated centered hero, remove it and replace the underlying *editorial idea*, not just move it to the corner. If five different scenes repeat `big heading / big symbol`, redesign shot grammar.

## Correctly grounded RobloxLARP reinterpretation (original visual concept, not production footage)

- **Ownership:** an editorially staged source panel enters from the edge, code columns set in motion reveal someone else's duplicate. A small document icon could sit in the file tab, but the panel relation is the point.
- **Threat:** two panels separate spatially as the unauthorized copy loses a visible status chip. Rather than a floating thief icon, use an animated label/state in the card and typography that changes meaning.
- **Protection:** the panels sweep into a deliberate masked reveal of a permission workflow. A small lock glyph appears inside the `Protect` control after the component is clearly established.
- **Proof/payoff:** button press and state change carry into the next shot; a small checkmark in a badge communicates completion. The payoff typography owns the frame, not a large shield sticker.

These are teaching examples, not required creative instructions. Claims and user-provided scripts/audio remain locked; mark planned capabilities accurately.

## Approval questions

1. Does the sequence work if *all SVG/PNG/emoji layers are hidden*?
2. Can you describe each scene by what happens, without mentioning an icon noun?
3. Are the icon layers anchored to an actual card/button/toolbar/state rather than floating center-screen?
4. Do camera/transition/motion/SFX decisions tell the story before the decorative pass?
5. Does icon use improve the polish of an existing design rather than create a new slide?

Do not game these questions by hiding icons over a blank video. Change the underlying edit.
