# 149 — ENSEMBLE MOTION: scenes built from relationships, not slides (v74)

## Why v73 still failed
The user's most recent 24.5-second full-HD render still reads as `one object + one headline → next single object + next headline`. The shapes move, but the composition has no evolving cause-and-effect. Greater pixel change, more cuts, prettier SVGs, or smoother easing do not solve the problem. **The primary unit is a connected action between several elements, not one complete static layout per narration clause.**

## Required preproduction rehearsal: a 4-layer causal score
Before rendering, design each meaningful sequence as four cooperating roles (not a numerical quota, and not four required graphics):
1. **Actor / primary action** — what *changes*, with a readable origin, motion, and result. Choose a verb: split, collide, unwrap, reveal, absorb, latch, reroute, reject, cut through, reshape, regroup. A mere float/spin/zoom is not enough unless the movement itself expresses the story.
2. **Responders / consequences** — foreground, background, interface affordance, second object, shadow, echo, or camera reacts to the first action. Their timing and paths differ; if both are moved by the same group transform, the scene usually needs a more interesting relationship.
3. **Typography / guidance** — text enters as a response to the action, labels a consequence, is occluded or pushed by an actor, or exits through the same physical transition. It does **not** autonomously declare a completed slide first. Text must support understanding; do not require reading to comprehend every major action.
4. **Forward bridge** — begin preparing the next scene *while the current action is still happening*. A moving edge, handed-off object, direction of travel, growing mask, camera orbit, transformed material, held color shape, sonic prelap, or motivated contrast is carried across the boundary.

**Use these as interacting relationships, never as four independent decorations.** One brilliantly directed character or item can dominate, but nearby elements should react. A beautiful single-object transformation is allowed when it genuinely changes meaning and flows forward. Do not insert arbitrary icons to satisfy a count.

## Time structure that prevents the `complete slide → wipe` effect
The action in a scene does not need to begin and end on the shot boundaries. Design overlapping arcs:
- **Before cut:** previous state is still visible; an element responds; the successor is *seeded* as a color, outline, mask, movement direction, surface, detail, or audio lead.
- **At cut/bridge:** the action progresses, not resets. Preserve a motion tangent, spatial location, actor identity, recognizable contour, or clear *contrast purpose*.
- **After cut:** the previous action produces its payoff *inside the new scene*, while the next action starts. Do not reveal a new finished poster after a generic full-screen wipe.

Use matched action, match on shape, graphic collision, foreground occlusion, through-object camera move, typographic reflow, or deliberate hard cut on sound and meaning. A clean cut is often better than a forced morph; there is no requirement for every seam to have a transition effect.

## Why simply 'multiple objects' can still fail
Bad: a code card, a tiny key and a padlock orbit each other while a text title hangs above. That is an animated slide with stickers.
Better **illustrative mechanism, not a copyable scene recipe**: the running source visually divides; its split forces a nearby verification control to change; this displacement pushes typography and exposes a negative-space path that carries into the next action. Every element earns its place through a consequence.

## Director's concrete working notation
For each 2–5-second visual movement write one sentence: `X acts on Y; Z reacts; text resolves ___; W begins the next scene before this one ends.` Specify element IDs, depth, staging, cause and result, anticipation, overshoot where purposeful, and exact shared seam anchor. Keep locked user-supplied voice and music; design SFX based on actual action and carry its tail when a transition needs it.

## Cheap-looking patterns to reject at storyboard stage
- `background + one centered card + headline` repeating three times, even if the card is animated.
- All active elements take exactly the same ease curve, rotation or scale; their motion is mechanically coupled but not narratively related.
- An actor stops, the frame settles, then a generic wipe presents another actor.
- Every spoken phrase instantly creates a new card or background instead of developing the current visual sentence.
- Icon swap mistaken for an action; extra glow, particles, emoji or SVG used to disguise a missing scene idea.
- Camera motion used as the only action: moving across a finished static design is not the same as storytelling.

## Corrective loop
Render a rough 3–5-second section **including its entrance and exit**. Watch at 1x with the real sound. Hide text and ornamental icons once; if the physical/graphic action is invisible, rewrite it. Then do a simple reversed test: freeze the primary actor. If the secondary motion still appears unrelated, remove or reconnect it. Finally render both sides of the next seam and check what the viewer follows across it. **Do this before polishing UI radii, fonts or SFX.**

## Consistent creative boundaries
No copying other videos' pixels, transitions or asset designs. Product websites are informational except explicitly user-authorized isolated owned branding. Solar/Lucide icons may unobtrusively support controls after staging is solid; they must not turn the ad into an icon gallery. Optional subagents may independently challenge the story, but only the director chooses one connected timeline.
