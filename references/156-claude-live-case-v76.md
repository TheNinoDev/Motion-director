# 156 — What the new Claude film actually teaches (Ads Wizard v76)

## Grounding
The user provided an actual 19.8-second RobloxLARP vertical film, 1080×1920 and 30fps, and the full execution log. We compared it with a prior 24.6-second Ads Wizard test, which featured repeated centered panels and headers. They do NOT have the same scripts, durations and briefs: this is informative editorial evidence, NOT a controlled model competition.

## Visual progression, approximately timed
- 0–2.4s: one code-card subject is authored and made readable; a little glow supports it.
- 2.3–3.4s: this same card shrinks and joins a multi-item library. New cards stagger in as a reaction, not as unrelated wallpapers.
- 3.5–4.95s: an illustrated shield draws and its successful state becomes a small card badge.
- 5.75–6.55s: a separate creator card physically arrives in an empty library slot, and the destination reacts at contact.
- 7.2–9.3s: cursors travel into specific cards; those cards highlight and show actions. Microinteraction explains what users do.
- 9.3–10.05s: the library makes way for the original hero to return to the foreground; transition changes focus, not just colors.
- 10.55–13.2s: source text changes and multiple shells/lock activate at different times around the same underlying card.
- 13.55–16.1s: code fragments arc, fall, react and clear; attempted extraction becomes an action with physical consequence.
- 16.15–19.8s: the protected card moves toward a resolved final brand/message with underline, supporting text and a CTA.

## Actual execution behavior
Claude first inspected the uploaded v75 package, then resolved missing voice/song inputs. Once supplied, it measured narration pauses and song dynamics. It authored a deterministic Pillow frame function with reusable hero_state, hero_sprite, lib_card, caption and protective-shell components, instead of letting separately completed scene templates drift apart. It generated several native stills and a chronological overview before full export, then fixed hero scale, cursor targets, font sizing, wordmark baseline and clipping by editing coordinates and font bounding boxes. These were observable source-code changes, not declarations of polish.

The soundtrack/SFX mix was measured; SFX gain was reduced and voice gain was increased to improve balance. This is signal-level evidence, not proof of subjective listening. A failed background render was identified; foreground rendering was then used to produce the actual video.

The first full export contained 594 source frames. The existing every-two-frame scanner sampled 297 frames across nine pages and correctly reported visual_review_done: False. Claude separately examined those sheets, repaired the library reaction, an unpleasant color crossover, and a small/weak outro, then rerendered the actual video and checked it again. Its final review reopened FOUR of the nine pages, NOT all nine. Claude admitted the final audio was not personally auditioned. Never describe that as perfect QA.

## Transferable decisions, not copied designs
1. Design a single evolving visual subject/relationship, not a headline-per-feature slideshow.
2. Change what it MEANS: a private item becomes part of a collection, a chosen item, then a protected one.
3. Attach cause to reaction: slot receives an object and flashes; a cursor selects and a card responds; a lock engages with supporting motion.
4. Different phases can have distinct density, accent, spatial framing and camera relationships while retaining one story.
5. Make the animation deterministic and source-editable. The native compositor is useful, but renderer choice must fit the desired film.
6. Review before, during and AFTER full rendering. Fix exact geometry, visual continuity and audio mix rather than add generalized effect quotas.
7. If a final page or soundtrack was not reviewed, say so.

## Limitations
The Claude ad is not automatically perfect: its library and end hold relatively long, some visual language is still code-card-like, and the audio review was explicitly incomplete. Its success is a direction for future decisions, NOT permission to copy its code art, audio, layouts, cursor graphics, frames or exact scene sequence. Client websites and local projects remain informational except separately permitted individual visual assets.
