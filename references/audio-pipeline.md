# Audio-first workflow

## Assets and narration
1. Validate script and user-music gate. Probe the supplied file (FFprobe or equivalent); decode a working copy to PCM WAV 48 kHz, preserve original. Do not delete originals. Keep music stereo, VO mono/stereo as appropriate. Accept common decodable formats rather than demanding MP3.
2. Parse script into spoken lines and nonspoken direction. Preserve exact final words (user-written or agent-written and finalized); make performance plan (tone, intensity, emphasis, pause) without rewriting. If script is ambiguous, clarify only necessary details. Choose an authorized voice (user preference or appropriate natural default), generate phrase clips using available TTS or recorded voice. Concatenate with intentional pauses. Listen to pronunciation, artifacts and clipping if playback is available; regenerate faulty phrases. Do not invent TTS capability. If only a browser TTS is available, it is usable only if actual audio file export is possible. No secret/API-key leakage; disclose cost/credentials before invoking paid services if authorization is needed.
3. Obtain real word/phrase timestamps from provider alignment, forced aligner or manual review. Word timings can be approximated for rough preview only; verify before claiming accurate sync. Manifest records spoken text, start/end seconds, confidence and alignment method. Caption text may use a shorter faithful emphasis phrase without changing narration, unless user wants verbatim captions.
4. Analyze song independently: tempo candidates, transients/onsets, musical sections, downbeats, energy and silence. Automated peaks are candidates, not confirmed beats; verify by playback when possible. If song length differs, trim a suitable passage, crossfade phrase-aligned loop if allowed, or let intro/outro carry music. Avoid audible mid-phrase chopping. If vocals clash with narration, prefer instrumental sections or reduce track during VO; do not silently substitute the song.
5. Build audio edit and cue sheet first. Give each phrase meaning and set speech duration. Pick music cue times for emotional pivots, major cuts and CTA when feasible; edit visual timing to the soundtrack but never distort speech rhythm to fit every beat. Prelap music/SFX, use J/L cuts for cohesion. Add silence/breaks deliberately.

## Mixing
- Keep dry VO, music bed, SFX and final mix as separate assets. Never overwrite originals. Optional de-ess, high-pass around 70–100 Hz if necessary, mild compression, gentle EQ for clarity; verify not overprocessed.
- Suggested starting gain: music 12–20 dB below narration during speech, recover during gaps; use smooth sidechain ducking or keyed envelope. SFX below speech unless planned impact; duck around sibilants. Do not set gains solely by peak amplitude; listen and measure.
- Typical social master target -14 to -16 LUFS integrated, true peak <= -1 dBTP (not a mandatory platform standard). Use two-pass loudnorm or equivalent and confirm output. AAC 48 kHz stereo in MP4, ~192–320 kbps. Leave short tails for music and reverb, no clipped first/last words. Do not change user's music pitch/speed without reason and permission when significant.
- SFX palette: short soft click/tab tick on UI; subtle whoosh for actual travel; low impact/metallic hit on meaningful hero; gentle riser to payoff; reverse texture only if suitable. Source licensed effects or synthesize simple ones; keep style consistent. SFX follows action, never pile the same whoosh on each scene.
- Cue sheet: time seconds, layer name, intended action, gain envelope, exact asset, verification state.

## Practical tools
Use TTS provider or local engine installed in environment, forced alignment if available; FFmpeg for conversion/mix; audio waveform/beat tools for candidate detection. This package includes `scripts/probe_media.py`, an optional FFmpeg + Python stdlib analyzer (no TTS, no semantic audio understanding). It returns onset candidates, not actual beats. Use real playback/manual confirmation before claiming synchronization.
