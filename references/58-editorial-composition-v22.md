# Editorial composition and polish — phase 4/5/6 amendment

The v21 preview received a lower subjective user evaluation than v20. Avoid treating new features as evidence of creative progress. In v21 the point-field assembly occupied long intervals, the UI remained relatively small, the inset screenshot competed with type, and many frames repeated the header / centered object / footer formula. The historic brand video includes very different densities and scales, graphical badges that share a camera move, typography that is itself an object, and rapid product evidence. Translate those observations into the following standalone rules; the original reference clips are not needed.

## Decide the composition BEFORE the renderer
1. Pick the single concrete story. Mark its four or five meaningful visual beats on the real audio timeline. A beat is an idea change, not a fixed number of seconds.
2. Select an existing shape motif from actual product artwork or interface. Do not default to a ring, particles forming a letter, or generic metallic shapes. If the product is the visual, do not bury it under effects. Use a hero CGI object only when the visual metaphor makes the message easier to understand.
3. Plan variation in size and location: opening may fill the complete frame with type or evidence, the next shot can be an extreme detail, another may put type on a moving visual surface, and a quiet beat can hold a meaningful image with little motion. Do not animate every word by scaling alone. Reveal with a mask, change scale and placement, then use a short stable readable landing.
4. Include at least one *actual* change in visual representation: e.g. a scrolling texture turns into a single statement, a sliced interface aligns into one genuine screenshot, a crop pulls back to its context, or multiple real UI states are organized spatially. Choose only if it advances the message. Do not imply that a decorative montage is a demonstrated function.
5. Give the proof enough real pixels. A screenshot floating at half canvas width is usually illegible on a vertical mobile feed. Use a specific readable crop, and then a full-context shot if valuable. UI animations should use real captured states. Do not invent interactions or data.
6. Polish with a consistent palette, tight tracking at large scale, clear weights, thin supporting rules where warranted, and restrained optical effects. Make the focal object and foreground type contrast from the background. Avoid glows around all text, permanent grain, excessive microtext, repeated full bleed UI windows or constant overshooting movement. Intentional quiet is valid; accidental empty frames are not.

## Recipe choice (no historical file access)
- A crowded story opening: `wall` clears a space for one voice-synchronized statement. Pair with an actual detail in `shutter` to suggest consolidation. Avoid using this as an intro for unrelated stories.
- A product discovery: `macro` starts on an actual detail and moves to a related crop. Follow with `folio` when context is important. For an intentional user interaction choose the existing UI engine with genuine sequential states instead.
- A sharp reveal: `poster` with a high contrast palette; `aperture` is literally a photo-filled text mask, so choose a short word and a crop that makes the letterforms readable. Do not use on small copy.
- A short brand closure: `signature`. Keep the brand and CTA visible for at least the length needed at spoken pace. Do not hold a static endcard for half the video.
- For genuine CGI/selective motion use fusion/studio/scene3d, preserving material and camera continuity. Mix with editorial shots. Review the intermediate actual image(s) rather than assuming a configuration is beautiful.

## Mandatory comparison and revision
At preview stage, inspect at least 3 sample frames per shot and 2 close to each transition, and listen/watch when available. Choose ONE main problem per weak shot: hierarchy, crop, composition, detail contrast, pacing, motion, narrative or lighting. Edit high-impact problems first. Never change the script unnecessarily to compensate for poor graphics. Use the existing visual_review.py, plus the new editorial contact-board script for exact boundary frames. Mark issues as observed, not aesthetic metrics. Fix offscreen essential text, unreadable source crops and empty starts; rerender and compare. Do not claim that a lower blur score or larger palette represents better style. Document aesthetic limitations if only still frames can be inspected.

The new renderer is an additional native-size 2D technique library, not a 3D physical compositor or a replacement for the older engines. It has no automatic human-level creative judgement or final quality guarantee. The v22 example is a technical study; the real production still requires actual voice, selected authorized music, original assets, truthful copy and final release review.
