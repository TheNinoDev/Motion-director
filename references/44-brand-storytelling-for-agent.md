# Brand Storytelling: pre-solved production patterns (no references required)

The historical development research covered nine vertical motion-design videos. This guide is the **usable result**; the agent should not seek or need those original files. The last case demonstrates the design of a transformation narrative: show what the user believes, expose an honest contradiction, break the old presentation into minimal structure, hold a quiet reset, reveal an authentic new direction, show evidence, and return to the opening motif with changed meaning.

## Production logic (not mandatory literal script)

| Beat | Typical start if 25–35s | On-screen structure | Recommended engine | Narration intent |
|---|---|---|---|---|
| Establish world | 0–3s | real UI headline tightly cropped, camera reveals context | ui | relatable specific assertion |
| Contradiction | 3–7s | large highlighted phrase + authentic contrasting UI | type, ui | why this is not quite right |
| Demonstrate sameness | 7–12s | same screenshot keeps layout, visual treatment changes meaningfully | ui, optional brand | show one issue, not 10 features |
| Strip down | 12–16s | interface skeleton/wireframe becomes fewer rectangles | expressive/wireframe | honest realization |
| Empty center | 16–20s | hold cursor/blank with 0.2–0.8s of deliberate quiet if sound supports it | expressive/hold or ui | hinge, not filler |
| New identity | 20–26s | selective CGI hero + real new product imagery | material, scene3d, ui | introduce change |
| Proof montage | 26–32s | 2–3 actual evidence tiles; one metric if verified | ui, data | benefit made tangible |
| Callback/endcard | 32–35s | opening form returns with new meaning; real brand + URL readable | type | natural CTA |

**Do not invent an actual rebrand.** For products without a historical redesign, reinterpret old/new as a real, verified problem vs authentic product solution. The user must have a website/project/source brief; the skill contains no marketing facts about their app.

## Motion design principles from frame study

- Hierarchical scale: giant headline, small caption, huge negative space; prevent all text from competing.
- UI semantic match: an authentic section is captured once and re-framed, NOT replaced with an invented look-alike when demonstrating a feature.
- Controlled color evolution: palette shifts are meaningful; do not imply a colorway is an available product theme unless verified.
- Unbuild before rebuild: wireframe reduction, caret hold, and a sharp contrasting reveal make the second half impactful.
- The look changes without changing all variables. Retain one shared anchor (logo center, caret, screenshot title, motif shape) as a bridge.
- A dense visual sequence should have a still period soon after. Do not add unnecessary whooshes during the quiet hinge.
- CGI accents only at moments of narrative status; typically 0–2 hero CGI shots in an ordinary product ad.
- Explicit before/after claims, feature counters, dates and awards need proof. Do not show fictitious metrics as factual.
- Endcard duration typically 1.5–2.5s; verify safe area on phone and CTA legibility.

## Exact safe execution route

1. Identify genuine problem/contrast from source, then choose actual screenshots/claims.
2. Write 3 distinctly different non-corny hooks (not one word swapped). Choose one with a visual payoff in under ~7 seconds.
3. Finish a human sounding script. Put ElevenLabs/Fish tags in TTS input, preserve clean captions as separate text; no tag should be spoken aloud.
4. Acquire actual voice, confirm total length and align meaningful words. Ask music only if needed; verify current trend and rights when claiming viral/music legality.
5. Use `starter/unified/production.py` and `examples/brand-story-project.json` as the executable SHAPE, not as a content/script model. Map voice beats to integer `frames` with overlap math.
6. Choose no more than one primary animation per beat, one secondary detail max. Use honest photo/UI proof as soon as script makes a product promise.
7. Render silent preview, inspect 12-frame contact sheet, inspect transitions and frames in video. Fix errors and only then run mixed `--final` video.
