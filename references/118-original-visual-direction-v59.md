# 118 — From semantic facts to an entirely original film

This guide is the agent's replacement for the legacy “capture the real website UI and animate it” direction. Read 117 first. All visuals must originate inside the production tools or from a separately authorized independent asset, not from the source website/project/references.

## 1. Extract facts, then close the source
Make a short fact brief before designing. Separate: product identity and audience; verified functional verbs (search, compare, publish, review); real limitations; intended result; supporting reference for the *claim*. Do not carry over pixel screenshots, extracted fonts, CSS values, HTML template structures, layout proportions, logo shapes or downloaded site textures. The production context contains a text description of the PRODUCT, not the page. When implementing, do not place the site's URL or screenshots into scene assets. Only reopen source for factual verification, not to fetch media.

One honest fact can inspire multiple ORIGINAL films. “Search by game” could be an optical lens metaphor, a kinetic word-index system, or an original maze of spatial tiles. None requires a frame of the actual game-search page. Product functionality is represented editorially; don't claim a schematic is a capture of the live application.

## 2. Three distinct concept mechanisms
Develop internally three genuinely different stories with a physical/graphic action and payoff, not just typography variants. Example for a site that truthfully lists scripts and can filter by game:

**A — Search lens:** giant original dimensional magnifying shape moves through an abstract field of custom game-type glyphs. It finds the desired subject, then transforms into a crisp newly typeset game label. Optical reveal, not a page zoom.

**B — Index compression:** original individual script symbols fly into a 3D index tower; a specific verified filter divides it into ordered branches, each with original graphic semantics. A single entry becomes dominant. Spatial organization, not an HTML list screenshot.

**C — Question to answer:** a large kinetic question mark fragments into independently drawn search criteria; the correct criterion locks in and a concept card resolves as a completely new designed object. Semantic reveal, not a copied site card.

Pick the strongest meaningful product story and build original typography, icons, materials, movement paths and scene composition from the installed libraries. Never default to the same concept for all users. A concept is good when the viewer sees an action and consequence even without a website capture; mere spinning cubes are not a story.

## 3. Concrete shot specification for a weak agent
For each significant visual event write in *existing project working notes* (no new tool/schema required):
- Source **FACT** (text and where verified); no site image path.
- Purpose (question, complication, action, answer or callback) and exact voice/music cue once known.
- Original asset(s) to CREATE: geometry/mesh/type/symbol/light/material, and the generation method in installed tools.
- Entry positions, layer hierarchy and screen-space reading order, not copied site coordinates.
- Causal main animation: object A changes something observable in B; start, peak and resulting state.
- Secondary motion that supports attention; no mandatory glow/particles/glass.
- Exit/incoming shared anchor, direction and timing, or a deliberate motivated hard cut.
- Truth check (actual claim tied to source fact) and output-origin check (all image/video paths original, authorized separate, or renderer-owned stock? Stock isn't automatically authorized; verify license).

Do not invent renderer property names. Consult guide 86 and appropriate active engine help. Build procedural vectors, text, 3D, compositing, path motions, soft-body/jelly and original lighting as needed. An original generated material may resemble generic physical reality, but do not recreate distinctive protected designs from source frames. Existing technical examples that include real UI captures are for syntax study only; replace their actual media and layout with original objects before shipping a film.

## 4. 20–25 second illustrative original promo (NOT a template)
A fictional script-catalog site is only known to offer a game filter and an upload action. These facts are conditional, not verified for another project. The story is “find what matters among a field of possibilities.” With actual voice and music available, a film might develop this original sequence:

| Approximate section | Visual (100% new) | Why it exists |
|---|---|---|
| 0–3 s | A single original type glyph drifts through depth, then dozens of freshly designed symbols emerge behind it; original lighting catches one sharp edge | Intrigue and scale. No site header or screenshot |
| 3–7 s | The lead symbol becomes a lens aperture; original glyphs deform around a new original focal shape | Purposeful action: search |
| 7–12 s | A chosen game label is typeset in an original font; three abstract dimensions of filtering align around it, with camera continuity | Clarify actual verified feature, without fake UI |
| 12–17 s | One abstract script capsule assembles from geometric layers, then reveals a legible factual summary as original text | Explain outcome, not a counterfeit listing screenshot |
| 17–21 s | The capsule duplicates into new spatial entries and a small original share symbol transforms toward viewer | Publishing metaphor, only if feature is verified |
| 21–25 s | A final conceptual grouping resolves into product name newly typeset as text; the first glyph motif returns | Earned payoff, not a recycled site logo |

**Important:** These are rough storyboard positions only. Recalculate when real narration/music exists. Different products need different original motifs. Avoid 6 new title screens, a random default cube, or a gallery of fake site cards. Complex renders matter only when they help the core mechanism. Choose native sharpness, material, depth and cinematic lighting according to the shot, not an effect-count quota.

## 5. Render original output and audit
Prepare two representative original styleframes with different shot roles, inspect at full resolution and phone scale. Render the hardest moving transition slice to validate dynamics. Never produce a temporary HTML page from the product source for film capture; an HTML compositor that the AGENT itself writes from blank primitives is permitted ONLY if it does not copy/rebuild the source page and if the resulting visuals are wholly original. Check original asset lineage before whole-film render. With actual audio, sync focal events against measured phrases and music, not guessed word times. Inspect the final video, including mid-transition frames and ending. No source screenshot may appear in any frame, even as a texture or tiny thumbnail. For drift/failure, discard the contaminated visual and regenerate from abstract fact, not by recoloring the prohibited media. See 119.
