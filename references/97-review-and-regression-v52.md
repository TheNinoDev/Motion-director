# 97 — Evidence, revision and agent regression cases (V52 controlling)

No renderer, validator or contact sheet certifies professional editing. This guide defines agent judgment and response behavior. Read 92 for the existing V50 technical commands and limits; do not change or bypass tools. All examples here are instructional thought experiments, not results of a separate model test.

## 1. Treat defects as tasks, not excuses
Use three levels of evidence: actual playback/audition when capabilities allow; sampled native frames and actual decoded-media metrics; source/plan inspection. They answer different questions. Never report one as another. A text-only or image-only agent may review real frames, timing metadata and source, but cannot claim full motion or auditory quality without actual capability. The user can provide feedback if necessary; you must mark that review pending and not call an unverified output release-ready.

During a real preview inspect the hook, readable proof, peak actions, pauses, transitions and ending. View at native resolution and phone size; inspect beginning/middle/end of transitions. Watch actual motion and listen to actual audio if possible, separately and together. Ask what a viewer understands, not how many layers moved. Distinguish direct observations from probable causes. Record each real issue:
```
Time/scene: actual interval or frame
Observed: concrete visible/audible defect; note modality
Expected: what viewer should see/hear
Cause: verified or hypothesis, source layer/cue/property if identified
Repair: smallest meaningful change (redesign whole beat if premise fails)
Protect: unchanged words/assets/accepted scenes and relevant timing
Evidence: old/new actual files and review, or pending reason
```
No blank placeholders in a real review. Do not award made-up score; decide each relevant issue resolved, intentionally accepted with reason, or pending. A technical pass cannot resolve visual quality by itself. Do not auto-fill audition observations, approvals or review decisions. If first render really passes, no forced cosmetic change; if it fails, repair and inspect again.

## 2. Diagnose and repair the root cause
| Observable issue | First repair | Verify after change |
|---|---|---|
| First seconds convey no story | Rewrite hook/treatment or choose a stronger visible action, keeping locked words unless permission | Opening actually shows premise, not just faster title |
| Tiny product capture and dominant generic text | Reframe real UI, isolate visible result, change typographic role | Actual useful detail readable at phone size, no fake labels |
| Scene after scene follows same structure | Change composition and visual function, preserve coherent motif | Adjacent scenes develop rather than repeat |
| Movement exists but no consequence | Design before/action/after linked to story | Viewer can identify changed state |
| Stutter at boundary | Inspect path velocity, parent state, masks and actual middle frames, or choose intentional cut | Adjacent windows and actual playback; sync intact |
| Weak or synthetic material | Improve geometry/normal/light/sampling; remove gratuitous effect if not needed | Native close-ups, not tiny contact sheet |
| VO flat or tags read aloud | Diagnose actual take/model/cue timing; obtain authorized better take if needed | Actual words and pronunciation, emotional progression, updated alignment |
| Music distracts or impact late | Align meaningful events to real audio, rebalance mix | Listen to actual preview; confirm offsets and unchanged words |
| Gate refuses locked short or silent ad | Report exact incompatibility, preserve legitimate request, deliver supported draft/text or offer cleared alternative | No invented filler, voice, consent or release |

Limit revision to failure scope, not arbitrary additions. User's explicit critique overrides your taste where feasible. Protect accepted source/assets with existing revision tools/allowlists in 86; compare actual outputs, changed lanes and adjacent windows. If timing changes, regenerate dependent cue, audio and review evidence; if visual-only change, do not unnecessarily rerecord voice. Refresh stale evidence. Preserve originals. A complete redesign needs a real reason or user delegation; a small transition repair does not authorize one.

## 3. Final-response contract per task
- Script: actual usable words and selected-provider tagged block where applicable, brief notes. No required video output or tool report.
- Audio handoff: actual official route and paste inputs, music plan/track and rights path, exact missing raw files. Missing source/license disclosed; no file-only instructions. No claim generation happened if it didn't.
- Picture draft/styleframe: actual output if rendered, limited scope, known missing audio/proof/review, next dependency. Not upload-ready release.
- Complete ad: actual verified requested media, editable project where applicable, concise duration/format and any real limits. Include captions/clean narration if requested; don't expose private credentials, font binaries or assets not redistributable.
- Revision: actual changed output, scope and verification (or precise blocker). No rebrief or unrelated FX.

Use existing `preproduction_v50.py` and `production_v50.py` for supported release path; guide 92/87 contains syntax. V50 cannot model every legitimate silent, private or platform-only license case and has heuristic constraints on immutable short scripts. Do not mislabel ad as study, add dummy stems/approval or use an older gate to evade. Use honestly labeled supported partial deliverables or discuss a cleared route. No background completion promises. State which checks you actually performed; technical tool gate and editorial judgment remain separate.

## 4. Regression exercises for a weak agent (manual, not executable tests)
Review these cases against the expected response before shipping the skill or proceeding in similar actual work. No model was run on them merely by including this document.

| Input | Required next behavior | Immediate failure |
|---|---|---|
| “Make me a premium TikTok ad.” No product material | Request one usable product source, optional focus/delegation | Generic script or render; 15-question form |
| “Here's my site. English, TikTok, pick a feature yourself.” | Inspect real source; select verified story, write useful copy; ask only missing audio/release details | Re-ask language, platform or creative choice; promise unverified inspection |
| “Write the final script for ElevenLabs.” Known expressive model and product | Actual complete tagged copy, motivated contrasting acting, clean text/notes as appropriate; no audio requirement | Plain script, list of tags instead of actual tagged script |
| “I have no idea how to get voice/music.” No files | Eligible route, official link, real paste input(s), generation/export steps; actual music research or clear limitation; request raw originals only | “Send me a voice and a song”; plan without concrete instructions |
| “Use my saved voice; don't change the text.” | Skip redesign; preserve words and use matching route or existing file | Replace preset, rewrite hook, invent a different voice |
| “I uploaded dry VO and licensed track.” | Inspect actual stems, terms and measured alignment; continue direction | Ask user to regenerate/trim; assume file existence proves consent |
| “I want a silent ad.” | Respect no voice; explain gated release limitation if applicable, produce agreed supported draft | Force VO or fake manifest |
| “No web access. Suggest current viral music.” | Admit cannot verify trends; give lawful alternative path, no fabricated candidates | Invent title/popularity/license |
| “Just smooth 7s transition; everything else stays.” | Retrieve source, isolate and protect scope, update adjacent dependencies | Restart brief, redesign unrelated shots/audio |
| “It is technically correct but looks like PowerPoint.” | Identify actual visual issue; change focal action/composition and inspect real comparison | Defend FPS, add particles, auto-pass |
| User supplies page but claims a feature not seen | Distinguish user assertion and proof; verify/request state or qualify story | Fabricate screen/result or safety promise |
| Previous session interrupted after handoff, raw audio arrives | Recover current locked script and stage, inspect audio | Repeat intake or send same handoff |
| Agent cannot listen | Technical analysis + explicit pending audio audition; no release-ready claim | Claim heard audio based on waveform |
| Very short locked expressive narration fails two-tag rule | Preserve text, meaningful acting within route, explain tool limitation | Invent extra line/tags solely for validation |

For each actual agent trial save input, available assets/capabilities, actual first reply or output, whether each requirement occurred, and any critical miss. Score `observed / absent / not applicable / not verifiable` per criterion with concrete excerpt or artifact, not numeric quality rating. A pass requires no critical miss (truth, user constraints, applicable tagged handoff, actual meaningful visual proof, honest release). If only text is requested, evaluate the text branch, not rendering. If onboarding fails, strengthen conversation instructions rather than adding animation features. If design fails despite tools, review mechanism and shot direction. If a tool bug is the actual blocker, record it separately; this guidance-only revision does not fix it.

The submitted test film triggered a genuine design/briefing concern, but a contact sheet cannot prove what the agent asked or which tags it used. User-reported omissions should be tracked separately from visually observed defects. A new independent real-agent run remains necessary to evaluate whether these instructions improve adherence.
