### Two particularly useful debugging lessons

1. **Broken cell positions.** Claude initially saw cells line up incorrectly. It checked actual `x/y` values and computed transforms but eventually fixed the *element's default positioning* (`position:absolute;left:0;top:0`) at creation. The quality gain came from **observed render + targeted model of the bug**, not from adding glow or jitter.
2. **Transition bugs are sometimes state bugs, not easing bugs.** The code handled visibility, display resets and successive parent transforms. It examined specific frames around **7.3/7.6 s**, **13.9 s** and **16.3–17.0 s**, and rerendered after changing the state transitions. For a custom renderer, a deterministic frame function must reset all properties, including `display`, opacity and transforms, on **every** invocation; otherwise screenshot order can corrupt the result.

### What does NOT generalize

- The Run-button wall, bright lime design, stylized listing graphics, and “LOOK FIRST” treatment are specific to that script and should NOT become the default for a script-protection video. The latest user direction requires **all site/project/reference content be facts only**; do not import page pixels, site CSS, screenshots or logos unless explicitly authorized.
- The user said the music was theirs. That resolved Claude's conversation enough for it to continue, but does **not** independently establish all commercial rights or cross-platform sync. Never claim verified rights from a statement alone.
- The Claude run had failed render attempts and used rough waveform-based alignment, which it accurately disclosed as not auditioned. Reproduce the honesty and recovery, not those limitations as a preferred route. If a genuine listening/ASR tool is available, use it.
- The 20.5-s Claude film and 24-s GPT film address different stories. A richer visual progression can be identified in this pair; one example cannot prove any model intrinsically excels. Don't report an invented numerical improvement from the skill update.

**Transferable lesson:** The successful loop is *specific story → varied state design → deterministic animation → actual representative render → inspect and debug → whole-film export → review and correct*. It is not “HTML is better than Pillow” or “use more motion”. See 130 for the executable decision protocol, 131 for engine architecture, and 132 for acceptance/revision.
