# Audio first: from writing to finished voice and music

**V6:** Read guide 25 for provider-specific acting tags, clean-script preservation, and compilation before any TTS handoff. It supersedes older vague tagging guidance. The original preset in guide 24 was successfully tested by its author (user-reported).

## Distinguish three operations
TTS = text to spoken audio. ASR = recorded audio to text with timestamps. Forced alignment = align known script to recorded speech. None of these is interchangeable. Never transcribe a source by copying on-screen captions unless clearly labeled OCR/visual text. No transcript from waveform amplitude. If reference audio is mixed, compare original source and optional authorized separation; don't treat separation artifacts as exact words. Keep uncertain tokens [unclear], do not silently fix. For reference speech analysis record time, exact verified spoken words or uncertain, vocal delivery notes from listening (pitch, emphasis, pauses, speed, tone shifts), music/SFX candidates, visual cue, confidence. If no listening capability, only measurable audio facts and recommended creative direction.

## Voice production steps for incompetent agents
1. Write plain-text voiceover script. Separate bracketed acting directions into a JSON performance plan; never let TTS read stage directions unless intentionally spoken. Expand ambiguous numerals or spell out acronyms for TTS while preserving intended meaning. User supplied exact script cannot be reworded without permission; normalization only for pronunciation.
2. Choose supported TTS via actual available tool/CLI docs. Use a stock licensed voice appropriate to audience; no impersonation of reference voice. Try two reads. Directions: conversational, relaxed, small dynamic contrast, no news-announcer hype. Phrases 4–12 words often work. Use contractions naturally; pause to let visual proof land. Target ~130–180 wpm initial estimate; actual generated duration controls. Start 0.1–0.3 s into video, allow 1.5–2 s CTA after last phrase. Not rigid. Avoid filler and breathless reading.
3. Decode to 48 kHz PCM. Retain original audio and exact script. If TTS provides word timings use them and verify with playback. If ASR available, run on dry voice, compare text against locked script. Common Whisper CLI example after verifying installation/help: `whisper voiceover.wav --model small --language en --word_timestamps True --output_format json --output_dir work/asr`. Local models must actually exist or download be authorized/available. If provider supplies only phrase chunks, concatenate measured PCM pieces with explicit pauses; produce phrase boundaries, not invented exact word times. Never call robotic espeak release quality by default. For speech quality verify pronunciation of names, clipped ends, pauses, pacing and exact meaning. Regenerate only faulty phrase with consistent voice.
4. User music: accept MP3/WAV/M4A/FLAC/OGG or any ffmpeg-readable audio. Keep source immutable. Audition start/middle/end, choose a useful excerpt; avoid arbitrary loop seams. If absent ask once unless waived/delegated. For a commercial ad verify music rights or flag release restriction. Extract an audio tempo estimate if useful; spectral flux transients are not verified beats. Build `audio-cues.json`: phrase start/end and emphasis, music section start, beat candidates + verified beats, sound effects, planned silence. Cut to words when words drive story; choose downbeats for emphasis; don't force all cuts on beats. A repeated action can accelerate across the phrase; pause before reveal. Use few consistent SFX (typing, click, soft hit, swish), silence is valid.
5. Mix voice first, music second, SFX third: normalize voice with restraint, use gentle ducking, music starting roughly 12–18 dB below voice and adjust by listening; voice should be intelligible at phone speaker level. Export stereo 48kHz, aim -14 to -16 LUFS integrated and ≤-1 dBTP as a starting target, not a universal platform mandate. Avoid clipping from stacked SFX; verify after AAC encode. Use 2-pass loudnorm if normalization needed: first `ffmpeg -i mix.wav -af loudnorm=I=-15:TP=-1.5:LRA=9:print_format=json -f null -`, second with measured_I, measured_TP, measured_LRA, measured_thresh, offset and linear=true; verify actual output instead of assuming linear mode. No audio pitch/speed alteration solely to fill an arbitrary duration.
6. Validate timing from actual mix and frame quantization. `frame=round(seconds*fps)`; preserve end-exclusive shot coverage. Captions: exact words, split by phrase, max 1–2 lines, legible mobile size. Kinetic title is separate from accessibility subtitles. Export SRT file optionally separate, never fake complete captions. Check no VO beyond end, no music cutoff, final CTA hold; recheck final encode.

## No reliable audio available?
Use scratch TTS only for animatic, label draft. If professional TTS unavailable and user did not approve scratch, do not deliver scratch as finished. If source speech can't be understood, mark tone unknown; if alignment uncertain, use verified phrase-level animation rather than word-level lip-sync. `scripts/audio_cues.py` only measures mixed or dry waveform properties, not ASR; `scripts/prepare_audio.py` is offline scratch fallback. Tools and exact versions vary by runtime. Use actual local documentation before integration.
