# Project structure, revisions and campaign continuity
Keep input originals unchanged. Suggested project: inputs/ (script, song, logo, approved captures), audio/ (dry VO, timing JSON/SRT, mix, optional SFX), source/ (renderer, components, fonts/licenses), plans/ (brief, claims, hooks, shot plan, ledger), renders/ (preview, final), qa/ (contact sheets, reports). Never include API keys, private product source, unlicensed assets, reference video files, or credentials in delivery ZIP. Link actual verified outputs and state duration/format, assumptions, unknown checks, exact command to reproduce. Provide script separately readable. User can request only MP4 or only source; honor.

For a revision preserve user-locked content, previous approved look, working animation and audio, unless explicitly changed. Identify shot IDs and reason, fix and render isolated test then affected/full output. Compare with previous version. Keep separate version filenames. If requested change affects narration, ask only if locked script needs editing; re-time dependent shots. Before next campaign video read ledger; record date, topic, proof, hook family, motif, CTA, rendered output. Reserve unused angles, avoid repeated phrases and repetitive choreography; maintain same brand tokens. A campaign is not a feature checklist. No promises of future results without actual workflow.
