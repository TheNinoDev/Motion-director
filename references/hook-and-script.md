# Hook engineering and scriptwriting

## Think in moments, not feature bullets
A hook is a promise of a satisfying answer. It can be a statement, action, visual mystery, joke, striking contrast, honest question or surprising fact. It must not lie or depend on an unsupported claim. Pair an audible hook with an independent visual hook: sound-off viewers should understand enough from the screen. The frame can show an action before narration or intentionally delay a reveal. For typical social edits establish topic or curiosity in 0–2 s, context within ~3–5 s, first proof quickly (often by ~5–10 s), then escalation/reveal and a clean payoff. These are defaults, not source-derived timing laws. A deliberate slow open can work if the tension is clear.

### Hook families and examples (original hypothetical copy; adapt only to verified facts)
- Relatable action: “You just want to find one script.” Show the exact search flow or friction, then resolve it.
- Contrast: “Finding something shouldn't be the hard part.” Show search uncertainty vs a relevant real product flow.
- Pattern interrupt: “This is not a feature tour.” Then actually show one surprising workflow rather than deliver a list.
- Open loop: “One small change made this much easier.” Reveal what and demonstrate, only if a real change exists.
- Visual-first: a cursor tries an action, a specific result appears, narration explains why it matters.
- Aspiration: “Your work deserves to be found.” Show a verified creator/discovery flow.
- Metaphor: tiny object grows into something meaningful; connect metaphor to the product rather than just decorative CGI.
- Honest reversal: set an expectation, show a genuine unexpected outcome, return to proof.

Avoid generic “Introducing”, “Are you tired of”, “revolutionary”, “game-changing”, “in today's digital world”, “the future is here”, “wait until the end”, forced teenage slang, empty negativity, and unsupported superlatives. A brand intro only if concept justifies it. Do not use a provocative confession (“we lied”) unless its meaning is truthful and fair. No bait-and-switch, manufactured pressure or deceptive urgency.

## Internal hook selection
Draft 3–5 genuinely different candidates with verbal line, first-frame visual, predicted viewer question (not predicted metric), promised payoff and factual dependencies. Score clarity, curiosity, relevance, credibility, distinctiveness and visual translation 1–5; reject unsupported facts, even high-scoring hooks. Pick strongest for intended audience; if user requests variants present options. Do not send a pile of mediocre options as the only output.

## Structure options
- Tension → specific proof → release → CTA.
- Cold open → context → escalation → twist → resolution.
- Ask → show → reveal → takeaway.
- Visual metaphor → product connection → demonstration → tagline.
- Before → after → how it happened (grounded in evidence).
- One unbroken demonstration with carefully timed text and final payoff.

Make each line do a job: hook, context, tension, proof, twist, payoff or action. Cut sentences that merely restate what is seen. Alternate concise punchlines with natural connective phrases; preserve spoken cadence. Use concrete verbs and outcomes. The viewer should understand even without prior product knowledge. Write for the actual audience, not investor copy; simple English when requested, short sentence structure, necessary technical vocabulary only. Avoid stuffing all benefits; one main idea. A short 15–30 s film often fits ~35–75 words, 30–45 s ~65–110 words, depending on speaking rate and pauses; measure actual generated VO instead of enforcing a word count. Do not speed-run a script to squeeze in more facts.

## Deliver the full script
Supply the clean copy as `script.txt` for speaking; separately `script-direction.md` with beat, voice mood, emphasis, silence, visual idea, claim IDs and CTA. Do not feed bracket tags to engines that read them aloud; map direction to supported TTS controls or split phrases. If exact user script given, no rewrite without permission. If agent writes, give a complete usable script immediately; no needless approval barrier for delegated full production, but wait when user expressly asks to approve. Hook promise should be repaid before CTA. End with a concrete relevant action or memorable brand line (URL if useful), not three CTAs. Ensure no misleading new offer or terms.
