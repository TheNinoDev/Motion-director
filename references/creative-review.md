# Creative review and release gates

## Mandatory gate A: before audio
- Sufficient source context and claim inventory; distinguish observed, user-provided, planned and inferred. No secret material/unsupported claims.
- One specific message and target action; feature budget; distinct from prior campaign topics if ledger available.
- Strong hook with visual and verbal angle; clear payoff; concise clean spoken script; delivery notes separated. Locked user script honored.
- Required assets and music before edit (explicit waivers recorded). No fake confirmation.

## Gate B: before final render
Score with concrete evidence, not an automatic self-congratulating pass. Rate 0–5 or `unverified` for each: hook relevance/clarity; credibility/evidence; payoff and audience fit; script performance; focal hierarchy; typography; motion timing; continuity; visual variety; product accuracy; CGI craft (N/A if none); audio design and sync; CTA; technical readiness. Target at least 4 for reviewable areas, address concrete failures. Do not claim objective quality/retention. A score alone does not establish success.

Questions for reviewers: does a new viewer understand the topic by the proof? Would hook still engage without a generic effect? Is the hook's question answered before CTA? Is any unrelated feature sneaked in? Are scenes conceptually connected or just consecutive? Does each visual add information or mood? Is motion on meaningful layers rather than all layers? Are quiet moments intentional? Does the edit feel clean without flattening all energy? Can key text be read at phone-size? Does the song support voice rather than fight it? Does final file actually show what's promised?

## Gate C: delivery
Check actual output media structure, decode, duration, streams, resolution, frame rate, audio mapping/loudness, safe zones, glyph coverage, flicker, unintended freeze/black, first and last seconds. Review full motion and listen if possible. Record missing tests in QA. A successful probe is not proof of picture/sound quality. Never deliver watermark copied from reference or platform-end card. Keep source and dependencies reproducible; actual MP4 only when created.

## Failure taxonomy and repairs
- Generic ad / feature parade → narrower angle, real conflict, proof and payoff.
- Hook overpromises → rewrite or change evidence; don't make CTA the answer.
- Monotonous narration → delivery variation, natural pauses, remove filler; respect final script lock.
- Eye fatigue → reduce competing anchors, blur/noise, shorten or remove FX, increase reading holds; don't add uncontrolled flashes.
- Obvious template repetition → change visual grammar, composition, pacing and transitions across scenes.
- Disconnected beats → shared visual or semantic bridge, consistent style tokens and sound bed.
- Poor 3D → more realistic geometry/light or honest 2D replacement; avoid excessive use.
- Fake UI/metrics → real verified capture/data or explicitly labelled illustration.
- Audio mismatch → recalculate actual alignment; repair cuts/mix, re-export.
- Unavailable tool → document blocker, deliver usable fallback, do not report simulated success.

## Revision policy
Keep existing approved branding, motion, FX, features, script and assets unless user changes them. Read prior plan and outputs. Record issue/scene IDs and exact changes. Render affected scenes then reassemble and verify entire master. Provide concise changelog, actual output path and any unverified test. Do not make user re-answer known choices.
