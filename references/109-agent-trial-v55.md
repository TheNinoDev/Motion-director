# 109 — Small independent trial: score evidence, not instruction recall (V55)

For the user or an evaluator testing the installed skill later. This is a manual test design, not an automated test or a claimed run. Do not feed the expected outputs to the trial agent. Keep exact prompts, actual first replies, subsequent audio instructions and rendered artifacts. Use a fresh session if evaluating onboarding. If comparing versions, use the same model, input files and tool availability; record different access/budget rather than attribute it to the skill. Do not judge quality from token count, self-rating or successful render alone.

## Trial A: first response
Prompt: “Make a 20–25 second ad for this site.” Provide a real site/project and no additional direction; record whether the agent actually has access. Expect a concrete grounded observation, recommended direction and only unresolved consequential questions (audience/goal if material, spoken language, release, audio existence/delegation). If the source cannot be accessed, an exact screenshot/source request is acceptable, not invented inspection. Failure: asks for technical design decisions by default, ignores already supplied inputs, claims unsupported features, or starts a final render without enough facts.

## Trial B: selected script and complete audio handoff
Answer A's unresolved questions, e.g. “English, public Shorts, you choose creative and music, I don't have audio. I don't know how to make the voice.” Supply evidence/permissions as applicable. Do not tell the agent to add tags; that is being tested. Expect actual natural copy with a coherent hook and payoff, full selected-provider supported tagged paste text when route is verified, separate exact voice design if relevant/new, explicit concrete steps, real music recommendations with rights evidence when research available, and exact raw files to return. If current access/support cannot be verified, accept a truthful clean script with separate acting direction and legitimate research path; mark the expressive model support or music check pending, not automatically passed. Failure: tagless script for a known compatible expressive model, generic slogan list, only a file link or tag glossary, fake provider/menu/song/license, asks user to edit the audio or retries questionnaire. Compare the actual spoken words and voice design to locked sources.

## Trial C: returned files and film
Give raw voice and cleared music (or explicitly approved alternate legitimate scope), actual product captures and any approved copy. Ask for the ad. Expect actual media inspection, measured timing, creative design and rendering, visible purposeful progression, actual product proof, deliberate sound alignment and visual review. Review opening, proof, boundaries and ending; if possible watch whole output on a phone and listen. Record actual timestamps of defects, not just a global score. Failure: inert screenshots under changing titles, fabricated functionality, poor legibility, repetitive motion or false final approval. A quiet purposeful result hold is not itself a defect.

## Trial D: targeted revision
Ask to fix one named observed defect, keeping the rest. Require adequate source for a true edit; if only MP4 is available, note limitation and assess honest scoped alternative. Compare locked content/timing and actual before/after. Failure: starts from scratch, rewrites narration unnecessarily, adds unrelated effects or delivers unchanged artifact with a claim of improvement.
