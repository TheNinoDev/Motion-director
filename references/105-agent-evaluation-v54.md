# 105 — Test the agent's outputs, not the size of the skill (V54)

These are manual evaluation cases, not executable tests, not evidence of an independent weak-model run. They address actual reported issues: inadequate intake, missing instructions for getting audio, tagless narration, generic copy and repeated title-over-small-screenshot compositions. The old clip was reviewed from sampled frames; the original agent chat and separate narration were not supplied. Do not treat reported failures as independently verified conversation transcripts.

## Run protocol
Give a fresh agent the installed skill, one test prompt and only the stated assets/capabilities. Do not tell it the answer key. Save exact prompt, first user-visible reply and subsequent files/replies when relevant. Use the rating `observed / absent / N/A / not verifiable` with excerpt or concrete file evidence. Do not score the number of guide words or presets. For a full-ad test, continue the conversation with real available assets, then examine the actual rendered output. A skill text review is not a model run.

## Copy evaluation (not a numeric quality score)
Does the first line create a distinct question, tension or visible event? Does the next line progress it? Is the consequence verifiable for THIS product? Would the text still work unchanged with competitor name? Is the ending the same story's payoff? Does the copy sound like natural target-language speech? For expressive models check full paste block, before-phrase supported cues and real intent variation. Avoid demanding sarcasm or excitement in all campaigns. Check locked words against actual output. Reject generic hype/feature enumeration as a premise, even if tags pass a validator.

## Audio handoff evaluation
Can a novice distinguish Voice Design from TTS? Can they see both exact inputs if both needed? Can they identify actual provider/model and right tool, know what to select and paste, how to generate, what to listen for, how to export and exactly which original files to return? Is music actually researched if available with accurate title/version and use rights? Are impossible or unavailable actions labeled? A link to a generated instructions file is not sufficient if the user cannot see the actual required script. Check time-sensitive claims with current evidence rather than assume prior docs remain current.

## Visual evaluation of actual artifacts
Inspect beginning, main proof, peak actions, boundaries and ending at native and phone scale. Where possible watch actual moving film and hear actual mix. Identify one concrete observation per weak event, its effect on viewer understanding and one plausible targeted repair. Compare actual before/after. If only sampled frames are available, do not diagnose exact motion timing or sound as if played. Test whether the product proof is large and visible, whether the subject develops, whether motion transitions are purposeful and whether typography/materials support hierarchy. Reject an observed slideshow even if the renderer/technical gate succeeds. Do not accept a claimed change unless file/source/evidence supports it.

## Release outcome
A critical miss on relevant truth, scope, actual tagged handoff, audio rights, actual product proof or honest review fails that case. Missing capability is not itself proof of bad creative behavior if disclosed and feasible work delivered, but mark the unverified dimension as pending. No artificial percentages. Use results to modify a specific instruction that failed rather than make the next skill indiscriminately longer. For a real failed test, archive exact observed outputs and what the agent could access; do not infer hidden thoughts or fabricate a run. Existing tools remain unchanged in V54.
