# Campaign / content strategy

The deliverable is one good video, not one encyclopedic video. Build a topic bank even for a single film when a larger product is involved. Keep prior videos, selected and unused angles in `templates/campaign-ledger.json`; load existing ledger before new campaigns so the user doesn't get the same video repeatedly. When evidence changes, update its status instead of silently recycling old claims.

## Angles (choose one per film)
- Problem/solution: dramatize a specific friction and show the real alternative.
- Mini mystery: show a surprising outcome, then reveal the cause.
- Product proof: complete one relatable task in real UI.
- One differentiator: unpack why a single capability matters.
- Culture/identity: show a real audience desire and let product become its expression.
- Founder/change story: what changed and why, supported by verified history.
- Behind the scenes: actual engineering/design story with approved data.
- Community showcase: permissioned real work, not fabricated testimonials.
- Myth/objection: explain a real misconception without misleading strawmen.
- Launch/update: one coherent improvement, a meaningful milestone or an authentic invitation.
- Visual metaphor: familiar object → abstract concept → product payoff.
- Comedic reversal: relatable expectation → visible twist → proof.

For each idea define audience, emotional promise, claim IDs, visual motif, distinct hook family, proof, CTA, length estimate, feature budget and overlap with prior videos. Select by relevance, novelty, strength of proof, visual potential, ease of production, brand fit. Do not claim predicted virality or retention. Do not force all ideas to use the same tone or text structure. Keep some quiet/product-first and some energetic; no constant fake controversy.

## Feature budget and narrative scope
Default one lead product outcome, 0–2 supporting details that directly reinforce it. Other unrelated capabilities go into later ideas, not a rapidly narrated list at the end. For an explicitly requested overview, cluster related features into one overarching story; use visuals instead of narration dumps. Claims that require explanation get their own film.

## Example campaign (illustrative; verify facts with project)
For a script-discovery website: one ad about discovery friction; another about showing off a creator's work; another about a verified key flow; another about profile customization; a later release story. These are separate audiences and proof moments. If a key reward or integration is planned rather than live, omit it as a current benefit. Contrast examples must be fair and specific; don't accuse competitors without proof. A provided existing campaign may supersede this example entirely.

## Content ledger process
Mark topics `idea`, `selected`, `scripted`, `rendered`, `published` or `retired` only based on actual progress. Log hook, main promise, format, visual signature, feature IDs and result metrics only when supplied. Future ideas should differ in angle + hook + evidence, not merely song or colors. Use actual analytics if user provides it; do not invent A/B results. On request generate multiple hook variants for the same subject with matched body to support real comparison.
