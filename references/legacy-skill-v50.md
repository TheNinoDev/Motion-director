# Motion Director 50 — producer first, renderer second

**Read `references/87-producer-first-v50.md` now for EVERY new advert.** It is mandatory, not an optional lookup. Legacy guides are technique manuals, not alternative workflows. Never start by rendering a slideshow or copying the bundled FORM example. Do not call a technical study a finished ad. User requirements and approved decisions override creative defaults, not honesty or rights.

## FIRST MESSAGE (new ad)
Inspect the supplied product source read-only; use one adequate source (local project, URL, HTML, screenshots, direct description). Do not require all. Establish product/feature, audience, language, publish destination, audio choices. Ask only genuinely missing essential decisions in ONE compact natural message in user's language. If product info is known, do not ask for it again. Offer to choose the feature/duration/visual treatment yourself. Do not ask the user to write the script, choose effects, make a storyboard, edit files, or give credentials. Marketing is commercial by default, distinguish platform-only vs cross-platform permissions. See guide 87 for exact questions and examples.

## Mandatory sequence for a narrated advert
1. Fill `templates/preproduction-v50.json` in work directory (actual facts, not placeholders). Run `python scripts/preproduction_v50.py next WORK/brief.json`. Follow returned stage. No visual production before resolved brief and usable audio. Research/product inspection and draft concepts can proceed first.
2. Write THREE distinct hooks and choose one, write a natural single-story script, revise aloud, and produce a performance JSON per `templates/performance-v50.json`. Read guides 02,03,25. No feature laundry list, generic hype, fake claim, or forced slang. Use at least two motivated expressive cue types for Eleven v3/v4 or Fish S2; compile correct model-specific syntax. Keep clean captions and tagged paste-ready text separate. Never replace the exact preferred holographic prompt in guide 24. If human recording or supplied VO, separate acting notes (no literal tags spoken). Use script-only route when asked; deliver script rather than demanding audio files.
3. Select music only after intended use known. Research actual named tracks with current trend/date/region evidence and licensed alternatives; if supplied/no music, skip redundant questions. Do not imply a trending track is cleared. Offer choice unless delegated. Give complete step-by-step audio handoff: the actual tagged text to paste, voice choice/model, separate voice design prompt if needed, legal source and exact acquisition steps for chosen track, request **raw** WAV/MP3 stems only. Explain the agent does all mixing/timing/editing. Generate with authorized tools only if available/eligible/delegated. Do not push ineligible users to sign up or pay. See guides 21–25. Run `python scripts/preproduction_v50.py handoff WORK/brief.json WORK/handoff` to prepare copyable artifacts; present the applicable instructions to user, not only a file link. If missing audio, wait for input, not background work. Do not invent audio or use scratch as final.
4. Once raw audio arrives, actually audition and measure voice/music, verify permissions, align each phrase to actual speech, record SHA-256 and timing. Run `next` again. Do not fake listening, proof, approval, rights or alignment. User explicitly requesting a silent/technical preview may use an honest study route; never relabel ad to dodge gate. Private preview is not public release.
5. ONLY after the real ad's preproduction state is ready: write original creative plan and source. Each beat must have an actual visible subject, before/action/after/why/transition and linked motion tracks or intentional hold. Use one central metaphor, product-specific visual proof, animated type, masks, framing, persistent anchors, and controlled transitions. Do not just put a title over a screenshot. Read guide 86 for renderer syntax and guide 87 for editing rules. Use no more CGI than needed; choose engines based on purpose. Render two distinct styleframes with real text, choose by actual inspection. No compulsory glass/chrome/jelly. Use audio alignment, named cues, motion profiles, components, 2D/3D, and real UI. Do not invent unsupported properties: `director_v49.py capabilities SOURCE.json LAYER_ID`.
6. `python scripts/production_v50.py start SOURCE.json CREATIVE.json WORK/session --manifest WORK/brief.json` checks stages and builds the actual stem mix. `python scripts/production_v50.py next WORK/session` returns exact next command. Do not use legacy production_v49 for new real ads. Check full playback and sound, native PNGs, transitions, cadence, pixel and flow, cue timing, compare against actual product. Correct weak beats and rerender. Export only after evidence and judgments, never auto-pass. Use high/optional lossless RGB quality. Deliver MP4 and project; disclose actual limitations.

## Other tasks
- **Script only**: intake known facts, write and direct copy, compile correct tags; no forced TTS account or render. See guide 87.
- **Revision**: inspect actual source and output; use `revision_guard_v49.py` for protected changes; preserve unaffected audio, asset, effects and text. For real ads use approved manifest and new session; older projects may retain their canonical legacy workflow only for compatible revisions, not a new ad.
- **Technical animation / study**: use exact matching renderer or recipes; label as a study; no fake claims or audio needed. `production_v50.py start examples/director-v49.json examples/creative-v49.json WORK/study` works without manifest for the bundled fictional study only. See guide 86.
- GPU, glass, softbody, font and rendering tools remain in guide 86 and earlier manuals.

Technical gates verify artifacts and recorded decisions, not creativity or honesty. A successful encode is not a successful advertisement.
