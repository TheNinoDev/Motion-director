# V50 — mandatory producer workflow and failure recovery

## Why this replaces the old start
A real 25-second RobloxLarp advert created by an agent had mostly isolated title/screenshot layouts and slow visual development; user reported weak copy, no acting tags, poor intake and no explanation of audio sourcing. The film had 1080x1920 video and an audio stream; separate script and agent transcript were unavailable. This is a workflow failure, not a shortage of shaders. Do not use these observations as proof of spoken words or the agent's internal behavior.

## Decision table: what to ask, and what NOT to ask
- New vague request: first inspect provided product information. If insufficient, ask for ONE source (URL/project/HTML/screenshots/description). Ask the topic or offer to choose one. Use the user's known target/language/format; otherwise ask essentials together. If only the user says "make an ad", do not invent feature evidence. Never ask the user to tell you which animation, font, easing, camera, or technical renderer to use.
- Example initial message, localized: “Send me your website or local project if I don't already have it. Which one feature should the ad focus on — or should I pick? Who is it for and where is it going? English or German? Do you already have a voice/music file, or should I prepare a voice script and recommend songs?” Omit resolved fields. Public marketing defaults to commercial; ask distribution scope only if uncertain. Offer recommended duration based on the story, not a compulsory field.
- If user says "choose everything", record delegation and choose specifically; still ask for genuinely unavailable product facts, necessary legal permissions, or external assets/capabilities. Don't repeat questions.
- A script-only user gets a completed script (with tags for selected expressive model or separate acting notes when provider unknown) and optional concise handoff guidance, NOT forced video production.
- Existing audio: do not ask for a provider or rebuild voice. Check actual files, rights, clean script, alignment, missing items only. If supplied narration is immutable, preserve its exact words; ask permission before rewriting. Short/locked scripts that cannot pass the normal heuristic should use documented manual review/legacy revision; don't invent filler.
- If the agent has authorized TTS and audio tools, and user delegates, use them; otherwise be transparent and provide ready-to-paste directions. No login credentials, payment, or account creation on their behalf; respect age, consent and license terms. No fake background jobs.

## Write first: not generic advertising
Draft three different opening lines (curiosity, contradiction, action); select one grounded in actual product evidence. A 20–30s clip often needs only 40–70 short spoken words depending on delivery, pauses and music. Do not pad, read dense feature lists, assert superiority without evidence, use “game changer,” or put a brand logo before the hook. Make it sound like a human telling a friend something useful. One believable situation, one turning point, one proof, one CTA that follows the proof. Use conversational contractions where natural; don't force slang or imitate a creator's wording.

BAD: “Discover our revolutionary platform. Benefit from powerful features and a seamless experience. Try us today.”
BETTER (fictional example): “Wait. Which version did I send you? ... The one called final? Or final-final? [real product proof here, not a claim to invent] ... Oh. That's the one.” Rewrite placeholders into actual verified copy before delivery.
For the uploaded RobloxLarp film's *topic*, a stronger hook candidate is “Would you run this without reading it?” A possible follow-up is “A copy button doesn't tell you what the code does.” Show actual source-inspection functionality only if verified. Do not imply that readable source is safe or that running third-party scripts is risk-free. Do not present generic competitor accusations as verified.

## Acting is required, not decoration
For Eleven v3/v4 use model-specific bracketed audio tags, not SSML breaks. For Fish S2 use supported square-bracket natural language tags immediately before the affected phrase. Official reference: https://elevenlabs.io/docs/overview/capabilities/text-to-speech/best-practices ; https://elevenlabs.io/docs/help-center/product/core-capabilities/text-to-speech/how-do-audio-tags-work-with-eleven-v3-and-v4 ; https://fish.audio/blog/fish-audio-s2-fine-grained-ai-voice-control-at-the-word-level/ (checked Nov 19 2026). Existing compiler maps conservative cues. Tags are suggestions to the TTS, not guarantees. At least two distinct motivated cues in an expressive marketing script, not a tag on every word or random emotional switches. Keep tags out of captions. The approved user-authored exact original voice design description is in guide 24; do not edit it or paste it into the narration. If creating a new suitable voice, provide the description separately; otherwise use existing authorized voice.
Example (fictional product):
```
[curious] Wait. Which version did I send you?
[sighs] The one called final? Or final-final?
[thoughtful] Oh. There it is.
```
These are sample ElevenLabs cues, not a universal script. Explain acting intent per phrase. Run `preproduction_v50.py handoff` to compile actual project script. The file `provider-input.txt` is directly pasteable. Review for accidentally spoken tags, wrong emphasis, pronunciation, rushed speech, excessive artifacts. Use actual listening, not just waveform. If unsupported or actual voice supplied, supply separate human acting notes and state why no inline tags. Respect a user's explicit locked text; the tool will not silently rewrite it.

## Audio sourcing: show the user exactly what to do
Read 21,22,23,24,25 only as needed. Give actual working source links and current instructions, not “get audio.” Offer eligible routes: existing audio / eligible provider / own recording / authorized agent-generated voice. ElevenLabs Voice Design (if eligible and new voice desired) → separate description → audition/save → TTS → select expressive model → paste tagged script → generate → audition → export MP3/WAV → upload. Fish Audio → authorized voice selection → S2 → paste tagged text → audition/export → upload. Check provider age/guardian/plan terms and commercial voice rights before offering signups; do not promise free commercial rights. Provide chosen route only, not an encyclopedia. Links checked for syntax, not signed-in service UI.
Music: if research requested, present 2–3 actual candidates, including current/rising only when verified with source/date/region/metric, and a fitting timeless cleared alternative. Give track and version, sample link, why it fits, proposed cue points, license coverage and legal acquisition instructions. User chooses unless delegated. TikTok's CML restrictions: https://ads.tiktok.com/help/article/commercial-music-library?lang=en . Platform-cleared music is not automatically exportable to other platforms. If only platform insertion permitted, offer a clearly labelled preview or platform-specific delivery, never claim a baked commercial master is cleared. No piracy or circumvention. If cannot find eligible track, state blocker, offer original/cleared alternative or explicit no-music choice.
The actual handoff must be in chat (or equivalent UI) and contain the pasteable tagged script, selected provider/model, voice prompt if needed, selected music acquisition instructions, and request for only the missing raw files. Do not require user to cut, normalize, combine, remove tags, sync music, or export a video. Agent does that. Preserve raw files. No fabricated musical trend, transcript, tags, listening, permission or UI labels.

## State and commands
Copy `templates/preproduction-v50.json` to project `brief.json`; replace nulls with real decisions (do not pretend a user confirmed them). Copy `templates/performance-v50.json` to `performance.json`; replace example text with approved actual script, write exact `locked_text` matching joined beat texts. `python scripts/preproduction_v50.py next WORK/brief.json` lists missing fields/stage. `handoff WORK/brief.json WORK/handoff` emits clean and tagged text and directions. Do not wait to ask questions already answerable from context. Record `audio_delivery.mode`: `user_handoff` with generated handoff folder and a factual note about what was sent; `agent_acquired` only if authorized tools actually sourced the audio; `already_supplied` only if it was already supplied. The tool hashes actual handoff files and rejects stale scripts. This is still a recorded action, not independent proof of the chat message. No final rendering until resolved. For actual recordings create `alignment.json` using measured actual phrase boundaries, full voice file digest, method `asr_verified`, `forced_alignment_verified`, or `manual_listen_verified`; example in template. Record actual audition observations and permission evidence for stems. `production_v50.py start ... --manifest ...` creates a new WAV bed with voice, music ducking and limit, pins the manifest/stems/alignment. A raw mixed arbitrary bed no longer satisfies V50. Audition the resulting mix and full preview. Audio and visual evidence are not proof of honesty; no auto-attestation.

## Direct the video; do not animate a slide deck
For each beat use direction fields: `subject_layer` (existing linked ID), `operation`, `before`, `after`, `why`, `transition` and only when justified `intentional_hold`. Use actual proof (real screenshots/interaction states or verified data) and link them in creative record. Hooks show a visible action immediately. Use at least three distinct compositions across multi-beat ads: e.g. full-bleed kinetic type, macro product control, edge-to-edge evidence, object assembly, editorial crop, sparse callback. Don't just change text or zoom a tiny screenshot. Preserve dominance, readable margins and contrast. Break up narration into visual events, often 0.5–2s but respect voice rhythm; not one flat shot per phrase. No arbitrary motion quota; intentional holds for proof/readability. Use persistent motif, match movement and silhouette, not a repeated fade. One or two meaningful 3D moments maximum by default, no compulsory materials. Use original typography/CGI assets only when relevant; font catalog and actual type comparisons. Use effects together, not all at once. Improve actual rendered design rather than adding new decorative features.
Motion audit is conservative: detects changes to supported local tracks on linked layers, not all advanced FX/parenting or quality. When using specialized engines, retain equivalent actual visual evidence; don't rename layouts to game the gate. Inspect video at full playback; compare native typography, product legibility, transitions; make at least one targeted revision when weak. Never submit the first minimally functional render. If cannot inspect audio/video, mark pending and deliver labeled draft only.
