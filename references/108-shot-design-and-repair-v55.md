# 108 — Direct the picture before using effects (V55)

Use with 104 for reference-derived principles and actual technique routing. The uploaded failed advert was assessed from sampled stills: repeated title/small screenshot layouts were a real issue. Its original transcript, project and exact motion/audio were not independently available. Avoid treating that example as evidence of all agent behavior. This guide describes concrete alternatives rather than inventing quality scores.

## Design at three scales
At film scale: one subject, tension, turning point, proof, payoff. At beat scale: focal action, visible consequence, connection to next beat. At frame scale: dominant silhouette, readable typography, meaningful depth, controlled contrast. A video can satisfy frame-level polish but still fail as a story. A beautiful styleframe can still fail in motion. Verify both.

For a new campaign, compare three visual mechanisms, not palettes. For example, on a verified project with a filter control and a matching result:
- Interaction-led: start inside real crowded content, reveal an actual filter and change attention to actual result.
- Metaphor-led: represent the clutter as an original stack of shapes, resolve one dominant colored shape into the corresponding real filter; clearly separate editorial graphics from product proof.
- Editorial-led: magnify an actual word or label, then widen to reveal its relationship with the real interface; juxtapose two actual states with distinct composition.

Select the mechanism that best serves the script and available evidence. Build different actual styleframes with changes in hierarchy/scale, not just backdrop color. If a treatment requires a feature, material or geometry that isn't available, select a different treatment without lowering ambition to title slides.

## Translate an approved script into a shot plan
Use a concise working grid with these fields: actual phrase or music cue (provisional until audio), viewer question, visible starting state, dominant action, resulting state, transition anchor, needed source asset, implementation technique and evidence to inspect. Not every phrase needs a new shot; not every shot needs a spoken line. One visual action can start before the sentence and resolve after it. Pick an editorial rhythm that changes according to actual performance and product explanation.

A sample directed sequence (fictional note app, with real demonstration assumed):
| Beat | Visual action | Connection / evidence |
|---|---|---|
| “Where's my packing list?” | Open on tight readable real note titles; viewer sees a crowded list, not the whole browser. A graphic focus marker pulls gaze to the wrong item. | Actual titles are legible at phone scale. Marker is an editorial overlay, not fake app control. |
| “Nope. Also nope.” | Two different wrong rows move past the same focal point with asymmetric timing; quicker second rejection. Keep list baseline and scale relationship. | No repeated new title card; two accents coordinated with actual speech. |
| “Wait, I marked it blue.” | A visible actual blue label becomes the anchor. Reveal the surrounding filter controls by reframing from that anchor; represent a real supported selection. | Before/after capture matches actual UI behavior; do not invent a live control. |
| “There it is.” | Show real filtered list and named matching result, large and readable. Reduce competing movement while result lands. | Reuse blue shape or row edge at payoff. Keep real result visible long enough to understand. |

Optional one hero dimensional blue tag, only if a good silhouette and material connect the recalled label to its real UI shape. Use the available tools for real bevel geometry, light, correct perspective and native sampling; skip if weaker than a flat original motif. This example is a method, not a template to clone. For a different product, choose a different proof and visual grammar.

## Shot-by-shot motion direction
- Entry: define where the object is before it becomes focal. It may already be on screen. Avoid forcing every element to fly in.
- Anticipation: guide attention through staging, a reaction, an intentional stillness or a small counter-movement when needed. Not every event needs a spring.
- Action: transform an actual relevant property/relationship. In a product interaction, establish what is real footage and what is editorial treatment.
- Secondary motion: offset subordinate motion from main action, use common event anchors and coordinated overlap; do not make every layer move in synchrony or chase every music transient.
- Result: maintain readable dwell and visual stability; if using elastic or physical motion, demonstrate energy loss and settle. For purposeful continuous movement, connect velocities at the next state.
- Exit: choose anchor (shape, row baseline, object center, light, directional flow or narrative cut). Match actual geometry/direction where intended, or use an intentional contrasting cut. Test frames at entry, midpoint and end, and actual playback when possible.

Choose existing implementation by problem (104 technique map), not newest recipe. For nested groups confirm transforms; for UI isolate real regions; for native text test actual face/size and line breaks; for glass, light/refracted content must support the focal object; for jelly use an understandable contact or impulse; for real 3D ensure edges/normal/surface/view are right. For animation continuity use supported state or path techniques; for cue dependencies use named events when useful. Use the actual tool help or schemas to discover parameters. No need to modify skill tools to make a video.

## Repair by observed symptom
| Observed issue | First inspect | Fix and verify |
|---|---|---|
| Text-over-thumbnail slideshow | Compare adjacent shot roles and actual product scale | Replace inactive proof with active crop/interaction and new composition; render meaningful new states |
| Everything visually busy | Focal object and relative prominence | Remove/reduce competing moves, preserve meaningful motion; test at phone size |
| All animations feel same | Actual trajectories, relative speed and transition mechanisms | Vary movement based on physical/narrative role, preserve natural easing; don't randomly alternate presets |
| Unreadable UI | Actual native capture, crop and legible label | Enlarge real proof, keep real UI identity and enough dwell; don't merely increase headline size |
| Poor material | Native geometry, edges, camera, normals, light | Improve fundamentals before adding bloom or blur; compare native frames |
| Awkward cut | Boundary frames, timing, subject position and motion | Adjust shared anchor, coverage or intentionally use a cut; inspect actual transition |
| Wrong emphasis | Actual voice and music | Align action and result to real stressed words, intentional offbeats or silence; no fake timing |
| Missed product promise | Script claim vs actual supported action | Fix story or obtain evidence; do not fake proof |

## Evidence and release
Use actual render, not planned layout, to reject an edit. Inspect phone-scale and native frames, actual playing motion and audio when accessible. If playback/audio unavailable, say that it remains unverified; do not claim listening from waveform or motion quality from a contact sheet. A technical gate is not aesthetic approval. When possible make and compare a targeted actual revision, not two full renders solely for a quota. Preserve accepted areas, audio and source. If the user says 'make the whole edit better', address premise, rhythm and visual composition, not just add more effects. If they specify one transition, do not reopen the campaign.
