# 103 — Audio delivery that a novice can actually follow (V54)

This guide controls copy and audio replies. It incorporates the required output of 99/95; use 90 for exact local compiler identifiers, 24 for the exact original voice design, 21/25 for provider details and 22 for music research. Provider state is time-sensitive: historical docs explain methods, not proof of current entitlements/UI. Verify official documentation when possible at the time of a real task. All fictional examples below are not product claims or current provider research.

## A. Make the spoken story worth editing
Before writing: identify a specific person/situation, their visible friction or desire, the actual action and consequence, and evidence. Choose a hook mechanism that sets a question the film answers. Compare three distinct opening mechanisms (e.g. overheard confession, visible contradiction, escalating repetition) and two complete drafts for a new campaign. Don't present them all unless asked. Choose the stronger relationship between words and picture. Read aloud mentally; replace written corporate language with speech. Keep one idea. Do not turn an ad into a list of every feature, no matter how many features were supplied. User's locked words and target audience/language govern.

Example: fictional list app with **verified manual tags and tag filtering**. No automatic tagging or speed guarantee. A weak draft: “Introducing the ultimate productivity app. Organize with tags and powerful filters. Stay productive.” None of the phrases offers a story. Alternative A: “Where did I put the invoice? Not there. Not there either. Wait, I tagged it. There it is.” Alternative B: “I named it 'important.' Along with everything else. Next time: one tag I can actually find. Invoice.” Choose A only if an actual tagged invoice and filtering result are available; B if the actual recording supports naming/tagging. Do not invent an invoice in a real user's dataset. If no individual data can be shown, use a clearly identified demo project with approved demonstration data. End on the resolved problem rather than a generic 'try it today.'

Acting progression for A: question, repeated frustrated search with tightening pauses, realization, quiet relief. For a supported, verified ElevenLabs expressive route, the actual paste block in this fictional case could be:
```
[curious] Where did I put the invoice?
[sarcastic] Not there. Not there either.
[thoughtful] Wait, I tagged it.
[excited] There it is.
```
The second tag should be dry, not aggressive; the last should be small relief, not a shout. If audition is wrong, adjust delivery/cue with compatible controls without changing locked words. For Fish S2 with verified support, the **same words** could be:
```
[curious, rising tone] Where did I put the invoice?
[slightly sarcastic] Not there. Not there either.
[thoughtful, measured tone] Wait, I tagged it.
[excited] There it is.
```
Only send the selected actual route in normal production. Use these as mechanism examples, not copy templates. If the user wants a voice different from the playful preset, respect it. A mature serious ad may need restrained acting; not every script needs sarcasm. Meaningful neutral lines can remain untagged. Every relevant change of intention should be directed; the compiler's two distinct non-neutral cues is a floor, not a performance target. Don't force filler words or tags into locked short copy.

## B. Keep four artifacts separate
| Artifact | Contents | Where it goes |
|---|---|---|
| Voice character | Timbre/personality description | Voice Design only, if supported and needed |
| TTS input | Exact words + model-native cues | Text to Speech only |
| Clean narration | Exact spoken words, no tags | Captions, alignment, human recording |
| Acting notes | Stress, pace, pause, intention | Outside paste block |

For a suitable new holographic voice, copy the exact original paragraph in guide 24, not the alternate, into a separate copyable block in the actual reply. The user's tested prompt is preserved; do not redesign it or include its fictional lore in spoken text. If they already own/use their authorized saved voice, never make them create another. If using another provider, do not assume the same Voice Design field exists. If provider is unknown, send clean narration and explicit phrase directions; ask or select an eligible verified route, not random guessed markup. Do not imply an expressive route is supported by every TTS model.

## C. Complete first-use handoff (actual response order)
Once copy/story sufficiently grounded, send a short package that contains ALL applicable parts in the same turn. Use the user's chat language for instructions and target spoken language inside script. No placeholders in real output. If user requested script-only, stop after the relevant script; don't force a full production package.

1. **Selected story:** one sentence explaining the setup/payoff and actual proof, no full internal concept report. State if script is provisional or locked. If length target, estimate until recording (never precise timecodes from word count).
2. **Voice provider:** official tool link and verified model selection, saved voice or new design, eligibility/use conditions when known. Existing official start routes: https://elevenlabs.io/ and https://fish.audio/ . Use current official docs to identify actual feature and available model when browsing permits. Do not assume every account shows model IDs from compile_voice.py. If the chosen route is unavailable, say what cannot be verified and offer an authorized saved recording or other eligible route; no paid signup without consent.
3. **Voice Design if needed:** open supported feature, explicitly distinguish description versus preview speech. Paste full exact original 24 description when relevant. Give actual campaign excerpt as preview text if needed, audition for natural phrasing/intelligibility/synthetic tone, save selected voice. If uncertain UI labels, tell the user feature names rather than pretend current menu clicks. Don't repeat if existing voice is already suitable.
4. **TTS input:** select voice and verified expressive model, paste the complete selected-provider tagged narration in its own copy block. No labels/timecodes/direction notes inside the block. If the provider has a verified limit, split at natural phrase boundaries, supply complete blocks and ordered filenames. Human/unsupported route gets clean words plus separate notes. Tags belong before the intended phrase; no tags in captions. Never require the user to reconstruct tags from a table.
5. **Generate and export:** generate using allowed tool; listen through for exact words, names, pacing, emotional contrast and accidental spoken tags; regenerate only necessary take/phrase if supported. Download original WAV or MP3 via legitimate supported export. Do not cut silence, combine, normalize or add music. Return ordered raw files. If agent has authorized tool and generation is delegated, produce the real file instead of burdening the user.
6. **Music:** actual selected track/researched shortlist with title, artist/version, official listening and acquisition link, why it fits opening/reveal/landing, intended distribution and evidence of rights. Explain how to legally obtain/export the original stem if permitted. If a platform-only license, explain in-platform insertion and provide a truthful alternative for portable master. See decision table below. No demand for user to research song when delegated.
7. **Return only missing files:** e.g. original dry narration and cleared music stem if both missing, plus only unresolved necessary permission. Agent owns musical segment selection, align, cut, SFX, duck/mix, render, review. Existing stems do not need to be uploaded again if accessible. Do not promise a background task.

## D. Music is a creative choice AND a rights check
| Situation | Required next action |
|---|---|
| Public commercial ad, user delegates | Research current relevant tracks when possible (dated regional/platform trend evidence if claimed) AND a suitable evergreen/cleared candidate. Verify synchronization, paid ads, region/platform, edits/attribution and actual download permission. Recommend one, present alternatives only when useful. |
| Track selected by user | Verify exact version, rights and acquisition. Keep it if suitable and authorized, explain concrete limitation otherwise. |
| No research access | State trends/individual rights cannot be verified. Give official lawful library/source route, search mood/use criteria and ask for selected licensed stem/confirmation only if needed. A generic library link is NOT a verified track recommendation. Don't invent candidates. |
| Platform-only allowed | Distinguish platform insertion from mastered music. Do not rip audio or export a universal commercial master containing it. State compiler limits and provide cleared alternative or honestly scoped picture/voice version. |
| Private or silent/no music | Respect scope; don't invent permission, a soundtrack, or a placeholder stem to satisfy a validator. |

For researched options keep a compact record: [track/artist/exact version] [actual official listening URL] [source/date for current popularity if claimed] [rights page and scope] [specific fit to story] [legitimate acquisition]. Fill with evidence, not placeholders, in real reply. Don't imply a song is commercially cleared solely because a library offers preview/download or a creator used it. No unauthorized extraction. If music is blocked, still send actual script and voice instructions.

## E. Raw assets returned
Inspect actual audio stream/duration and exact version. Preserve raw voice and music separately. Determine words and pronunciation with real audition or verified transcript; do not claim listening from a waveform. Align phrases/words to measured evidence; provisional timing from draft is not alignment. If accidental tags read aloud or words changed, obtain corrected take only if required, preserve accepted script. Plan music around real accents/structure, prioritize intelligibility. A voice-only correction does not imply redoing every shot. If no playback available, disclose pending listening and review. Use 87/92 actual compiler route and restrictions; do not fake rights, alignment or approval. This handoff ends when the real asset exists, not when a checklist is printed.
