# V8: Headless-first operating procedure
This is a mandatory implementation policy for novice agents. Avoid GUI-controlled software as a dependency. A tool is suitable only if its actual executable, API, inputs, dependencies and result have been checked. Never tell a weak model to "use professional tools" without a concrete path. User should not operate a video editor. Existing product and audio intake, truthful claims, legal and release checks remain in force.

## Choose by capability, in this order
1. Run `python scripts/doctor.py`, `python --version`, `ffmpeg -version`, `ffprobe -version`. Check Pillow and Playwright imports. If local Python + Pillow + FFmpeg work, use the bundled data-driven compositor for ordinary text, screenshots, cards, cursor and 2D layers. If they don't, use an available tested engine or state blocker. Never assume npm, Blender, paid accounts or GUI access.
2. For true UI, use browser via headless Playwright, not GUI navigation. For local HTML supplied as standalone file use `capture.py`; relative assets need an authorized, working local dev server or self-contained HTML. For websites, start with read-only navigation and scroll. Do not submit forms, create content, make purchases, edit live data or use private accounts unless separately authorized. Use a disposable mock/test fixture for clicks and state changes. Never put tokens/account IDs or private user data in renders. Do not bypass login/access policies; request actual screenshots/HTML if access fails.
3. For animated data use tested `starter/data_motion.py` as illustration, replace values with validated data and create proof. For hero CGI use `starter/hero_token.py` when shape suits story. This is a limited actual 3D renderer, not a general 3D authoring system. Optional Blender headless Python (`blender -b ... -P ...`) or Three.js headless only after a working smoke test and documented API. GUI is never mandatory. A complex shot can be rendered as a clip and combined with `starter/ui_engine/stitch.py`.
4. For any new effect, first design a 1–2s isolated mathematical or HTML/Canvas/SVG scene, render at low resolution, compare 3–5 frames to the desired motion, and only then integrate. Never install arbitrary/unverified packages, start servers on public interfaces or expect user to repair environment errors. Use authorized local assets and system/user-owned fonts; bundle no system font files.
5. Generate at most a small amount of glue code when a recipe exists: plan in JSON instead. Use absolute integer frames and deterministic easing; cache static textures. Do not use live browser animation timing as your export clock. Preview frames -> short draft -> full resolution -> final audio -> QA. Avoid entire-video rerender for one isolated shot if possible. For video layers beyond bundled still compositor, render a separate clip using tested software or extend with tests; do not pretend support exists.

## Compositor contract
`starter/ui_engine/render.py PLAN.json OUT.mp4 [--audio aligned.wav] [--font path]` renders frames in shot order. `--frame N` instead writes PNG. Plan root is asset base, dimensions are even pixels, fps positive integer. Each shot has `frames`, `background`, ordered `layers`. Types image (`src,w,h,radius,crop_center`), text (`text,size,color,font,spacing`), rect (`w,h,color,radius,outline,stroke`), cursor. Every layer can have center x,y, positive scale, opacity 0..1, rotation in degrees, reveal 0..1 (left-to-right local clipping). `animate` maps property to arrays `[localFrame,value,ease]`; easing on destination key: linear, out, inout, hold. Hold changes exactly at the destination. Missing keys hold constant; before first and after last holds endpoint. All key times unique and inside shot. Top-to-bottom array order = back-to-front compositing. Negative center positions and overscan may be intentional. No arbitrary eval, no realtime clocks. No automatic text wrapping, group transforms, blend modes, motion blur, shader engine, video layers, or optical flow; measure text and break lines manually. If cropping screenshots, do not accidentally omit facts. Pixel output uses RGB H264, yuv420p. Aligned audio duration must match timeline (0.1s tolerance). Silent demo is not final film.

### Recipe values at 540x960, scale pixels for other canvases
- Word reveal: each text layer opacity: [[0,0],[start,0],[start+7,1,"out"]] (omit duplicate time 0). For left-aligned line composition compute x=left+measured width/2.
- Macro-to-full: image scale [[0,2.2],[32,1,"inout"]]; x/y start based on crop focus, end at chosen card center. Cut from a matching crop rather than replacing with a different unrelated image.
- State change: A opacity 1→0 over 6f, B opacity 0→1 over same frames, identical x/y and bounds, unless designed slide. Actual screenshots of both states required for proof.
- Feature list: each row a text layer, delay 5f, 8f fade/slide from y+16 to final. One focus row, others lower contrast. Never show fake metric/feature.
- Cursor: move from previous location over 12–20f; compress scale .8→.65→.8 over 5–7f if actual click is represented. Only demonstrate verified behavior; cursor alone does not mean a click occurred.
- Final fan: 2–3 panels, main in front, back panels offset 80–140px and rotate ±6–9deg. 18–25f move and 20–45f hold; protect text margin. Use source aspect ratio instead of distorting UI.
- Deliberate breathing room: hard cut to background and one readable phrase or small decorative label; hold until next voice/music cue.

## Reconstruction protocol (not copying)
For each reference construct a shot coverage ledger: observed shot, visible action, actual available primitive, asset needed, implementation command, acceptance still/clip, status (tested/available/needs development/unavailable), fallback. Only call a technique "rebuildable" after successful isolated output and visual inspection. Entire reference is reproducible only after shot coverage 100% at required quality, actual assets/audio and timing supplied. Exact clone requires source assets/project, original shaders and audio that may be unavailable. For marketing use original brand, rights-cleared assets and original script. Do not claim matching original quality based on a smoke test. `33-reference-capability-matrix.md` provides the current honest coverage baseline.
