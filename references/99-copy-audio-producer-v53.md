# 99 — Write, direct, and hand off audio like a producer

Read before any copy or audio response. Guide 95 remains the detailed pipeline; 90 gives the exact local compiler cue map. This document concentrates on eliminating lazy writing and incomplete user-facing handoffs. Examples are fictional instructional material, never actual campaign evidence.

## 1. The editorial competition
Before writing, establish the viewer's situation (who, doing what, with what frustration or desire), the one verified product change and the visual proof. Distinguish a product feature from the consequence of using it. “Auto-crops” is a feature; “the person is still in frame” is a visible consequence only if the actual proof supports it. Avoid claims about automatic behavior if a manual adjustment was required.

Generate three meaningfully different hook mechanisms and at least two materially different complete short drafts internally. A set of three synonyms or three rhetorical questions about the same issue is not three ideas. Compare confession, visual contradiction, overheard dialogue, escalating absurdity, specific challenge, unexpected reveal, or simple demonstration as appropriate. For each draft, identify:
- What the viewer is curious about after line one.
- Whether the next line develops rather than explains the first one again.
- What exactly can be shown as proof (actual assets or states, not a made-up badge).
- Whether the last line resolves the same premise.
- Whether this could be pasted unchanged into a competitor's ad. If yes, specificity is missing.

Choose the strongest idea unless the client wants options. Do not make the client review all your discarded drafts. No compulsory joke, sarcasm, CTA, or brand name in every script. Write to the actual audience (clear language, natural contractions if applicable; don't talk down to them). A genuine product name can be part of the ending; a generic slogan isn't necessary. A script should work as spoken language without the viewer needing to read a marketing paragraph. Never manufacture testimonials, first-person product experience, competitor problems or numbers.

### Redline pass
Read each phrase as if spoken by a person. Remove empty opening (“In today's digital world”), adjective stack (“revolutionary powerful seamless”), generic CTA (“unlock limitless possibilities”), repeated voice-over explanation of already clear proof, and laundry lists disguised as sentences. Keep repetition when it creates comic rhythm or meaning. Replace assertions with a concrete action that can be verified. Choose one benefit; additional functionality may appear only if it supports the same story. Avoid making a product claim solely because there is an attractive compositing idea for it. If a hard time cap exists, shorten BEFORE locking text; don't speed up every word later. Estimate duration honestly, not an exact timing claim.

## 2. Casting and performance map
A voice description answers “who is speaking?”, the narration answers “what do they say?”, the acting map answers “how is each phrase delivered?”. Keep all separate. Use user-provided voice and script first. The exact original 962-character preset in guide 24 is the preferred design for suitable playful technology ads when a new voice is actually needed. Retrieve it from that file, copy it verbatim (not a paraphrase), and give its own copy block. Do not generate a new voice for every episode. Do not promise to imitate an actor or fictional character.

Divide narration by meaningful spoken intentions, not equal seconds. For each phrase choose objective, cue, operative word, pace/pause, emotional change from previous phrase, and relation to on-screen action. The tag should appear BEFORE what it affects, not appended to the end. A short neutral interval can be stronger than maximal acting. In a normal multi-phrase expressive ad, at least two distinct genuinely motivated cues are expected; no fixed number per sentence. If a short locked line naturally has fewer, preserve it and state compiler limitation. A cue like a laugh must contribute to the story; don't add random laughs/sighs to meet a count. A clean script and a cue list do not substitute for the fully tagged paste block.

For example, if the selected confirmed ElevenLabs expressive model supports these cues, a hypothetical crop-editor narration might read:
```
[curious] Why is my face missing?
[sarcastic] Lovely. A very cinematic forehead.
[thoughtful] Wait. Move the frame, not the photo.
[excited] There I am.
```
This is an example only; the real product must support shifting the crop and showing the corrected result. If using Fish and its verified supported expressive route, map to the actual syntax in 90 rather than reusing ElevenLabs strings. Keep spoken words identical across selected variants. Do NOT give several provider versions routinely: one selected eligible paste-ready route is best, alternatives only when helpful. If provider/model is unresolved, supply clean copy + separate acting plan and resolve the route; do not claim unverified tags work. Human recording: no inline tags to read; acting notes separate. Caption text never contains tags.

## 3. The novice-proof handoff (in the response, not just a generated file)
If the user must obtain audio, write the following with the actual selected content. Never send a generic example or literal placeholders. Use the user's conversation language for instructions, target language for speech.

**A. Voice route:** Identify direct official product/feature link, exact supported model as known/verified, whether a saved voice can be reused or a new voice is needed, and real prerequisites. Use current official docs if accessible; no claim of current UI, age/plan eligibility, pricing or commercial entitlement without verification. Guide 24 contains the existing ElevenLabs documentation links; 21 and 90 contain alternative routes. If the user's eligibility is not established, do not instruct them to bypass it. Offer an authorized existing recording, eligible alternative or own recording. If authorized generation is delegated and available, generate actual file instead of unnecessary handoff.

**B. Voice design only if needed:** Explain the difference from TTS. In the appropriate provider voice-design description field, paste the EXACT original description from 24 in a separate complete block. For a user who has a saved voice, omit this step. Give a real preview excerpt from the current clean script if the provider asks for one, compare candidates for clarity and the desired tone (not identity imitation), save selected voice. A preview text is not the voice-description field. With a provider that doesn't expose this control, explain that rather than inventing one. Avoid unnecessary paid attempts.

**C. Narration input:** Explain where to select the saved/authorized voice and expressive model, then provide the COMPLETE selected-provider tagged narration in its own copyable block, not buried inside an explanation/table/JSON. No timestamps, notes or extra instructions in the block. Preserve all words. If a provider has a length limit, give separately numbered, complete paste blocks with clear file naming, and request raw takes in order. Give clean copy separately as needed and concise acting notes OUTSIDE the paste block. If provider does not accept expressive tags, provide clean copy and separate instructions instead.

**D. Generate and inspect:** Tell the user how to generate and listen to the result: check words, pronunciation, natural emotion, intelligibility, correct pause, no spoken cue labels or unwanted sound. If bad, rerender only as needed with authorized controls, do not rewrite locked words just to fix delivery. Explain how to use the provider's supported download/export control, MP3 or WAV original, no music in narration. If you cannot verify button names, use the feature name rather than inventing click locations. Ask the user to return only the original untrimmed voice file(s). Don't ask them to remove silence, normalize, combine clips, or learn an editor.

**E. Music with real acquisition:** Determine soundtrack role from actual campaign and intended posting use, then select real track options if research available. Consult 22 and 95 for detail. Where appropriate, include a current/rising track supported by a dated source and a fitting timeless/cleared option. Identify exact title/artist/version, authorized preview/source, why it serves this particular story, intended musical moment (provisional until audio), and license scope with evidence. A trending track is not necessarily usable in a commercial post. A subscription/free download isn't automatically a license. A platform-only track may only be inserted inside that platform; do not suggest ripping or bake it into a cross-platform master. For a genuine direct licensed download, identify the actual lawful source and steps based on verified controls. If user already has a track, check rights and keep it if suitable. If no verifiable candidate, state that clearly and offer a lawful actionable alternative (user's licensed track, original music/authorized library route, or no music with consent). Do not invent song names, trend claims, links, license terms, or permission. A search page is a source route, not a selected song. Keep this unresolved if necessary while still delivering voice/script.

**F. Exactly what to return:** List ONLY missing original files and any genuinely necessary rights/selection confirmation. Say who handles what: agent aligns speech, picks segment, edits music, ducks/mixes, creates SFX, renders and checks. If the user already returned files, omit acquisition steps and start inspection. Do not say you will work in the background after they upload; continuation is a new actual work step. No passwords, API secrets or payment details.

## 4. Mandatory last-mile audit
Imagine the user has never generated audio before. Can they tell the difference between voice design, preview sample and final narration? Is the actual tagged script in the reply, not merely “use [curious]”? Is there a real selected route or clearly stated unresolved dependency? Do they know how to obtain the original files? Are music rights addressed separately from creative preference? Have you avoided asking them to perform producer/editing work? If any answer is no, fix the delivery before sending. Existing V50 handoff files support the reply but cannot replace it. If no audio is needed, skip this audit branch.

When actual stems arrive, inspect streams, versions, rights, true durations, pronunciation/acting if playback is available, and measured alignment with the exact locked words. Use 87/92 for existing tooling. Do not use a WORD COUNT estimate as a measured timeline, and do not pretend to hear audio from waveform or transcript alone. Only then finalize timings and picture-locked mix.
