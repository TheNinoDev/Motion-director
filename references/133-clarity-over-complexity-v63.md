## The observation: Claude is not simply more animated

The new Claude protection film uses notably few primary motifs: a large off-white source sheet, a red stealing/reposting state, a purple three-dimensional instruction transformation, an account/device binding illustration, a bright upload/enable contrast and a violet final declaration. They are distinct, visually separated and mostly built from restrained shapes. The new film also deliberately holds the opening document and last tagline across multiple seconds. Its appeal is not a high frame-change rate. The earlier Claude discovery edit uses a dark background, one oversized question, a bright wall of Run buttons, a focused four-step inspection chain, a bold lime LOOK FIRST / RUN payoff. Different films, same **editorial hierarchy**: large understandable meaning over decorative density.

The supplied GPT v60 protection film covers similar information, but often shows multiple thin panels, fine code lines, grid marks, halos, headings, tiny annotations and centered symbols in parallel. These can be technically correct yet weaken clarity. Its animations often show an abstract state changing without a viewer-recognizable story event. Adding more circles, details, particles or faster movement would worsen this failure. When a shot is busy but feels empty, ask: **what visual fact should the audience notice right now?**

Claude's observable production advantage also involved *looking*: the first Claude log shows several contact-sheet reviews, diagnosing an element-layout bug from real positions, fixing transitions, rendering again, and inspecting final files. GPT also reviewed technically; it often kept a poor composition and merely adjusted its motion. Transfer the habit of making a **creative** correction, not just a bug fix. Do not assume a specific programming language creates taste.

## The director's three choices (quick, private)

**Choose the hero:** Identify the ONE thing the viewer must look at in this beat (word, card, hand, signal, shape, action). Frame it to read at phone size. Everything else must either support it or go. Text can be a beautiful hero if it is actually doing narrative work; it does not need ornamental objects underneath it.

**Choose the verb:** The hero must *do one intelligible thing* or intentionally hold an earned result. Useful verbs: split, steal, collapse, select, reveal, protect, transform, compare, return. Avoid “animate”, “rotate”, “add effects”, or “zoom” as narrative verbs. A movement is good only when it shows consequence, directs attention, changes mood, or sets up the next shot. Don't mechanically add movement to every second.

**Choose the contrast:** Make the next important beat different for a reason: paper vs dark void, one sheet vs proliferating copies, small problem vs full-frame result, tension vs relief, colored danger vs calm control. Contrast can come from geometry, framing, negative space, material, color or pace; do not cycle palettes or camera moves without a reason. A strong cut often beats an elaborate transition.

## Subtractive design pass (before code, and again after first rough cut)

At the first frame of each main beat, make an honest small-screen thumbnail. Pretend only the hero and the two largest shapes survive. Is the point still obvious? If yes, stop decorating. If no, simplify the concept until the hero's action becomes clear. Remove any decorative border, scanline, particle layer, technical micro-label, ornamental 3D, secondary icon or caption that does not change perception or comprehension. A page of detailed shader work is not automatically a finished film.

For the actual rough cut, compare the same time window with decorations **off** and with them on, where the source allows it. If the simpler version reads faster or has stronger impact, keep it. A busy scene can be excellent for an intentional emotional overload; it earns complexity only when *overload itself is the point*, as with the earlier Claude Run-button wall. The next shot should then offer contrast and breathing room. Avoid a global visual-complexity quota.

## Example: script protection, without cloning either film

Bad: Large title "CUSTOM VM", a small centered code window, twenty tiny cubes, circular radar pattern, pulsing lines, five technical tags, scanlines and slowly spinning background. The audience reads words but sees no compelling event.

Better in principle: The *actual statement* is transformation. Start with **one readable source object** occupying the frame. One edge initiates a change; the original structure folds or separates into a new arrangement visibly different from the source; hold the new result briefly so the audience understands it. A single supporting title can then identify the concept. Use real sound timing. If the implementation is illustrative, label its technical claims accordingly. The design need not literally be folding paper or cubes; invent a distinct metaphor that suits the brand and story. Resist adding extra interface chrome after the event becomes legible.

Bad: Every 3 seconds force a new animation because a frame-difference metric reports stillness. This destroys anticipation, a readable claim and a musical drop. Better: Give a still moment a purpose; when there is no purpose, cut it, reframe it or make its subject act. Motion metrics can point to a segment to **inspect**, never diagnose creative quality alone.

## Agent self-interruption when polish becomes clutter

When more than one visually demanding idea competes in a shot, stop implementing and state privately: `Hero = ...; change = ...; eliminate = ...`. Then actually remove or redesign something in the renderer. If the viewer needs the caption to know that anything changed, the action has not been communicated. If the artwork is already instantly understandable, do NOT keep adding more detail for a sense of effort. Spend effort on precise positioning, typography, timing, compositional contrast and transitions. Good editing may be simple, but it is never careless.

**One test question:** On a phone, with audio and tiny captions hidden, what should be remembered from this five-second section? If the answer is a list of decorations or software features, simplify until it becomes an image and a change.
