# 158 — Case study: new 24-second RobloxLARP ad, v76 model output

Evidence: user-uploaded `RobloxLARP_Script_Protection_Ad(4).mp4`, 1080×1920, 30fps. The observations are approximate timestamped visual diagnoses, not derived from metadata alone. This MP4 is a reference for understanding the failure—not a skill asset to distribute or copy.

| Period | Visible pattern | Failure and direction |
|---|---|---|
| 0–3s | YOU BUILT THIS over centered code card, navy grid | A neatly arriving object is not a compelling construction. The camera stays nearly fixed; invent a visible build/action and destination |
| 3–8s | STOLEN / STRIPPED / REPOSTED stack; a red duplicate code panel | Headline changes dominate; enact duplication, stripping, distribution and changed relationships rather than relying on text stacks |
| 8–13s | SCRIPT PROTECTION over another central code panel with scan lines | Repeats the introduction's geometry. Carry the previous cause into a visible transformation and change how the frame is used |
| 13–18s | CUSTOM VM/opcode tiles then CONTROL ACCESS credential tiles | Two largely self-contained technical diagrams; little visible causal relationship or spatial change. Show a genuine state change, not a feature list |
| 18–21s | UPLOAD ENABLE PROTECT and compact upload/toggle panel | Small UI summary of a new feature, not the earned consequence of earlier action. Stage a focused interaction rather than a new slide |
| 21–24s | R logo + stacked motto, quiet endcard | Outro does not inherit much visual energy or an object; use a motivated outro handoff and deliberate read hold |

**Recurring visual template:** upper-left large two/three-line text, small-ish centered code/UI card or symmetrical tiles, bottom miniature labels, constant blue perspective grid. More animated pixels do not solve repeated visual meaning or frame composition.

**Comparison with Claude's separately uploaded 19.8-second `robloxlarp-ad.mp4`:** single source card evolves to many related cards, then back to one selected/protected card; scale, lighting and density change. The useful principle is evolving *relationships and viewer focus*, not the specific cards, layouts, colors, numbers or other proprietary pixels. These productions use different scripts: do not pretend this is a model-only benchmark.

Keep claims truthful and mark planned protection features appropriately. No unsupported guarantee of impossible reverse engineering.
