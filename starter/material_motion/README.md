# Material Motion — GUI-free CPU tools

Run from skill root. Requirements: Python 3, NumPy, Pillow, OpenCV, FFmpeg/ffprobe on PATH. Use `python -m pip install -r starter/material_motion/requirements.txt` only if permitted and needed. Check dependencies before promising delivery. Use an authorized local TTF or OTF font; no fonts are bundled.

```sh
python starter/material_motion/render.py starter/material_motion/demo.json work/material.mp4 --font PATH_TO_FONT --samples 3 --preview-dir work/material-stills
python starter/material_motion/finish.py work/material.mp4 work/material-finished.mp4 --settings starter/material_motion/finish-subtle.json
```

Copy demo JSON into work, never alter shipped examples. Set width/height/fps, shots with contiguous durations in frames. `kind` choices: `macro` (cropped initial detail to context), `metal` (animated studio lights, bevel normals, reflected layer, contact shadow), `focus` (blurred/dim hero behind crisp caption), `emissive` (bright glyph and controlled bloom), `portal` (increasing scale/crop through an optical detail). Portal is an entry/exit building block; align the incoming shot manually using matching shape and center; it does not automatically transition to a second clip. All need text and frames. Caption is optional, max 100 characters. Use brand text or one symbol; large type must be visually checked for fit. Defaults: roughness .18, bevel .065, reflection .3, bloom .11, shutter .45. Their permitted ranges are in validator. For preview use 360x640 and 1 sample. For final use 1080x1920 and 3 or 5 samples, inspect performance first. Supersampled intra-frame exposure is applied to the material layer, clamped within the shot. Captions remain sharp. The shader is a height-field approximation, not true mesh/path tracing. Surface bevels account for holes, lighting changes the normal-based reflection, contact shadows/reflections are composited approximations; depth of field is layer-selective, not physically simulated. For a real rotating extrusion use `starter/scene3d` and optionally finish its output. Text that has no visible glyph in your font must be replaced/fixed before rendering.

## Finishing an existing clip
`finish.py` accepts an already rendered, constant-frame-rate MP4, outputs a separate MP4, preserves frame count and nominal FPS and maps audio streams (AAC re-encode). Use zero-based, normalized sources with aligned audio. It does not validate aural sync or preserve subtitles/chapter metadata. Use on separate shots before captions where possible; do not globally glow readable text or UI. Use subtle settings as shipped. `exposure` is linear-light stops, `bloom` adds blurred above-threshold light, `radius` is fraction of image width, `vignette` dims at edge, `grain` optional deterministic noise. It has no temporal blending across edits. It cannot reconstruct depth or subframe motion from a flattened video. For those use source-layer rendering and actual subframe samples. Avoid re-encoding repeatedly. Compare before/after at phone size; use unprocessed version if less readable. Preserve original audio stems and original timeline. Final release still requires full existing audio, product, motion and output checks.
