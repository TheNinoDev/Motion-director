# V35 hybrid CPU/CUDA compositor

Read `references/71-gpu-and-agent-execution.md` first. `render_backend.py` is a per-render session. `cuda_kernels.py` contains explicit CUDA kernels with per-pixel math ported from CPU references. One thread owns one pixel; no fastmath. Mask, softbody transform, scene parenting, light keyframes and existing optical/compositor functions operate as before. Tile the volume/text image grids and transfer each output back to CPU for compositing. Contact uses guarded full-frame ray buffers. The CPU volume kernel now also uses row-parallel Numba. GPU acceleration is optional.

CLI: `--backend auto|cpu|cuda`, `--device INDEX`, `--gpu-tile-mib N` for compositor. Contact accepts backend/device. `--at SECONDS` (repeatable), `--range START END` for compositor. Native PNG output and picture-only excerpt report with source frame start. Audio alignment is deliberately not altered for excerpts. Use fresh output dirs. Existing full render and profiles still work. `render-backend.json` records actual calls, selection and errors, not just requested mode.

Test command: `python scripts/gpu_doctor.py --test` on physical CUDA, or `--simulate` for CPU simulator. Simulator parity tests cover nine volumes, five glyph materials, two-body contact raster, and integrated softbody + glyph composition. Simulator does not test GPU driver, PTX compilation, memory usage or performance. Actual compilation and performance must be tested on supported hardware before claiming GPU production readiness. CPU integration and fallback are separately tested by `tests/test_v35.py`. Maintain parity when changing the duplicated kernel math. Do not let GPU feature requests silently replace CPU functionality.
