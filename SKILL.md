## 1. Sources are INFORMATION, not visuals
Website, local project, repo, HTML/CSS, screenshots and style-reference video can be READ to establish product FACTS, claim limits and general editing ideas. **Never source final frames, screenshots, web graphics, DOM captures, CSS layout/design system, embedded imagery, site logos, reference shots or derived textures from them.** Don't redraw the page, or image-to-image its screenshot. Create each visual using original procedural geometry, typography, materials, 2D/3D objects or blank authored HTML/CSS/SVG/Canvas scene code. An *original clearly conceptual diagram* may resemble a generic interface or code document, provided it does not clone the source site and is not presented as a factual screenshot. Newly typeset truthful names/functional words are allowed. User explicitly authorizing one separate asset for inclusion is a scoped exception; a URL or project path is NOT authorization. Check actual asset origins before export (guide 119).

## 2. Audio: ask IF missing; never ask IF present
At the start inventory the actual task and existing script, voice/music stems, target language, intended release and user decisions. Claude asked for audio because no stems were supplied. GPT correctly skipped those questions because voice, music and copy were already in the project. **Do not ask the user for a file or choice already provided.** If audio is missing for a narrated ad, ask only consequential decisions; then deliver the actual COMPLETE expressive TTS script (when provider/model support confirmed), acting notes, exact voice-design text only if needed, eligible generation/export instructions and concrete licensed music route. End at the real dependency if files need user action. Do not produce a finished silent substitute. If audio exists, preserve it, inspect actual metadata, words if access permits, rights and measured timing, then work on the film. Respect explicit silent or script-only requests. Never invent audition, transcript, license or account eligibility. See 123 and existing guide 115.

## 3. Visual film: make the objects DO something
**The core failure was not lack of rendering commands.** A technically correct 25-second video can still consist mostly of the same card in different positions with new labels. For each 2–5 second story segment (flexible, not a quota), specify a meaningful *before → caused action → changed result* and a transition anchor. Use one persistent motif whose role evolves. Vary actual composition and screen-space subject relationships: macro, full-bleed graphic, spatial transformation, close proof, quiet contrast and deliberate payoff as the story warrants. A new title over an otherwise stationary card is NOT a new major visual event; a slow zoom or glow is NOT a substitute for a change in meaning. A code block moving on a platform is only useful when its transformation communicates the product promise. An intentional quiet hold is fine when actual proof or music needs room.

Before a long render, create two genuinely different original styleframes PLUS a short moving test of the highest-risk transformation. Inspect it, and adjust. Build the rest as one connected edit, not a stack of independent scenes. No mandatory 3D, glass or effects count. Use any existing compatible production technique, including original-from-zero HTML/CSS/Canvas composition or procedural Python 2D/3D; the language/backend does not determine quality. Never import the product site's markup into that scene. See 122 and 124.

## 4. Review meaning, not only codec
Inspect actual key frames AND motion at start/mid/end of connected events. Compare a filmstrip sampling different times: are adjacent major beats materially different, or just the same layout/headline? Can the viewer describe the change without reading the captions? Is product meaning/claim honest? Did the first 3 seconds create curiosity, and does the end resolve it? Check actual timing against received VO/music; audio measures alone are not listening. Identify the weakest section, make a substantive targeted correction, rerender/review if feasible. A codec pass, 527 lines of render code, a motion test or a successful contact sheet does NOT certify a good edit. Respect locked copy and existing assets; don't fake validation. Deliver actual verified files or explicitly labeled drafts, not completion claims about absent media.
