# Motion Director 66 — Connected scenes, fluid motion, authored transitions

**V66 PRIMARY DIRECTIVE (overrides older dead-frame and transition advice).** A functioning sequence of strong individual shots can still be a bad film if the seams are unmotivated. **Direct and prototype the A→B handoff as part of each shot**, with a carried focal shape/object/action OR a deliberately motivated contrast/impact cut. Read `references/139-cross-scene-handoffs-v66.md`, `references/140-fluid-kinetics-v66.md` and `references/141-noiz-claude-transition-study-v66.md`. For visible problem timecodes use the supplied GPT-v65/Claude/NOIZ comparison, not an imaginary style score. Inspect both sides of each major seam at 1x and 0.5x using the packaged `scripts/seam_review_v66.py` review-strip utility when useful. Smooth in-scene movement needs sensible path tangents, speed changes, anticipation and follow-through; a hard cut need not preserve velocity mathematically. **Neither mandatory wipes nor maximal pixel change are goals**: use intentional quiet beats and high-impact editorial contrasts. Do not recreate reference footage/assets. Before finalizing, repair the weakest disjoint seam (by revising shot staging, not pasting effects); an independent subagent may critique seams if supported, while the director retains final ownership. Supplied voice/music are locked, and the existing editor capabilities should be used before inventing an inferior renderer.

**V65 CRITICAL UPDATE (read before V64 text).** The latest user video is still too static and looks cheap despite functioning exports. Almost no unintentional dead time: inspect actual decoded video with `scripts/hold_audit_v65.py` and fix long inactive stretches; intentional short reading holds are allowed but must be justified. Design before/action/after *with visible development during the beat*, fluid lead/follower motion, and continuity through transitions, not 3-second motionless cards. Read `references/136-motion-continuity-v65.md` and `references/138-editorial-repair-v65.md` before a long render. For visual variety and font roles read `references/137-svg-typography-v65.md`: never default to one generic Arial/Consolas look for the entire film. The user **explicitly allows independently sourced, licensed SVG artwork** from the internet, with file-level licensing and sanitization; this exception does NOT authorize copying product-site or reference-video assets. Prefer strong hero objects, distinct display/serif/mono roles as appropriate, real depth and transitions over pointless decoration. Keep narration/music locked when supplied.

**ACTIVE OPERATING CONTRACT.** The objective is not more detail or more animation; it is an edit the viewer understands and wants to watch. **One powerful visual idea executed clearly beats five intricate animations competing for attention.** For creative decisions read `references/133-clarity-over-complexity-v63.md` first. **Before building visuals, read `references/134-editor-capability-routing-v64.md` and use the actual packaged editor where it fits.** Consult `references/131-deterministic-render-debug-v62.md` only for implementation, `references/132-film-acceptance-repair-v62.md` for review, and `references/123-input-and-audio-routing-v60.md` for missing audio. When supported subagents genuinely exist, follow `references/135-subagent-orchestration-v64.md`: delegate only bounded independent tasks, keep one director and one final editor, and verify every handoff. If no subagents exist, perform the same passes yourself without pretending to delegate. Other references are supporting history, not additional stages or visual templates. User scope and actual evidence override generic defaults.

## Director owns the film; subagents own bounded tasks

If the host supports subagents, break substantial work into clearly scoped fact research, audio cue analysis, visual concept scouting, one native-editor shot/proof per worker, and independent whole-film critique. **The director chooses the one story, controls the locked inputs and master timeline, and accepts/rejects outputs after inspecting them.** Parallel workers cannot write shared files or each build a different final video. Do not delegate trivial work or force many agents when one focused editor is better. See `references/135-subagent-orchestration-v64.md` for precise contracts, barriers, file ownership and fallback.

## Before a render

1. Inspect the actual requested product, brief, locked script, existing narration and soundtrack. Product websites, project repositories, local projects and reference films are **INFORMATION ONLY** (independent licensed generic SVG libraries and font sources are allowed under guide 137): use facts, not screenshots, DOM, assets, logos, UI copies, source imagery, styling or reference-film pixels. Original hero visuals are required; the user also explicitly authorizes suitable third-party SVGs and licensed fonts from independent sources with provenance, sanitization and permission checks, never copied product-site assets. Never pretend a conceptual feature visual is an actual product capture or claim that a planned feature already exists.
2. **If narration/music already exist, preserve them and proceed.** Do not ask again. If a normal narrated-ad request has unresolved voice/music choices, ask only those consequential missing questions and stop for input when required; provide an actionable full audio handoff if generation isn't available. Respect silent/script-only requests. Never replace missing music with SFX and call it finished, fabricate music rights, or rewrite locked spoken words.
3. Choose **one real human problem and one emotional/visual turn**. Think in a few film moments, not a feature checklist. For each major moment define: *what the viewer sees first; what causes the change; what visibly changes; what they understand*. Make an original concept, not the art style of another agent's demo.

## Visual direction — subtraction first

- **One dominant focal subject per moment.** Text may be the subject; an object may be the subject. Establish clear hierarchy. A headline, micro-labels, floor grid, floating window, decorative rings, background stars and scanlines must not all compete by default.
- **Make the hero large and the meaning immediate at phone size.** Prefer a bold simple silhouette, a purposeful contrast and a believable relation between objects over fine technical decoration. If a detail can disappear without reducing comprehension, remove it before adding anything.
- **Change the idea, not just the heading.** A source document is duplicated; the stolen copy loses ownership; fragments recombine; a gate visibly decides; an upload action resolves. These are example *causal motions*, not required specific shots. Do not make every section another centered panel with a new caption.
- **Use deliberate motion, nearly zero unexplained stillness.** Anticipation → meaningful movement/change → clean settle, or a strong intentional cut. Vary scale and composition at story turns. Only short purposeful holds are valid for tension, important information or payoff; multi-second static screens while music/voice continues require a verified creative reason or repair. Don't add perpetual drift, glow, jitter, decorative 3D, synthetic camera movement or beat-synced cuts to avoid stillness. Claude's stronger examples often used *less* motion and *less* detail, not more.
- **Design for available audio.** Let voice and music define the emphasis and negative space. Only a few beats deserve hero events; don't animate every syllable. Keep readable text short and free from invented claims.

## Execute, inspect, revise

Build **one strong opening frame, one actual transformation and one closing frame** at realistic phone viewing scale before implementing the entire film. **Do not write a new full-frame Pillow/HTML renderer before inspecting the bundled Motion Director editors, validating one real editor shot, and documenting a concrete missing capability.** Prefer a native editable timeline for layers, masks, paths, grouped transforms and cross-shot continuity; use custom code only for a genuinely unsupported visual technique, then integrate it with the existing editor/audio pipeline. If the three look like the same template with different headings, redesign. The chosen engine must serve the visual idea; using advanced features is not a quota. The engine selection must be grounded in the available CLI/schema, not guessed from the name. A custom browser timeline may be best for difficult responsive layouts, but it must not become a simpler replacement for an available compositor. A deterministic `render(t)` is useful when debugging; inspect actual frames and motion, not just metrics. A single successful 2-second animation does not approve a 24-second film.

Watch the **whole rough cut** with sound when genuinely possible, and review it silently for visual clarity. Keep the editor project file, sources, and a short evidence-based list of actual editor capabilities used; a technical claim of capability is not evidence that it was exercised. Find the weakest scene; **first delete competing graphics and change the hero staging**, then fix motion mechanics. Compare an intentionally simplified variant against the current version at the same timecode. Judge whether the viewer can identify the main idea without reading the small caption. Do not mechanically fail long still sections: ask if they have a purpose. Rebuild a weak scene rather than covering it with effects. Verify full export/decoded media, truthful claims, asset origin and relevant actual audio checks; distinguish what was observed from what was not auditioned.

For supported narrated projects existing preproduction/production tools and gates remain valid (`references/87-producer-first-v50.md` and the relevant 92 guide). Do not invent successful checks or requirements to justify a renderer choice. Preserve existing user sources and revisions; do not make new production tools merely to satisfy this skill. Report a genuine blocker honestly and deliver current verified artifacts.

**Before saying done:** Review the A→B seam montage plus seam clips at real speed and half speed; a smooth animation entirely inside one shot is not sufficient. Run the actual 10fps hold audit and inspect every non-approved >0.85s interval; repair blank/static segments, typography, layering and transitions. See 136–138. Then ask: Is there one readable hero in each key moment? Did the edit accomplish a visible change? Would deleting the decorative half make it stronger? Did I actually review the whole film? Does the supplied music/voice remain unchanged where locked? If not, repair first. See 133 for illustrated decision examples; do NOT reproduce its sample designs.
